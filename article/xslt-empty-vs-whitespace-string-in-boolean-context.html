XSLT Empty vs Whitespace String in Boolean Context

In XSLT and XPath, evaluating strings within a boolean context often causes unexpected logic errors because the engine evaluates strings based entirely on character length rather than whether the content is meaningful. While an empty string evaluates to false, a string containing only whitespace characters evaluates to true. This article explains the core XPath casting rules behind this behavior, the common pitfalls it creates in conditional statements, and how to correctly handle whitespace strings using built-in functions.

The Boolean Conversion Rule for Strings

According to the W3C XPath specification (applicable to XSLT 1.0, 2.0, and 3.0), the rule for converting any string to a boolean value is strictly defined by its length:

  • A string is converted to true if and only if its length is greater than zero.
  • A string is converted to false if and only if its length is exactly zero.

The semantic content of the string is completely ignored during this automatic type conversion.

Empty String vs. Whitespace String

Because the conversion relies solely on string length, empty strings and whitespace strings produce opposite boolean results:

  • Empty String (""): The string has a length of 0. When evaluated in an <xsl:if test="..."> or <xsl:when test="..."> construct, it evaluates to false().
  • Whitespace String (" ", "\t", "\n"): A string composed only of spaces, tabs, or line breaks has a length greater than 0. Therefore, it evaluates to true().

Example Scenario

Consider the following XML element:

<description>   </description>

If evaluated using a direct boolean test:

<xsl:if test="description">
    <!-- This block WILL execute -->
</xsl:if>

In the example above, the text node contains spaces. Because the string length is non-zero, the test condition evaluates to true(), even though the element visually appears blank.

The Solution: Using normalize-space()

To treat whitespace-only strings as false, you must strip the whitespace before evaluating the boolean condition. The standard approach in XSLT is to use the normalize-space() function.

The normalize-space() function removes leading and trailing whitespace and replaces internal sequences of whitespace characters with a single space. If a string contains only whitespace, normalize-space() reduces it to an empty string (""), which subsequently evaluates to false.

Corrected Test Pattern

<xsl:if test="normalize-space(description)">
    <!-- This block will NOT execute if description is empty or whitespace-only -->
    <p><xsl:value-of select="description"/></p>
</xsl:if>

When working with variables, the same pattern applies:

<xsl:variable name="myVar" select="'   '" />

<!-- Evaluates to false -->
<xsl:if test="normalize-space($myVar)">
    ...
</xsl:if>

Summary of Differences

  • boolean('') results in false.
  • boolean(' ') results in true.
  • boolean(normalize-space(' ')) results in false.

To avoid false positives when checking for the presence of text data in XSLT templates, always apply normalize-space() unless the physical preservation of whitespace-only nodes as valid data is explicitly required by your transformation logic.
