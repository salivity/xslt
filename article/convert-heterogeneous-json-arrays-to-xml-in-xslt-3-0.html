Convert Heterogeneous JSON Arrays to XML in XSLT 3.0

XSLT 3.0 introduces native support for processing JSON data through built-in functions like json-to-xml() and parse-json(), combined with XPath 3.1 map and array data types. When an incoming JSON array contains heterogeneous objects—records with varying keys, types, and schemas—XSLT 3.0 allows developers to parse these collections, discriminate between different object shapes, and transform them into coherent, normalized XML documents using declarative template matching or functional mapping.

Ingesting Heterogeneous JSON

XSLT 3.0 offers two distinct approaches to ingest JSON data:

  1. json-to-xml(): Automatically transforms raw JSON into an intermediary XML vocabulary defined by the W3C (using namespaces such as http://www.w3.org/2005/xpath-functions). Heterogeneous objects inside an array become <map> elements with differing child elements (<string>, <number>, <boolean>, <array>, etc.).
  2. parse-json(): Converts the JSON string directly into native XPath 3.1 items (maps and arrays), which can be manipulated directly in XPath expressions and XSLT templates.

Method 1: The json-to-xml() Approach

The json-to-xml() function is often the simplest way to handle heterogeneous structures because it converts the problem into standard XML-to-XML processing. Once in XML format, template matching handles variation naturally without complex procedural branching.

Example Scenario

Consider an array containing two different object types—user records and system_event records:

[
  { "type": "user", "id": 101, "name": "Jane Doe" },
  { "type": "system_event", "eventCode": 500, "severity": "CRITICAL" }
]

XSLT 3.0 Transformation

Using template matching, you can direct each heterogeneous item to its dedicated target XML element:

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:fn="http://www.w3.org/2005/xpath-functions"
    exclude-result-prefixes="fn">

  <xsl:output method="xml" indent="yes"/>

  <xsl:param name="input-json" as="xs:string"/>

  <!-- Root Template -->
  <xsl:template name="xsl:initial-template">
    <root>
      <!-- Convert JSON string to internal XML and apply templates -->
      <xsl:apply-templates select="json-to-xml($input-json)/fn:array/fn:map"/>
    </root>
  </xsl:template>

  <!-- Match user objects -->
  <xsl:template match="fn:map[fn:string[@key='type'] = 'user']">
    <user id="{fn:number[@key='id']}">
      <name><xsl:value-of select="fn:string[@key='name']"/></name>
    </user>
  </xsl:template>

  <!-- Match system event objects -->
  <xsl:template match="fn:map[fn:string[@key='type'] = 'system_event']">
    <event code="{fn:number[@key='eventCode']}" severity="{fn:string[@key='severity']}"/>
  </xsl:template>

</xsl:stylesheet>

When an explicit discriminator field (like type) does not exist, you can match based on key existence:

<!-- Match objects that have a 'name' key -->
<xsl:template match="fn:map[*[@key='name']]">
  <entity type="named">
    <name><xsl:value-of select="*[@key='name']"/></name>
  </entity>
</xsl:template>

Method 2: The parse-json() and XPath 3.1 Maps Approach

Using parse-json() avoids generating intermediate XML nodes, working instead with native XPath 3.1 maps. This can be more performant for large datasets.

Iteration and Type Discrimination

Using map accessors, map:contains(), and map lookup operators (?*, ?key), you can iterate over arrays and dynamically build elements based on the presence of specific attributes.

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:map="http://www.w3.org/2005/xpath-functions/map"
    exclude-result-prefixes="xs map">

  <xsl:output method="xml" indent="yes"/>
  <xsl:param name="input-json" as="xs:string"/>

  <xsl:template name="xsl:initial-template">
    <dataset>
      <!-- Flatten JSON array to sequence of maps -->
      <xsl:for-each select="parse-json($input-json)?*">
        <xsl:choose>
          <!-- Discriminate based on 'type' key -->
          <xsl:when test=".?type = 'user'">
            <user id="{.?id}">
              <name><xsl:value-of select=".?name"/></name>
            </user>
          </xsl:when>

          <!-- Discriminate based on key presence -->
          <xsl:when test="map:contains(., 'eventCode')">
            <event code="{.?eventCode}" severity="{.?severity}"/>
          </xsl:when>

          <!-- Fallback for unexpected shapes -->
          <xsl:otherwise>
            <unrecognized-item>
              <xsl:for-each select="map:keys(.)">
                <field name="{.}"><xsl:value-of select="..?(.)"/></field>
              </xsl:for-each>
            </unrecognized-item>
          </xsl:otherwise>
        </xsl:choose>
      </xsl:for-each>
    </dataset>
  </xsl:template>

</xsl:stylesheet>

Key Differences and Best Practices

  • Use json-to-xml() when rules-based, declarative transformations are preferred. It simplifies structural navigation using standard XPath pattern matching, modes, and template priorities.
  • Use parse-json() when working with high-volume feeds where creating intermediate XML trees adds unacceptable memory overhead.
  • Handle Schema Drift: For heterogeneous data with unexpected structures, always provide a fallback template or an <xsl:otherwise> block to log or preserve unmapped data elements safely.
