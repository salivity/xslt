How to Use map:merge in XSLT 3.0

In XSLT 3.0, the map:merge() function is the standard mechanism for aggregating multiple discrete maps into a single unified dictionary. This article explains the syntax of map:merge(), details its duplicate-handling options, and demonstrates how to combine key-value pairs from multiple sources into a consolidated map structure.

Function Overview and Syntax

The map:merge() function is defined in the standard XPath and XQuery Functions and Operators 3.1 specification, which XSLT 3.0 supports natively. The function takes a sequence of zero or more maps and returns a single map containing all key-value entries.

It provides two signatures:

map:merge($maps as map(*)*) as map(*)
map:merge($maps as map(*)*, $options as map(*)) as map(*)

When called with a single argument, map:merge() applies default options. When provided with a second argument, users can control how key collisions and duplicates are resolved.

Handling Key Collisions with Options

When combining distinct maps, identical keys frequently occur across datasets. The $options parameter accepts a map specifying how to handle duplicate keys using the duplicates entry.

The available settings for duplicates include:

  • use-first (Default): If a key occurs in multiple input maps, the output map retains the value associated with the first occurrence in the sequence.
  • use-last: If a key occurs multiple times, the output map overwrites earlier entries with the value from the last occurrence in the sequence.
  • combine: When duplicate keys are found, their values are concatenated into a single sequence under that key.
  • reject: The processor raises an error (FOJS0003) if any duplicate key is encountered.
  • use-any: The processor is free to choose any of the supplied values arbitrarily.

Practical Examples

1. Basic Merging (Default Behavior)

Combining two distinct dictionaries without overlapping keys:

<xsl:variable name="mapA" select="map { 'id': 101, 'name': 'Alpha' }"/>
<xsl:variable name="mapB" select="map { 'status': 'active', 'role': 'Admin' }"/>

<xsl:variable name="combined" select="map:merge(($mapA, $mapB))"/>

The resulting $combined map contains all four keys: 'id', 'name', 'status', and 'role'.

2. Resolving Overwrites with use-last

When merging a base configuration with overriding settings, use-last ensures later maps overwrite earlier values:

<xsl:variable name="defaults" select="map { 'theme': 'light', 'fontSize': 12 }"/>
<xsl:variable name="userPrefs" select="map { 'theme': 'dark' }"/>

<xsl:variable name="config" select="map:merge(($defaults, $userPrefs), map { 'duplicates': 'use-last' })"/>

The resulting map contains:

  • 'theme': 'dark'
  • 'fontSize': 12

3. Grouping Values with combine

To group related data under identical keys without losing entries, set duplicates to 'combine':

<xsl:variable name="entry1" select="map { 'tag': 'xslt' }"/>
<xsl:variable name="entry2" select="map { 'tag': 'xml' }"/>
<xsl:variable name="entry3" select="map { 'tag': 'xpath' }"/>

<xsl:variable name="grouped" select="map:merge(($entry1, $entry2, $entry3), map { 'duplicates': 'combine' })"/>

The resulting map contains a single key 'tag' mapped to the sequence ('xslt', 'xml', 'xpath').

Constructing Maps from XML Nodes

A common pattern in XSLT 3.0 stylesheets is transforming a sequence of XML elements into a lookup map using an XPath for expression combined with map:merge():

<xsl:variable name="lookup" select="
  map:merge(
    for $item in //item
    return map { string($item/@id) : string($item/@value) },
    map { 'duplicates': 'use-last' }
  )
"/>

This pattern iterates over every <item> element, wraps each into an individual entry map, and consolidates them into a single dictionary optimized for fast key-based retrieval.
