Using the instance of Operator in XSLT Conditions

The instance of operator in XSLT and XPath provides a robust way to inspect and verify the runtime data type of values or nodes before processing them. By evaluating whether an expression conforms to a specific SequenceType, developers can safely route execution paths within conditional structures such as <xsl:if> and <xsl:choose>. This article explains how the operator functions, how occurrence indicators affect evaluation, and how to implement it directly within conditional branches.

Understanding the instance of Operator

Introduced in XPath 2.0 and supported natively in XSLT 2.0 and 3.0, instance of is a boolean operator that tests whether an item or sequence matches a specified data type.

The syntax follows this structure:

expression instance of SequenceType

The operator returns true if the evaluated value matches the expected type and cardinality; otherwise, it returns false. Unlike casting functions, instance of does not convert the data—it merely inspects it.

Syntax and SequenceTypes

A SequenceType consists of an ItemType and an optional occurrence indicator.

  • Atomic Types: Built-in XML Schema types such as xs:string, xs:integer, xs:decimal, xs:boolean, or xs:date.
  • Node Types: Structural XML components like node(), element(), attribute(), text(), or document-node().
  • Occurrence Indicators:
    • No indicator: Exactly one item.
    • ?: Zero or one item.
    • *: Zero or more items.
    • +: One or more items.

For example, $input instance of xs:integer+ returns true only if $input contains a sequence of one or more integers.

Implementing instance of in <xsl:if>

To conditionally execute a template block based on a data type, place the instance of expression inside the test attribute of an <xsl:if> element:

<xsl:param name="dynamicInput" />

<xsl:if test="$dynamicInput instance of xs:date">
    <formatted-date>
        <xsl:value-of select="format-date($dynamicInput, '[Y0001]-[M01]-[D01]')" />
    </formatted-date>
</xsl:if>

If $dynamicInput is not an instance of xs:date, the engine skips the inner block, avoiding runtime evaluation errors that occur when passing invalid types to type-sensitive functions.

Type Routing with <xsl:choose>

The operator is particularly useful inside <xsl:choose> constructs to handle polymorphic parameters, mixed content, or diverse function returns:

<xsl:variable name="payload" select="get-data()" />

<xsl:choose>
    <xsl:when test="$payload instance of element(record)">
        <xsl:apply-templates select="$payload" mode="process-record" />
    </xsl:when>
    <xsl:when test="$payload instance of xs:string">
        <output-text><xsl:value-of select="$payload" /></output-text>
    </xsl:when>
    <xsl:when test="$payload instance of xs:numeric">
        <output-number><xsl:value-of select="$payload * 2" /></output-number>
    </xsl:when>
    <xsl:otherwise>
        <xsl:message terminate="yes">Unsupported payload type encountered.</xsl:message>
    </xsl:otherwise>
</xsl:choose>

Evaluation occurs from top to bottom. The first <xsl:when> condition that evaluates to true is executed.

Schema-Aware Considerations

When working with standard, non-schema-aware XSLT processors, elements and attributes parsed directly from source XML documents typically carry the type xs:untyped or xs:untypedAtomic.

To verify such values against specific schema types, cast or convert them first, or configure a schema-aware processor (such as Saxon-EE) with an active XML Schema (xsl:import-schema). Once schema validation is active, typed nodes retain their specific types, allowing expressions like price instance of xs:decimal to evaluate accurately based on the source document's schema definitions.
