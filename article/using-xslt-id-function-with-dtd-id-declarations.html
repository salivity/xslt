Using XSLT id() Function with DTD ID Declarations

The id() function in XSLT provides a fast, direct mechanism to retrieve elements from an XML document based on unique identifiers declared in a Document Type Definition (DTD). Rather than scanning the entire document tree using standard attribute matching, the id() function leverages the parser's internal index of elements that possess an attribute explicitly defined with the ID type in the DTD. This article explains how the XSLT processor relies on DTD validation to identify these attributes, how the function evaluates queries, and how it behaves during transformation.

The Role of the DTD

In standard XML, an attribute named id is treated as plain text (CDATA) unless declared otherwise. The XSLT engine cannot inherently recognize an attribute as a unique identifier by its name alone. A DTD must be present to establish the attribute type:

<!DOCTYPE catalog [
  <!ELEMENT catalog (item+)>
  <!ELEMENT item (name)>
  <!ATTLIST item itemId ID #REQUIRED>
  <!ELEMENT name (#PCDATA)>
]>
<catalog>
  <item itemId="A101">
    <name>Widget</name>
  </item>
</catalog>

In this declaration, itemId ID #REQUIRED informs the XML parser that the itemId attribute contains a unique identifier belonging to the ID type.

How the XML Parser Prepares the Data Model

Before XSLT processing begins, a DTD-aware XML parser reads the document:

  1. Validation and Indexing: When the parser encounters an attribute declared as ID, it validates that the value adheres to XML naming rules (e.g., cannot start with a number) and ensures each value is unique within the document.
  2. Flagging in the Tree: The parser constructs the XPath/XSLT data model, marking these specific attributes as unique identifiers associated with their parent elements.
  3. Lookup Table Creation: Most XSLT processors build an internal hash table or index of these IDs during tree construction to enable constant-time \(O(1)\) lookups.

Syntax and Evaluation of id()

The id() function accepts a string, a node-set, or an object convertible to a string, and returns a node-set containing the matching elements:

id('A101')

When evaluated:

  • If passed a single string (e.g., 'A101'), the processor queries the index for the element whose DTD-declared ID matches 'A101'.
  • If passed a whitespace-separated string (e.g., 'A101 B202'), the function splits the string and returns all elements matching any of the tokens.
  • If passed a node-set, the function converts each node in the set to its string-value and returns the union of all corresponding matching elements.

Example Usage in an XSLT Template

<xsl:template match="/">
  <!-- Directly selects the item with itemId="A101" -->
  <xsl:value-of select="id('A101')/name"/>
</xsl:template>

Behavior Without a DTD

If an XML document does not contain a DTD (or an XML Schema that assigns ID types), the parser treats attributes like id="A101" as standard text attributes. Under these conditions:

  • The call id('A101') returns an empty node-set because no attributes were marked as type ID.
  • Developers must instead rely on standard predicates such as //*[@id = 'A101'] or use the XSLT <xsl:key> element and the key() function to manually define indexing criteria.
