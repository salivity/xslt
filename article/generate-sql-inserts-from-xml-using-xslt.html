Generate SQL Inserts from XML Using XSLT

Transforming raw XML datasets into SQL insertion scripts is a common requirement when migrating data or seeding relational databases. By utilizing Extensible Stylesheet Language Transformations (XSLT), developers can parse structured XML nodes and output formatted INSERT INTO SQL statements directly. This article explains how to configure an XSLT stylesheet with text output, map XML elements to relational database columns, and handle common challenges such as escaping special characters and managing data types.

Setting Up the XSLT Output Mode

By default, XSLT transforms XML into another XML document or HTML. To produce a plain-text SQL script, the <xsl:output> element must explicitly specify method="text". This instructs the XSLT processor to omit XML declarations and render only the string values produced by the templates.

<xsl:output method="text" encoding="UTF-8" indent="no"/>

Sample XML Dataset

Consider a scenario where an XML file contains customer records that need to be loaded into a database table named customers:

<?xml version="1.0" encoding="UTF-8"?>
<customers>
    <customer id="101">
        <name>Jane Doe</name>
        <email>jane.doe@example.com</email>
        <status>active</status>
    </customer>
    <customer id="102">
        <name>John O'Connor</name>
        <email>john.o@example.com</email>
        <status>pending</status>
    </customer>
</customers>

Creating the XSLT Transformation

The stylesheet iterates over each <customer> record and writes the corresponding SQL INSERT statement. Text matching elements and attributes are selected using XPath.

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="2.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="text" encoding="UTF-8"/>

    <xsl:template match="/customers">
        <xsl:for-each select="customer">
            <xsl:text>INSERT INTO customers (id, name, email, status) VALUES (</xsl:text>
            <xsl:value-of select="@id"/>
            <xsl:text>, '</xsl:text>
            <!-- Escaping single quotes in strings -->
            <xsl:value-of select="replace(name, '''', '''''')"/>
            <xsl:text>', '</xsl:text>
            <xsl:value-of select="replace(email, '''', '''''')"/>
            <xsl:text>', '</xsl:text>
            <xsl:value-of select="status"/>
            <xsl:text>');&#10;</xsl:text>
        </xsl:for-each>
    </xsl:template>
</xsl:stylesheet>

Handling SQL Syntax Nuances

When mapping XML to SQL, special care must be taken with string manipulation and data formats:

  1. Escaping Single Quotes: String values in SQL are enclosed in single quotes. If a data value contains an apostrophe (like "O'Connor"), it must be escaped by doubling the quote (''). In XSLT 2.0 or 3.0, the replace() function handles this natively. In XSLT 1.0, a recursive named template is required to replace ' with ''.
  2. Null Values and Optional Elements: If an XML node is optional, use conditional logic (<xsl:choose> or <xsl:if>) to output NULL instead of an empty quoted string ('').
  3. Data Types: Numeric values and booleans should be rendered without quotes, while strings, dates, and timestamps must be wrapped in single quotation marks according to SQL dialect rules.
  4. Newlines and Whitespace: Using the &#10; entity prints a line break at the end of each SQL statement, making the generated .sql file readable and easy to execute line-by-line.

Running the Transformation

The transformation can be executed using any standard XSLT processor. Using command-line tools like xsltproc (for XSLT 1.0) or Saxon (for XSLT 2.0/3.0), the command generates an executable SQL script:

java -jar saxon-he.jar -s:data.xml -xsl:transform.xslt -o:output.sql

The resulting output.sql file contains ready-to-run statements:

INSERT INTO customers (id, name, email, status) VALUES (101, 'Jane Doe', 'jane.doe@example.com', 'active');
INSERT INTO customers (id, name, email, status) VALUES (102, 'John O''Connor', 'john.o@example.com', 'pending');

This method is lightweight, portable, and allows developers to generate repeatable, database-agnostic import scripts without needing specialized ETL software.
