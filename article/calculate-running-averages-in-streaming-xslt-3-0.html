Calculate Running Averages in Streaming XSLT 3.0

Processing massive or unbounded XML feeds without exhausting memory requires stream-based processing. In XSLT 3.0, streaming allows you to parse documents without building a complete in-memory tree, but it restricts backward axes and multiple node visits. To compute stateful metrics such as running averages over this data, XSLT 3.0 provides accumulators. This article explains how to design, configure, and evaluate an xsl:accumulator to capture running sums and counts simultaneously, allowing you to compute and output running averages on the fly.

The Challenge of Streaming State

In an XSLT 3.0 streaming transformation, nodes pass through a processing pipeline sequentially. Because previous nodes cannot be re-inspected once consumed, you cannot use aggregate functions like avg() or sum() over preceding siblings.

Accumulators solve this restriction by passively observing the input document as it is parsed. They update an internal state whenever matching node events occur, without interrupting or violating streamability constraints.

Designing the Accumulator

To maintain a running average, the accumulator must track two values for every processed element:

  1. The accumulated sum of the target metric.
  2. The total count of items encountered so far.

Because an accumulator variable holds a single typed item, the cleanest approach in XPath 3.1 is to store a map containing both values.

Accumulator Declaration

Below is the declaration of a streamable accumulator that listens for incoming <reading> elements, extracts their numeric values, and stores the updated total and counter:

<xsl:accumulator name="running-average"
                 as="map(xs:string, xs:decimal)"
                 initial-value="map { 'sum': 0.0, 'count': 0 }"
                 streamable="yes">
    
    <xsl:accumulator-rule match="reading"
                          select="let $val := xs:decimal(@value)
                                  return map {
                                      'sum': $value?sum + $val,
                                      'count': $value?count + 1
                                  }"/>
</xsl:accumulator>

In this definition:

  • as="map(xs:string, xs:decimal)" sets the data model for the state.
  • initial-value initializes the state before any node matching occurs.
  • streamable="yes" informs the processor to evaluate this accumulator during streaming.
  • $value refers to the accumulator's current state before the rule executes.
  • The rule updates both 'sum' and 'count' whenever a <reading> element is traversed.

Reading the Accumulator State

XSLT 3.0 provides two built-in functions to read an accumulator: accumulator-before() and accumulator-after(). When calculating a running average for the current element:

  • accumulator-before('running-average') returns the state prior to processing the current node.
  • accumulator-after('running-average') returns the updated state including the current node.

To compute the running average at the current point in the stream, access the post-evaluation state using accumulator-after(), divide the sum by the count, and round as needed.

Complete Streaming Example

Here is a full XSLT 3.0 stylesheet demonstrating the streaming process:

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
                xmlns:xs="http://www.w3.org/2001/XMLSchema"
                version="3.0"
                expand-text="yes">

    <xsl:mode streamable="yes" on-no-match="shallow-skip" use-accumulators="running-average"/>
    <xsl:output method="xml" indent="yes"/>

    <xsl:accumulator name="running-average"
                     as="map(xs:string, xs:decimal)"
                     initial-value="map { 'sum': 0.0, 'count': 0 }"
                     streamable="yes">
        <xsl:accumulator-rule match="reading"
                              select="let $val := xs:decimal(@value)
                                      return map {
                                          'sum': $value?sum + $val,
                                          'count': $value?count + 1
                                      }"/>
    </xsl:accumulator>

    <xsl:template match="dataset">
        <results>
            <xsl:apply-templates select="reading"/>
        </results>
    </xsl:template>

    <xsl:template match="reading">
        <xsl:variable name="state" select="accumulator-after('running-average')"/>
        <entry id="{@id}" value="{@value}">
            <average>{$state?sum div $state?count}</average>
        </entry>
    </xsl:template>

</xsl:stylesheet>

Input Data

<dataset>
    <reading id="1" value="10.0"/>
    <reading id="2" value="20.0"/>
    <reading id="3" value="15.0"/>
</dataset>

Output Data

<results>
    <entry id="1" value="10.0">
        <average>10</average>
    </entry>
    <entry id="2" value="20.0">
        <average>15</average>
    </entry>
    <entry id="3" value="15.0">
        <average>15</average>
    </entry>
</results>

Key Considerations

  • Streamability Rules: The use-accumulators attribute must be declared on <xsl:mode> to activate accumulator monitoring across the stream.
  • Division by Zero: If using accumulator-before() on the very first node, implement a check (e.g., if ($state?count gt 0)) to avoid division by zero errors.
  • Memory Footprint: Maps are immutable in XPath; using simple maps with numeric values creates minimal garbage collection overhead, ensuring steady memory utilization regardless of the total stream size.
