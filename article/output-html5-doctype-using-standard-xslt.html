Output HTML5 Doctype Using Standard XSLT

Generating a clean, modern <!DOCTYPE html> declaration using standard XSLT serializers can be challenging because earlier XSLT specifications were designed around legacy HTML and XML standards that mandated PUBLIC or SYSTEM identifiers. Depending on whether your transformation engine runs XSLT 1.0, 2.0, or 3.0, the approach ranges from native serialization parameters to legacy-compatible workarounds and output escaping.

XSLT 3.0: The Native Solution

The W3C XSLT and XQuery Serialization 3.0 specification natively supports HTML5 output. If your processor supports XSLT 3.0 (such as Saxon 9.8+), you simply configure the <xsl:output> element with the html-version attribute.

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:output method="html" html-version="5.0" encoding="UTF-8" indent="yes"/>
  
  <xsl:template match="/">
    <html>
      <head>
        <title>HTML5 Document</title>
      </head>
      <body>
        <main>Content goes here.</main>
      </body>
    </html>
  </xsl:template>
</xsl:stylesheet>

This configuration outputs the exact HTML5 doctype declaration:

<!DOCTYPE HTML>

XSLT 2.0: The Legacy-Compat Approach

XSLT 2.0 serializers strictly adhere to older rules where a doctype must include either a doctype-system or doctype-public attribute. Consequently, supplying an empty string or omitting these attributes results in either an invalid doctype or no doctype at all.

To handle this, the HTML5 specification officially permits an alternative doctype known as the "obsolete permitted DOCTYPE" specifically for legacy generators:

<xsl:output method="html" 
            encoding="UTF-8" 
            doctype-system="about:legacy-compat" 
            indent="yes"/>

This generates:

<!DOCTYPE html SYSTEM "about:legacy-compat">

Modern web browsers recognize this string as fully valid HTML5 and will trigger standard standards mode rendering without quirks.

XSLT 1.0: Workarounds for Strict <!DOCTYPE html>

In XSLT 1.0, processors like libxslt or older MSXML engines cannot generate a standalone <!DOCTYPE html> through standard <xsl:output> attributes. If you require the exact string without about:legacy-compat, you must bypass standard serialization.

Method 1: Disable Output Escaping

The most common approach in XSLT 1.0 is omitting the doctype attributes from <xsl:output> and explicitly emitting the string at the root of the output document using disable-output-escaping.

<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:output method="html" encoding="UTF-8" indent="yes"/>
  
  <xsl:template match="/">
    <xsl:text disable-output-escaping="yes">&lt;!DOCTYPE html&gt;&#xA;</xsl:text>
    <html>
      <head>
        <title>HTML5 Document</title>
      </head>
      <body>
        <p>Generated via XSLT 1.0</p>
      </body>
    </html>
  </xsl:template>
</xsl:stylesheet>

Note: disable-output-escaping may not be supported in environments where the XSLT processor outputs directly to a DOM tree rather than a serialized text stream.

Method 2: Processor-Specific Extensions

Many common XSLT 1.0 and 2.0 processors offer custom extension attributes to omit the system identifier while keeping the doctype prefix:

  • Saxon (PE/EE): Allows setting saxon:doctype-system="" alongside <xsl:output> to suppress the system identifier completely.
  • Xalan: Certain distributions support empty string values for doctype-system directly on the <xsl:output> element to force a minimal doctype.
