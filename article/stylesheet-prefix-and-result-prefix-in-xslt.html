stylesheet-prefix and result-prefix in XSLT

The <xsl:namespace-alias> element in XSLT maps a namespace used within a stylesheet to a different namespace in the generated output document. This mechanism is primarily utilized when an XSLT stylesheet generates another XSLT stylesheet or other XML formats where namespace collisions occur during processing. The stylesheet-prefix and result-prefix attributes define this mapping by identifying which namespace prefix in the stylesheet acts as the placeholder and which target namespace replaces it in the final result.

The Function of stylesheet-prefix

The stylesheet-prefix attribute designates the namespace prefix used within the stylesheet for literal result elements. When an author needs to output elements that belong to an executable namespace—most commonly the XSLT namespace itself—without the processor attempting to execute them, an alternate prefix is assigned to those elements.

The stylesheet-prefix informs the processor which prefix is acting as the temporary alias. The accepted values are:

  • A valid prefix (NCName) declared in the scope of the <xsl:namespace-alias> element.
  • #default, which targets the default namespace (elements without a prefix) within the current scope.

The Function of result-prefix

The result-prefix attribute specifies the target namespace that will appear in the output document. While stylesheet-prefix identifies what to match inside the stylesheet template, result-prefix defines the actual namespace URI that the matched elements will inherit in the output.

The accepted values are:

  • A valid prefix (NCName) associated with the intended final namespace URI.
  • #default, indicating that the resulting elements in the output should belong to the default namespace without a prefix.

How They Work Together

When transforming documents, the processor identifies any literal result element whose namespace URI matches the namespace mapped by stylesheet-prefix. Upon serializing the result tree, the processor changes the element's namespace URI to match the namespace URI bound to result-prefix.

For example, generating an XSLT stylesheet requires using an alias such as axsl:

<xsl:stylesheet version="1.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:axsl="http://www.w3.org/1999/XSL/TransformAlias">

    <xsl:namespace-alias stylesheet-prefix="axsl" result-prefix="xsl"/>

    <xsl:template match="/">
        <axsl:stylesheet version="1.0">
            <axsl:template match="item">
                <axsl:value-of select="."/>
            </axsl:template>
        </axsl:stylesheet>
    </xsl:template>

</xsl:stylesheet>

In this transformation:

  • The template uses axsl on elements so the executing processor treats them as inert text and markup rather than instructions.
  • stylesheet-prefix="axsl" identifies this placeholder prefix.
  • result-prefix="xsl" swaps the placeholder namespace URI (http://www.w3.org/1999/XSL/TransformAlias) with the target XSLT namespace URI (http://www.w3.org/1999/XSL/Transform) in the final output.
