Running XSLT 3.0 in Node.js and Headless Browsers

Native web browsers and the Node.js runtime only support legacy XSLT 1.0 out of the box, leaving modern XSLT 3.0 specifications unsupported by default. However, developers can reliably execute XSLT 3.0 transformations across both Node.js runtimes and headless browser automation frameworks—such as Puppeteer and Playwright—by leveraging Saxonica's Saxon-JS engine alongside Stylesheet Export Format (SEF) precompilation.

The Challenge with Native Processors

Modern web engines (Blink, Gecko, WebKit) have frozen their native XML transformation capabilities at the XSLT 1.0 standard via the browser-level XSLTProcessor API. Node.js features no built-in XSLT processor. To use modern XSLT 3.0 features—such as streaming, JSON manipulation, higher-order functions, and packages—you must execute an external JavaScript-based processor or interface with an external native runtime.

Executing XSLT 3.0 in Node.js

The standard method for executing XSLT 3.0 within Node.js is using Saxon-JS, a high-performance XSLT 3.0 processor written entirely in JavaScript.

1. Compile XSLT to SEF

Saxon-JS does not interpret raw .xsl files directly at runtime in JavaScript. Instead, the stylesheet must first be compiled into an intermediate JSON-based format called Stylesheet Export File (SEF).

Install the compiler globally or as a project dependency:

npm install -g xslt3

Compile your stylesheet:

xslt3 -xsl:transform.xsl -export:transform.sef.json -t -ns:xml=true

2. Run the Transformation in Node.js

Install the runtime library:

npm install saxon-js

Use the SaxonJS.transform method to execute the transformation asynchronously:

const SaxonJS = require("saxon-js");
const fs = require("fs");

async function runTransformation() {
  const result = await SaxonJS.transform({
    stylesheetFileName: "transform.sef.json",
    sourceFileName: "input.xml",
    destination: "serialized"
  }, "async");

  fs.writeFileSync("output.xml", result.principalResult);
}

runTransformation().catch(err => console.error(err));

The destination property can be set to "serialized" for string output, "document" for a parsed DOM tree, or "raw" for direct XSLT return items (useful when outputting JSON).

Executing XSLT 3.0 in Headless Browsers

When running headless browser instances with tools like Puppeteer or Playwright, you cannot rely on the window-level XSLTProcessor for XSLT 3.0. Instead, you inject the browser-compatible build of Saxon-JS into the virtual DOM page context.

Implementation with Playwright or Puppeteer

  1. Compile the .xsl file to transform.sef.json.
  2. Launch the headless browser instance and navigate to a blank or host page.
  3. Inject the SaxonJS2.js browser bundle into the page context.
  4. Execute SaxonJS.transform() inside the browser's execution context using page evaluation.

Example using Playwright:

const { chromium } = require("playwright");
const fs = require("fs");

(async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();

  // Load an empty page
  await page.goto("about:blank");

  // Inject Saxon-JS into the headless browser environment
  await page.addScriptTag({
    path: require.resolve("saxon-js/SaxonJS2.rt.js")
  });

  const sefContent = fs.readFileSync("transform.sef.json", "utf8");
  const xmlContent = fs.readFileSync("input.xml", "utf8");

  // Execute the transformation within the browser context
  const output = await page.evaluate(async ({ sef, xml }) => {
    const result = await window.SaxonJS.transform({
      stylesheetText: sef,
      sourceText: xml,
      destination: "serialized"
    }, "async");

    return result.principalResult;
  }, { sef: sefContent, xml: xmlContent });

  console.log(output);
  await browser.close();
})();

Alternative: Server-Side Execution via Java Bridge

If compiling XSLT files into SEF format is not feasible for your pipeline, and you only require Node.js execution without browser rendering, you can execute Saxon-HE via a child process:

const { execFile } = require("child_process");

execFile("java", [
  "-jar", "saxon-he-12.x.jar",
  "-s:input.xml",
  "-xsl:transform.xsl",
  "-o:output.xml"
], (error, stdout, stderr) => {
  if (error) {
    console.error("Transformation failed:", stderr);
    return;
  }
  console.log("Transformation complete.");
});

This approach bypasses the SEF compilation step and runs the raw XSLT 3.0 directly, but it introduces a dependency on the Java Runtime Environment (JRE). For pure JavaScript and headless browser environments, the Saxon-JS and SEF approach remains the standard and most performant architecture.
