Enforcing Cardinality with zero-or-one in XSLT

This article provides an overview of the zero-or-one() function in XPath and XSLT, focusing on how it enforces sequence cardinality constraints during transformations. By examining its mechanics, error handling, and practical use cases, you will understand how this function guarantees data integrity, prevents downstream processing bugs, and ensures that expressions only evaluate to either an empty sequence or a single item.

The Purpose of zero-or-one()

In XSLT 2.0 and later versions, standard XPath operations work heavily with sequences. Many transformation operations assume that an expression will evaluate to an optional single value—meaning zero items or exactly one item.

The fn:zero-or-one() function acts as an explicit runtime check to enforce this specific cardinality constraint (? occurrence indicator). Its signature is:

fn:zero-or-one($arg as item()*) as item()?

The function evaluates the input sequence $arg and behaves according to the number of items it finds:

  • Empty sequence (()): Returns an empty sequence without error.
  • Single item: Returns the single item intact.
  • Two or more items: Immediately raises a dynamic error (err:FORG0003).

Why Cardinality Enforcement Matters

In loosely validated XML environments or transformations processing third-party data, documents may unexpectedly contain duplicate elements. When an XSLT template expects at most one element (such as an optional <email> or <middle-name>), unconstrained queries can introduce subtle, hard-to-debug defects.

Without explicit cardinality checks, expressions that evaluate to multiple items might either cause silent errors or trigger unintended behavior depending on the processor context (such as taking only the first item in XPath 1.0 compatibility mode or concatenating values unexpectedly).

Using zero-or-one() guarantees a "fail-fast" mechanism. If an input contains unexpected duplicate nodes, the stylesheet halts execution with an explicit error rather than passing corrupt or ambiguous data into subsequent logic.

Practical Usage Example

Consider an incoming customer XML payload where a customer might have no secondary address or at most one secondary address:

<customer>
    <id>1042</id>
    <secondary-address>123 Maple St</secondary-address>
    <secondary-address>456 Oak Ave</secondary-address>
</customer>

To strictly assert that the customer cannot have more than one secondary address before assigning it to a variable, apply zero-or-one():

<xsl:variable name="altAddress" select="zero-or-one(customer/secondary-address)" />

Because the XML contains two <secondary-address> nodes, the processor throws dynamic error FORG0003. If the element were present once, $altAddress would hold that single node. If absent, $altAddress would be assigned an empty sequence without throwing an error.

Context within Cardinality Functions

The zero-or-one() function is part of a standard family of XPath cardinality assertion functions:

  • fn:zero-or-one($seq): Enforces zero or one item (?).
  • fn:exactly-one($seq): Enforces strictly one item (no occurrence indicator / mandatory).
  • fn:one-or-more($seq): Enforces at least one item (+).

Using zero-or-one() makes transformation logic self-documenting by explicitly signaling to future maintainers that the operation expects an optional single item rather than an arbitrary list of nodes.
