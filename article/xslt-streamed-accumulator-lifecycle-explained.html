XSLT Streamed Accumulator Lifecycle Explained

In XSLT 3.0 streaming, an accumulator provides a stateful mechanism to compute and retain values during a single-pass, depth-first traversal of an XML document without buffering the entire tree in memory. Because streamed execution permits only a single forward scan of the document events, accumulator values evolve through strictly defined pre-descent and post-descent phases at each node. Understanding this lifecycle ensures that streamed stylesheets accurately track document context, generate aggregations, and access previous structural data without violating streaming rules.

Initialization

The lifecycle begins when the streaming processor starts reading the document. An accumulator is declared using the xsl:accumulator element, which specifies an initial-value attribute. At the document root before any children are visited, the accumulator's expression is evaluated to set its base state. This initial value serves as the input value for the first matched rule during traversal.

Pre-Descent Evaluation (phase="start")

As the parser encounters an opening tag (start-element), the accumulator enters its pre-descent phase:

  1. Context State: The current value of the accumulator is inherited either from the immediately preceding sibling's post-descent value or from the parent node’s pre-descent value if the node is a first child.
  2. Rule Matching: The processor checks all xsl:accumulator-rule elements with phase="start" (the default phase) that match the current node.
  3. Value Transition: If a matching rule exists, its select expression is evaluated using the inherited value as $value. The result becomes the new value of the accumulator for that node.
  4. Availability: Within templates matching this node, this state is retrieved using the accumulator-before() function. It remains the baseline state passed down to the node's descendants.

Descent and Child Processing

During the traversal of child nodes, the accumulator state is passed sequentially down the tree:

  • Child nodes receive the parent's phase="start" value when processing begins.
  • Each child evaluates its own rules, transitions its state, processes its own descendants, and finishes.
  • Subsequent siblings inherit the accumulator value produced by the end of the immediately preceding sibling's subtree traversal, maintaining a continuous chain of state across the document.

Post-Descent Evaluation (phase="end")

When the processor finishes processing all descendants of an element and encounters its closing tag (end-element), the post-descent phase triggers:

  1. Context State: The accumulator’s current value is the state left behind by the last processed descendant (or the node’s own phase="start" value if the node had no children).
  2. Rule Matching: The processor evaluates any xsl:accumulator-rule elements with phase="end" that match the node.
  3. Value Transition: If a match is found, its select expression executes using the post-children value as $value, updating the accumulator to its final state for this element.
  4. Availability: This updated value can be accessed via accumulator-after().

State Propagation and Completion

Once the post-descent phase finishes for a node, its resulting value is passed directly to the next structural event:

  • If the node has a following sibling, that sibling uses this value as its starting state.
  • If the node is the last child of its parent, the value becomes the input to the parent’s post-descent (phase="end") phase.

This cycle of start evaluation, recursive descent, and end evaluation repeats until the document traversal completes. When the processor closes the document root, the final post-descent value becomes the terminal state of the accumulator, completing its lifecycle without requiring tree-based memory retention.
