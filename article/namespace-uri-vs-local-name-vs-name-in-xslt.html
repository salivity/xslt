namespace-uri vs local-name vs name in XSLT

In XSLT and XPath, navigating and matching XML elements accurately requires a clear understanding of how an element's identity is constructed. XML nodes with namespaces have an expanded name consisting of a namespace URI and a local name, alongside an optional prefix used in the source document. The functions namespace-uri(), local-name(), and name() serve distinct purposes by extracting different components of this identity. Understanding their differences is essential for writing robust node tests that do not break when XML prefixes change.

XML Name Components

To understand these functions, consider an XML element defined with a prefix and a namespace:

<inv:product xmlns:inv="https://example.com/inventory">Widget</inv:product>

This node has three separate naming components:

  • Namespace URI: https://example.com/inventory (the globally unique identifier)
  • Local Name: product (the element name stripped of any prefix)
  • Prefix: inv (a local alias mapped to the namespace URI within the document)

The namespace-uri() Function

The namespace-uri() function returns the string representing the namespace URI of the node passed as an argument (or the context node if omitted).

  • Behavior: It resolves to the actual URI string, not the prefix.
  • No Namespace: If the node does not belong to a namespace, it returns an empty string ("").
  • Example Output: For <inv:product>, namespace-uri() returns "https://example.com/inventory".

The local-name() Function

The local-name() function returns the local part of the node's expanded name as a string.

  • Behavior: It completely strips out any namespace prefix and ignores the namespace URI.
  • No Namespace: If the node has no prefix, the returned string is simply the node name.
  • Example Output: For <inv:product>, local-name() returns "product".

The name() Function

The name() function returns the qualified name (QName) of the node exactly as it appears or resolves in the context of the source document, represented as a string.

  • Behavior: If the node has a prefix, name() returns prefix:local-name. If there is no prefix, it returns only the local name.
  • Caveat: The output depends directly on the prefix chosen by the author of the XML document.
  • Example Output: For <inv:product>, name() returns "inv:product".

Key Differences in Node Testing

The functional difference becomes critical when evaluating nodes in XPath expressions and XSLT templates:

Function What It Returns Dependent on XML Prefix?
namespace-uri() The namespace URI string No
local-name() The element name without prefix No
name() prefix:local-name (or just local-name) Yes

Why name() Is Fragile in Node Tests

Testing nodes using name() is generally discouraged in production stylesheets:

<!-- Fragile: Fails if the source XML uses a different prefix like <inventory:product> -->
<xsl:if test="name() = 'inv:product'"> ... </xsl:if>

Because XML prefixes are arbitrary and can vary between documents (or even within the same document), matching against the literal string "inv:product" causes the transformation to fail if the incoming XML uses <item:product xmlns:item="https://example.com/inventory">.

Combining local-name() and namespace-uri()

When dynamic prefix matching is required, or when working in environments where namespace prefixes cannot be declared ahead of time in the stylesheet, combining local-name() and namespace-uri() provides a reliable, prefix-agnostic test:

<!-- Robust: Matches regardless of prefix -->
<xsl:if test="local-name() = 'product' and namespace-uri() = 'https://example.com/inventory'">
    ...
</xsl:if>

Ignoring Namespaces

If you need to match an element purely by its tag name while ignoring namespaces entirely, local-name() is the correct choice:

<!-- Matches <product>, <inv:product>, or <shop:product> -->
<xsl:apply-templates select="*[local-name() = 'product']" />

In standard XSLT development, standard QName matching (declaring the namespace in the stylesheet and using prefix:element) is the preferred approach. However, when runtime inspection functions are required, use namespace-uri() to check identity against the URI standard, local-name() to evaluate the tag independently of prefixes, and avoid name() unless prefix preservation is explicitly required.
