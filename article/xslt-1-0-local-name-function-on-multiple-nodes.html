XSLT 1.0 local-name Function on Multiple Nodes

In XSLT 1.0, applying the local-name() function to a node-set containing multiple items results in the function returning the local name of only the first node in document order. Any subsequent nodes in the node-set are completely ignored during evaluation. This article explains the technical mechanics behind this behavior, the rules governing document order, and how to properly extract names from multiple nodes.

The First Node Rule

The XPath 1.0 specification (Section 4.1, Node Set Functions) defines the behavior of local-name() when supplied with an argument:

"The local-name function returns the local part of the expanded-name of the node in the argument node-set that is first in document order. If the argument node-set is empty or the first node has no expanded-name, an empty string is returned."

Unlike XSLT 2.0 and later versions—which use XPath 2.0 sequence handling and will raise a type error if a sequence of more than one item is passed to a function expecting a single item—XPath 1.0 silently truncates the set to its first member in document order.

Example Behavior

Consider the following XML fragment:

<catalog>
    <book id="1">XPath Guide</book>
    <magazine id="2">Tech Weekly</magazine>
    <journal id="3">Science Today</journal>
</catalog>

If you evaluate the following expression in an XSLT 1.0 template:

<xsl:value-of select="local-name(/catalog/*)"/>

The node-set /catalog/* contains three elements: <book>, <magazine>, and <journal>. The function processes this node-set, identifies <book> as the first node in document order, and returns:

book

The <magazine> and <journal> nodes produce no output and cause no errors or warnings.

Document Order Matters

The selected node is strictly determined by document order, not by the order of predicates or sub-expressions used to build the node-set. For instance:

<xsl:value-of select="local-name(//journal | //book)"/>

Even though //journal appears first in the union expression, <book> precedes <journal> in the source document. Therefore, local-name() still returns book.

How to Process Multiple Nodes

Because local-name() cannot return a list or array of names in XSLT 1.0, you must iterate over the node-set using <xsl:for-each> or apply templates if you need the local name of every node in the collection:

<xsl:for-each select="/catalog/*">
    <xsl:value-of select="local-name()"/>
    <xsl:if test="position() != last()">, </xsl:if>
</xsl:for-each>

When local-name() is invoked without arguments, it defaults to a node-set containing only the context node, properly outputting: book, magazine, journal.
