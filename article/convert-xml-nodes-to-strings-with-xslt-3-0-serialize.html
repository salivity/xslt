Convert XML Nodes to Strings with XSLT 3.0 serialize

The fn:serialize() function in XSLT 3.0 provides a native mechanism to transform an in-memory XDM (XQuery and XPath Data Model) node-tree into its lexical XML string representation. This overview covers the mechanics of the fn:serialize() function, including how it accepts node sequences, applies serialization parameters to format the output, and produces an escaped character string suitable for embedding inside attributes, other elements, or external text payloads.

Function Signature and Inputs

The fn:serialize() function is defined in XPath and XQuery Functions and Operators 3.0/3.1 and is natively available in XSLT 3.0. It provides two signatures:

fn:serialize($arg as item()*) as xs:string
fn:serialize($arg as item()*, $params as element(output:serialization-parameters)?) as xs:string
  • $arg: The sequence of items to serialize, typically a document node, an element node, or a sequence of nodes.
  • $params: An optional <output:serialization-parameters> element defining serialization properties (such as method, indentation, and omitting the XML declaration).

How the Node-Tree is Processed

When an in-memory node-tree is passed to fn:serialize(), the processor traverses the node hierarchy using the standard W3C Serialization specification:

  1. Tree Traversal: The processor traverses the node and its descendants in document order, reading element names, attributes, namespaces, comments, processing instructions, and text nodes.
  2. Grammar Reconstruction: It reconstructs the lexical markup syntax from the parsed tree, generating opening tags (<tag>), attributes (attr="value"), closing tags (</tag>), and self-closing tags (<tag/>).
  3. Namespace Resolution: In-scope namespaces for each element are resolved and serialized as xmlns attributes where necessary.

Controlling Output with Serialization Parameters

By default, fn:serialize($node) serializes output using the default XML method settings. You can override these defaults by supplying an <output:serialization-parameters> element from the http://www.w3.org/2010/xslt-xquery-serialization namespace.

<xsl:variable name="params" as="element()">
  <output:serialization-parameters xmlns:output="http://www.w3.org/2010/xslt-xquery-serialization">
    <output:method value="xml"/>
    <output:omit-xml-declaration value="yes"/>
    <output:indent value="no"/>
  </output:serialization-parameters>
</xsl:variable>

<xsl:variable name="xml-string" select="serialize($myNode, $params)"/>

Alternatively, XSLT 3.0 allows using an xsl:output declaration via the fn:serialize() parameter map or referencing named <xsl:output> definitions depending on processor capabilities.

How Escaping Works

The concept of "escaped string" operates on two distinct levels during serialization:

  1. Internal Content Escaping: Within the generated string itself, text content inside elements is escaped according to XML rules. Characters like & and < in text nodes become &amp; and &lt;.
  2. Escaping in the Result Tree: Because fn:serialize() returns an xs:string, placing the result into an XML result tree node causes the serialization process of the outer stylesheet to escape all markup characters. For example, the opening tag <item> inside the string becomes &lt;item&gt; in the final document output.
<!-- Source XML Fragment -->
<data>
  <user id="101">John &amp; Doe</user>
</data>

<!-- XSLT 3.0 Expression -->
<payload>
  <xsl:value-of select="serialize(data/user)"/>
</payload>

The resulting output document:

<payload>&lt;user id="101"&gt;John &amp;amp; Doe&lt;/user&gt;</payload>

The outer markup parser preserves the string as character data, preventing the serialized fragment from being interpreted as active nodes within the parent tree.
