Missing Mandatory xsl:param in XSLT Explained

When a mandatory <xsl:param> lacks a default value and is omitted during template invocation, the behavior depends on the XSLT version being executed. In modern XSLT (2.0 and 3.0), failing to supply an explicitly required parameter triggers a fatal dynamic error that halts stylesheet execution. In legacy XSLT 1.0, there is no native construct for a mandatory parameter, meaning an omitted parameter without an explicit default simply evaluates to an empty string rather than throwing an error.

Behavior in XSLT 2.0 and XSLT 3.0

XSLT 2.0 introduced the required attribute to formalize mandatory parameters. A parameter is explicitly designated as mandatory using the syntax:

<xsl:param name="paramName" required="yes"/>

According to the W3C XSLT specification:

  • Disallowed Defaults: A parameter marked with required="yes" is legally forbidden from having a default value. Attempting to provide one via the select attribute or within the element body generates a static error (XTSE0010).
  • Missing Value Execution Error: If a template containing a required="yes" parameter is invoked via <xsl:call-template> or <xsl:apply-templates> without a matching <xsl:with-param> element, the XSLT processor raises dynamic error XTDE0700. Unless caught by an xsl:try block in XSLT 3.0, this terminates transformation immediately.

Type-Checking Complications

If a parameter lacks the required="yes" attribute but specifies a type via the as attribute that does not accept an empty sequence or zero-length string (for example, as="xs:integer"), omitting both the default value and the runtime argument causes a dynamic type error (XTTE0590 or XTTE0790). Because the default value for an untyped, empty parameter is an empty string "", the processor fails when attempting to coerce the empty string into the non-nullable target type.

Behavior in XSLT 1.0

XSLT 1.0 does not support the required attribute or typed parameters.

  • Default to Empty String: If <xsl:param name="paramName"/> is defined without a select attribute and with an empty content body, its implicit default value is an empty string ('').
  • Silent Fallback: If the caller omits this parameter, no error is generated. The template executes normally, treating the variable as ''.

To simulate mandatory parameters in XSLT 1.0, developers must explicitly validate the parameter within the template body:

<xsl:template name="exampleTemplate">
    <xsl:param name="requiredParam"/>
    <xsl:if test="not($requiredParam) or $requiredParam = ''">
        <xsl:message terminate="yes">
            Error: Parameter "requiredParam" is required.
        </xsl:message>
    </xsl:if>
    <!-- Template logic continues -->
</xsl:template>

Summary of Processor Outcomes

Specification Parameter Definition Result When Parameter is Omitted
XSLT 1.0 <xsl:param name="p"/> Evaluates silently to empty string ('').
XSLT 2.0 / 3.0 <xsl:param name="p" required="yes"/> Throws dynamic error XTDE0700 and halts.
XSLT 2.0 / 3.0 <xsl:param name="p" as="xs:integer"/> (No default, required="no") Throws dynamic type error XTTE0590 due to empty string mismatch.
