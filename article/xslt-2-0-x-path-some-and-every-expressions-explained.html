XSLT 2.0 XPath Some and Every Expressions Explained

In XSLT 2.0 and XPath 2.0, the some and every keywords form quantified expressions used to test boolean conditions across a sequence of items. This article explains the purpose of these operators, contrasts existential and universal quantification, details their syntax, and demonstrates how to implement them effectively to simplify conditional logic within your XSLT stylesheets.

Understanding Quantified Expressions

Quantified expressions allow you to iterate through an sequence and test each member against an explicit condition, returning a single boolean value: true or false. They replace verbose and error-prone workarounds from XSLT 1.0, such as using count() predicates or complex recursively called templates, with clean, declarative syntax.

The expressions rely on a temporary variable bound to each item in the evaluated sequence.

The Basic Syntax

Both expressions follow the same structural pattern:

some $variable in sequence satisfies test-expression
every $variable in sequence satisfies test-expression

Multiple variables can also be bound within a single expression:

some $x in seq1, $y in seq2 satisfies $x = $y

The some Expression (Existential Quantification)

The some keyword performs existential quantification. It checks whether at least one item in a given sequence satisfies the defined condition.

  • Result is true if the satisfies condition evaluates to true for at least one item.
  • Result is false if no items satisfy the condition, or if the input sequence is completely empty.

Example

Consider an XML document containing an order with multiple items:

<order>
    <item price="25" status="in-stock" />
    <item price="60" status="backordered" />
    <item price="15" status="in-stock" />
</order>

To test if any single item costs more than $50:

some $item in /order/item satisfies xs:decimal($item/@price) > 50

Because the second item has a price of 60, the expression immediately resolves to true().

The every Expression (Universal Quantification)

The every keyword performs universal quantification. It checks whether all items in a given sequence satisfy the defined condition.

  • Result is true if the satisfies condition evaluates to true for every item in the sequence.
  • Result is false if even a single item fails the condition.
  • Vacuous Truth: If the target sequence is empty, every always returns true.

Example

Using the same XML order data, to verify if all items are ready for shipping:

every $item in /order/item satisfies $item/@status = 'in-stock'

Because one item has the status backordered, the condition fails and the expression returns false().

Practical Application in XSLT 2.0

Quantified expressions are most commonly used in xsl:if tests, xsl:when conditions, and template match patterns.

<xsl:template match="order">
    <!-- Apply discounts if every item is eligible -->
    <xsl:if test="every $i in item satisfies $i/@discount-eligible = 'true'">
        <xsl:call-template name="apply-bulk-discount" />
    </xsl:if>

    <!-- Trigger an alert if any item is dangerous -->
    <xsl:if test="some $i in item satisfies $i/@hazardous = 'true'">
        <xsl:call-template name="flag-hazardous-shipment" />
    </xsl:if>
</xsl:template>

Key Benefits

  1. Short-Circuit Evaluation: XPath processors typically stop evaluating items as soon as the final result is guaranteed (e.g., some stops on the first match, and every stops on the first failure), optimizing performance on large node-sets.
  2. Readability: Quantified expressions state intent directly, eliminating the need to write unintuitive logic such as not(item/@status != 'in-stock').
  3. Type Safety: You can cast or validate variables directly within the satisfies clause before performing comparisons.
