Default XSLT Unicode Codepoint Collation Behavior

This article explains the default behavior of the Unicode codepoint collation during string comparisons in modern XSLT. In XSLT 2.0 and later versions, string comparisons and sorting operations rely on the Unicode Codepoint Collation by default unless another collation is explicitly defined. Understanding this behavior is critical for handling case sensitivity, diacritics, and deterministic sorting in XML transformations.

The Default Collation URI

The W3C XPath and XSLT specifications identify the Unicode Codepoint Collation by the URI:

http://www.w3.org/2005/xpath-functions/collation/codepoint

Unless a stylesheet specifies default-collation at the <xsl:stylesheet> level or provides an explicit collation attribute on functions or instructions, an XSLT processor falls back to this collation for all string comparisons.

Mechanics of Unicode Codepoint Comparison

The Unicode Codepoint Collation operates strictly on the numeric scalar values of Unicode characters. It compares strings character by character from left to right:

  1. Numeric Comparison: The processor checks the integer value assigned to each character in the Unicode standard. If the codepoints differ at the first non-matching position, the string containing the lower numeric codepoint is considered smaller.
  2. Length Evaluation: If one string is a prefix of another, the shorter string is evaluated as smaller (e.g., "cat" precedes "catalog").
  3. Exact Matching: Two strings are equal only if they contain the exact same sequence of codepoints.

Key Behavioral Characteristics

  • Strict Case Sensitivity: Because uppercase Latin letters occupy codepoints U+0041 to U+005A and lowercase Latin letters occupy U+0061 to U+007A, all uppercase ASCII characters evaluate as smaller than all lowercase ASCII characters. For example, "Zebra" evaluates as less than "apple".
  • No Canonical Equivalence: The collation does not normalize characters. A precomposed character such as é (U+00E9) will not match an identical visual representation created with the combining character sequence e + ´ (U+0065 followed by U+0301).
  • Absence of Cultural Awareness: The collation ignores language-specific alphabetization rules. For instance, in Swedish, ö comes after z, but in codepoint sorting, standard European accented characters generally appear after the basic ASCII block.
  • Deterministic and High Performance: Because the algorithm avoids complex locale rules, Unicode Collation Algorithm (UCA) weight tables, and case folding, it is the fastest and most predictable method for string comparison across different XSLT processors.

Impact on XSLT Operations

This default collation governs multiple areas of transformation:

  • Comparison Operators: Operators such as <, >, <=, >=, =, and != evaluate strings using their numeric code values.
  • Sorting (<xsl:sort>): Omitting a collation or language specification in an <xsl:sort> instruction defaults to codepoint ordering, grouping all uppercase-initial items ahead of lowercase ones.
  • Functions: Core XPath functions such as fn:compare(), fn:min(), fn:max(), and fn:distinct-values() rely on this behavior unless passed a specific collation argument.
