Difference Between xsl:copy and xsl:copy-of in XSLT

In XSLT transformations, <xsl:copy> and <xsl:copy-of> are both used to duplicate XML nodes from the source tree to the result tree, but they handle child nodes and attributes in fundamentally different ways. The primary difference is the depth of the duplication: <xsl:copy> performs a shallow copy that duplicates only the current node without its attributes or child elements, whereas <xsl:copy-of> performs a deep copy that duplicates the selected node along with all of its attributes, descendant elements, and text content.

Understanding <xsl:copy> (Shallow Copy)

The <xsl:copy> instruction creates a duplicate of the context node itself, including any namespace nodes associated with it, but leaves out all attributes and child elements.

Key characteristics of <xsl:copy>:

  • Shallow duplication: Only the outer tag of the current element is written to the result tree.
  • Can contain child instructions: Because it only copies the element shell, you can place other XSLT instructions inside <xsl:copy>—such as <xsl:apply-templates>, <xsl:attribute>, or literal text—to selectively process, transform, or filter its contents.
  • Context node scope: It always operates implicitly on the current context node; it does not take a select attribute.

Example usage:

<!-- Copies the element tag, but allows templates to modify its attributes and children -->
<xsl:template match="book">
  <xsl:copy>
    <xsl:apply-templates select="@* | node()"/>
  </xsl:copy>
</xsl:template>

This pattern is the foundation of the standard XSLT "identity transform," where nodes are recreated one by one while allowing specific rules to override default behavior.

Understanding <xsl:copy-of> (Deep Copy)

The <xsl:copy-of> instruction performs an exact, recursive clone of the node-set or subtree identified by its select attribute.

Key characteristics of <xsl:copy-of>:

  • Deep duplication: It copies the selected node, all of its attributes, and all descendant nodes (elements, text, comments, processing instructions) in their exact original form.
  • Empty element: <xsl:copy-of> is an empty instruction (self-closing). It cannot contain child XSLT instructions, meaning you cannot alter, filter, or template the internal content of the copied structure.
  • Requires a select attribute: You must specify an XPath expression in the select attribute to indicate which nodes, node-sets, or variables to duplicate.

Example usage:

<!-- Copies the entire <book> subtree, including all attributes and children, exactly as is -->
<xsl:template match="library">
  <xsl:copy-of select="book"/>
</xsl:template>

Side-by-Side Comparison

Feature <xsl:copy> <xsl:copy-of>
Copy Depth Shallow (current node only) Deep (entire subtree)
Attribute Handling Ignores attributes (must be added manually) Copies all attributes automatically
Children Handling Ignores children (must be processed explicitly) Copies all descendants automatically
select Attribute Not used (always copies the current node) Required (specifies what to copy)
Content Model Can contain child XSLT elements Empty element (cannot contain child elements)
Primary Use Case Modifying or filtering elements and attributes Inserting unchanged XML subtrees directly into the output

When to Use Which

Use <xsl:copy> when you need to maintain the structure of an element while changing its attributes, reordering its children, or selectively applying rules to its descendants.

Use <xsl:copy-of> when you have a section of XML that needs to be output exactly as it appears in the source document, or when you are inserting the contents of a previously stored variable into the output tree without modification.
