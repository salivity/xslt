Using xsl:on-completion in XSLT 3.0 Iteration

In XSLT 3.0, the <xsl:on-completion> element serves as a dedicated finalization mechanism within an <xsl:iterate> instruction. It executes once the input sequence is completely exhausted, allowing developers to cleanly separate per-item processing from final clean-up or summary logic. This article explains how <xsl:on-completion> functions, how it accesses accumulated iteration parameters, and how it handles edge cases such as empty input sequences.

Purpose of <xsl:on-completion>

The <xsl:iterate> instruction processes a sequence sequentially, passing parameters from one iteration step to the next using <xsl:next-iteration>. While the main body of <xsl:iterate> handles individual items in the sequence, <xsl:on-completion> defines what output should be produced after processing ends.

Common use cases include:

  • Emitting closing markup or summary elements (such as running totals or item counts).
  • Emitting fallback content when the input sequence contains zero items.
  • Generating a final transformation result derived from accumulated parameters.

Access to Iteration Parameters

<xsl:on-completion> has full access to the loop's iteration parameters (<xsl:param>). It receives the parameter values produced by the final <xsl:next-iteration> call.

If the input sequence is completely empty, the iteration loop body does not execute, but <xsl:on-completion> executes immediately, receiving the initial default values defined on the <xsl:iterate> parameters.

Execution Behavior vs. <xsl:break>

It is important to distinguish between normal completion and premature termination:

  • Normal Termination: When the input sequence runs out of items, <xsl:on-completion> is triggered automatically.
  • Early Exit (<xsl:break>): If an <xsl:break> element is reached during processing, <xsl:iterate> terminates immediately. Any content inside <xsl:break> is evaluated and returned, and <xsl:on-completion> is skipped entirely.

Practical Example

The following example demonstrates calculating a running total and outputting a summary block upon completion:

<xsl:iterate select="order/item">
  <xsl:param name="total-cost" select="0.0" as="xs:double"/>

  <!-- Output individual item details -->
  <li class="item">
    <xsl:value-of select="@name"/>: $<xsl:value-of select="@price"/>
  </li>

  <!-- Continue iteration with updated total -->
  <xsl:next-iteration>
    <xsl:with-param name="total-cost" select="$total-cost + xs:double(@price)"/>
  </xsl:next-iteration>

  <!-- Finalization logic executes after all items are processed -->
  <xsl:on-completion>
    <li class="total">
      <strong>Total Cost: $<xsl:value-of select="$total-cost"/></strong>
    </li>
  </xsl:on-completion>
</xsl:iterate>

In this example, each item generates a list entry during iteration. When the input sequence finishes, <xsl:on-completion> evaluates once, using the finalized $total-cost parameter to emit the final total row.
