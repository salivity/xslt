How innermost() and outermost() Filter Nodes in XSLT

This article provides an overview of how the XPath and XSLT 3.0 functions fn:innermost() and fn:outermost() simplify hierarchical node processing. When querying deeply nested XML structures using descendant axes, queries often return redundant nodes that share ancestor-descendant relationships within the same selection. You will learn the operational mechanics of both functions, how they resolve overlapping node sets, and practical examples illustrating their filtering behavior.

The Problem with Descendant Axes

In hierarchical data processing, selecting elements using descendant axes like // frequently yields elements that contain other selected elements. For instance, evaluating //section on a document containing nested sections returns both parent sections and their child sections in a single sequence.

Before XPath 3.0, filtering these nodes to retain only the top-level or bottom-level elements required verbose, computationally expensive predicate expressions involving axes such as not(ancestor::section) or not(descendant::section). The standard functions outermost() and innermost() address this challenge natively.

How outermost() Works

The fn:outermost($nodes as node()*) as node()* function takes a sequence of nodes and filters out any node that is a descendant of another node present within the input sequence.

  • Primary Purpose: Retains only the highest-level nodes relative to the sequence itself.
  • Mechanism: For every node \(N\) in the input sequence, \(N\) is kept if and only if no ancestor of \(N\) is also in the input sequence.
  • Document Order: The returned sequence maintains the document order of the original nodes.

Example Scenario

Consider the following XML:

<div id="1">
    <div id="1.1">
        <p>Text</p>
    </div>
    <div id="1.2">
        <div id="1.2.1"/>
    </div>
</div>

Applying outermost(//div) evaluates all four div elements. Because div 1 contains div 1.1, div 1.2, and div 1.2.1, those descendants are discarded. The function returns only:

  • <div id="1">

How innermost() Works

The fn:innermost($nodes as node()*) as node()* function performs the inverse operation. It takes a sequence of nodes and filters out any node that is an ancestor of another node in the sequence.

  • Primary Purpose: Retains only the leaf nodes relative to the sequence itself.
  • Mechanism: For every node \(N\) in the input sequence, \(N\) is kept if and only if no descendant of \(N\) is also present in the input sequence.
  • Document Order: The returned nodes remain in original document order, with duplicate nodes removed.

Example Scenario

Using the same XML structure:

Applying innermost(//div) evaluates all four div elements:

  • div 1 is removed because it is an ancestor of 1.1, 1.2, and 1.2.1.
  • div 1.2 is removed because it is an ancestor of 1.2.1.
  • div 1.1 is retained because it contains no other div.
  • div 1.2.1 is retained because it contains no other div.

The function returns:

  • <div id="1.1">
  • <div id="1.2.1">

Key Behavioral Rules

  1. Self-Contained Evaluation: Both functions only evaluate ancestor-descendant relationships existing within the supplied sequence. Ancestors or descendants outside the provided sequence have no impact on the outcome.
  2. Node Types: While most commonly used with elements, both functions operate on any node types (such as text nodes or comments) that can have hierarchical relationships.
  3. Empty Sequences: If the input sequence is empty, an empty sequence is returned. If no nodes in the sequence share ancestor-descendant relationships, the original sequence is returned unchanged.
