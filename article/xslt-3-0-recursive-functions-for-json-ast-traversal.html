XSLT 3.0 Recursive Functions for JSON AST Traversal

This article explores how to process arbitrary JSON Abstract Syntax Trees (ASTs) using XSLT 3.0 recursive functions. By leveraging native XPath 3.1 data models—specifically maps and arrays—alongside recursive xsl:function definitions, developers can navigate deeply nested, variable-depth JSON structures without converting them to intermediate XML formats. The following sections demonstrate how to inspect types dynamically, traverse nested branches, and transform AST nodes into alternative structures or target code.

Understanding the XDM Representation of JSON

XSLT 3.0 natively supports JSON through the XPath and XQuery Data Model (XDM) 3.1. Functions such as fn:parse-json() parse a JSON string directly into XDM maps (map(*)) and arrays (array(*)).

An arbitrary AST node in JSON typically consists of objects containing properties like type, operator, children, or value:

{
  "type": "BinaryExpression",
  "operator": "+",
  "left": { "type": "Literal", "value": 5 },
  "right": { "type": "Literal", "value": 10 }
}

Because ASTs can nest indefinitely, processing them requires functions capable of inspecting the dynamic type of each item (map(*), array(*), or atomic value) and recursing downward.

Designing the Recursive Function

The standard pattern for traversing an arbitrary JSON AST involves a recursive xsl:function that uses XPath typeswitch or conditional if-else expressions to handle three basic cases:

  1. Maps (AST Nodes): Extract node metadata (such as the type property), apply transformations, and recursively call the function on any child maps or arrays.
  2. Arrays (Node Lists): Loop over the array entries (e.g., child statements or arguments) and apply the recursive function to each member.
  3. Atomic Values (Leaf Data): Return or transform the value directly (strings, numbers, booleans).

Implementation Example

The following stylesheet defines an AST walker that evaluates or transforms simple expression nodes:

<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
                xmlns:xs="http://www.w3.org/2001/XMLSchema"
                xmlns:map="http://www.w3.org/2005/xpath-functions/map"
                xmlns:array="http://www.w3.org/2005/xpath-functions/array"
                xmlns:ast="http://example.org/ast"
                version="3.0"
                exclude-result-prefixes="#all">

    <xsl:output method="text" indent="yes"/>

    <!-- Entry Point -->
    <xsl:template match="/">
        <xsl:param name="json-input" as="xs:string">
            {
                "type": "BinaryExpression",
                "operator": "*",
                "left": { "type": "Literal", "value": 4 },
                "right": {
                    "type": "BinaryExpression",
                    "operator": "+",
                    "left": { "type": "Literal", "value": 2 },
                    "right": { "type": "Literal", "value": 3 }
                }
            }
        </xsl:param>
        
        <xsl:variable name="ast" select="parse-json($json-input)"/>
        <xsl:value-of select="ast:traverse($ast)"/>
    </xsl:template>

    <!-- Recursive Traversal Function -->
    <xsl:function name="ast:traverse" as="item()*">
        <xsl:param name="node" as="item()?"/>

        <xsl:choose>
            <!-- Case 1: The node is a Map (AST Node) -->
            <xsl:when test="$node instance of map(*)">
                <xsl:variable name="type" select="map:get($node, 'type')"/>
                
                <xsl:choose>
                    <xsl:when test="$type eq 'BinaryExpression'">
                        <xsl:variable name="op" select="map:get($node, 'operator')"/>
                        <xsl:variable name="left" select="ast:traverse(map:get($node, 'left'))"/>
                        <xsl:variable name="right" select="ast:traverse(map:get($node, 'right'))"/>
                        <xsl:sequence select="concat('(', $left, ' ', $op, ' ', $right, ')')"/>
                    </xsl:when>
                    
                    <xsl:when test="$type eq 'Literal'">
                        <xsl:sequence select="string(map:get($node, 'value'))"/>
                    </xsl:when>
                    
                    <!-- Fallback: Recurse over all map entries -->
                    <xsl:otherwise>
                        <xsl:for-each select="map:keys($node)">
                            <xsl:sequence select="ast:traverse(map:get($node, .))"/>
                        </xsl:for-each>
                    </xsl:otherwise>
                </xsl:choose>
            </xsl:when>

            <!-- Case 2: The node is an Array -->
            <xsl:when test="$node instance of array(*)">
                <xsl:for-each select="1 to array:size($node)">
                    <xsl:sequence select="ast:traverse(array:get($node, .))"/>
                </xsl:for-each>
            </xsl:when>

            <!-- Case 3: Leaf / Atomic Values -->
            <xsl:otherwise>
                <xsl:sequence select="$node"/>
            </xsl:otherwise>
        </xsl:choose>
    </xsl:function>

</xsl:stylesheet>

Transforming While Traversing

When an AST transformation requires producing a modified JSON AST rather than text or XML, recursive functions can return new maps and arrays using map constructor functions:

  • map:put($map, $key, $value): Updates or inserts a key-value pair, returning a new map.
  • map:merge(): Combines multiple map definitions, ideal for updating properties while retaining existing ones.
  • array:append($array, $value) or array constructors ([ ... ]): Builds modified child lists during bottom-up traversal.

For example, to rename a property across all AST nodes, the function checks for that property on each map(*), calls ast:traverse on all values, and returns map:merge() with the modified keys.

Alternative: Using json-to-xml() for Template-Driven Recursion

While native functions (xsl:function) provide complete functional control over XDM maps, XSLT 3.0 also offers the json-to-xml() function. This converts a JSON string into an XML representation in the http://www.w3.org/2005/xpath-functions namespace.

Using json-to-xml() enables the standard xsl:apply-templates mechanism:

  • AST nodes map to <map> elements.
  • Arrays map to <array> elements.
  • Primitive values map to <string>, <number>, and <boolean> elements.

This approach leverages pattern matching (match="fn:map[@key='...']") and shallow copy idioms (<xsl:mode on-no-match="shallow-copy"/>), making it preferable when extensive pattern matching and node filtering are required over direct programmatic traversal.
