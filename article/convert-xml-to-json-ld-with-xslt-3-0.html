Convert XML to JSON-LD with XSLT 3.0

This article outlines the end-to-end workflow for transforming legacy or structured XML datasets into semantic JSON-LD format using the modern features of XSLT 3.0. By leveraging XSLT 3.0’s native JSON support—such as maps, arrays, and serialization functions—developers can programmatically bridge traditional hierarchical XML data with linked data vocabularies like Schema.org, creating clean, search-engine-friendly metadata without relying on intermediary scripts.

1. Define the Semantic Model and @context

Before writing XSLT templates, determine the target JSON-LD schema:

  • Select Vocabularies: Choose standard ontologies (e.g., Schema.org, Dublin Core, or custom ontologies) that match the XML domain.
  • Establish the @context: Decide whether the context will be linked externally via a URI or embedded inline within the generated JSON-LD object.
  • Map Source to Target: Create a field-by-field mapping between source XML elements/attributes and JSON-LD properties (such as mapping <title> to name and <id> to @id).

2. Configure the XSLT 3.0 Processor and Output

XSLT 3.0 introduces native support for JSON output, eliminating the string-concatenation workarounds required in older XSLT versions.

Set up the stylesheet declaration and define the output method:

<xsl:stylesheet version="3.0" 
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    exclude-result-prefixes="xs">

    <xsl:output method="json" indent="yes" encoding="UTF-8"/>
</xsl:stylesheet>

3. Build the Data Using XSLT 3.0 Maps and Arrays

XSLT 3.0 provides native map and array data types, which directly serialize to JSON objects ({}) and lists ([]).

  • Create JSON Objects: Use the map { ... } syntax to define key-value pairs.
  • Create JSON Arrays: Use the array { ... } syntax to handle repeating XML nodes.
  • Handle Types: Ensure numerical and boolean values are cast explicitly (e.g., xs:integer(), xs:boolean()) so they serialize without quotation marks.

Example template:

<xsl:template match="/catalog/product">
    <xsl:sequence select="map {
        '@context': 'https://schema.org',
        '@type': 'Product',
        '@id': string(@sku),
        'name': string(title),
        'description': string(description),
        'offers': map {
            '@type': 'Offer',
            'price': xs:decimal(price),
            'priceCurrency': string(price/@currency)
        }
    }"/>
</xsl:template>

4. Alternative Method: Using the XPath fn:xml-to-json Function

For highly dynamic structures, an alternative XSLT 3.0 pattern converts XML into the standard W3C XML representation of JSON (http://www.w3.org/2005/xpath-functions), followed by the xml-to-json() function:

  1. Transform the input XML into intermediate elements: <map>, <string>, <number>, <boolean>, and <array>.
  2. Wrap the conversion inside <xsl:value-of select="xml-to-json($intermediate-xml)" transform-text="none"/>.
  3. Set the output method to method="text".

This approach provides granular control when mapping heterogeneous XML nodes dynamically.

5. Execute the Transformation

Run the transformation using an XSLT 3.0 compliant engine, such as Saxon-HE, Saxon-PE, or MorganaXProc.

Example execution using Saxon:

java -jar saxon-he-12.jar -s:dataset.xml -xsl:transform.xsl -o:output.jsonld

6. Validate the Output

After generation, verify the output meets JSON-LD and semantic web requirements:

  • Syntax Validation: Verify the output is valid JSON using a JSON linter.
  • Semantic Conformance: Paste the generated data into the W3C JSON-LD Playground or Google’s Rich Results Test to confirm the @context, @type, and property relationships resolve correctly.
