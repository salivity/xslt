Generating Prefixed Attributes with xsl:attribute

Generating prefixed attributes in XSLT using the <xsl:attribute> element requires explicitly associating an attribute name with an XML namespace URI. This article explains the underlying mechanism for generating namespace-prefixed attributes, covering the relationship between the name and namespace attributes, namespace resolution rules, and how XSLT processors manage prefix serialization in the output tree.

The Core Mechanism

In XML, an attribute with a prefix belongs to a specific namespace URI; the prefix itself is merely a syntactic placeholder. When using <xsl:attribute>, the XSLT processor determines the attribute's namespace and prefix using two attributes:

  1. name: Specifies the attribute name as a QName (Qualified Name), which can include a prefix (e.g., prefix:localName).
  2. namespace (optional): Specifies the target namespace URI directly.

Method 1: Explicit Namespace Assignment

The most robust method for creating a prefixed attribute is specifying both the prefixed name and the target namespace URI directly on the <xsl:attribute> element:

<xsl:attribute name="xlink:href" namespace="http://www.w3.org/1999/xlink">
    <xsl:value-of select="@url"/>
</xsl:attribute>

When both attributes are present:

  • The processor uses the URI defined in the namespace attribute as the true identifier for the attribute's namespace.
  • The prefix provided in the name attribute acts as a prefix hint. The processor will attempt to use this prefix in the output.
  • If the prefix is already bound to a different URI in the current scope of the result tree, the processor automatically generates an alternative prefix to avoid namespace collisions while maintaining the correct namespace URI.
  • The processor automatically adds the necessary xmlns:prefix="URI" declaration to the containing element if it is not already present.

Method 2: In-Scope Namespace Resolution

If the namespace attribute is omitted, the processor resolves the prefix against the in-scope namespace declarations of the stylesheet at the position where <xsl:attribute> occurs:

<xsl:stylesheet version="1.0" 
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:custom="http://example.com/schema">

    <xsl:template match="item">
        <outputElement>
            <!-- The 'custom' prefix is resolved using the stylesheet's declaration -->
            <xsl:attribute name="custom:id">
                <xsl:value-of select="@id"/>
            </xsl:attribute>
        </outputElement>
    </xsl:template>
</xsl:stylesheet>

If the prefix specified in name does not match any in-scope namespace declaration in the stylesheet, the XSLT processor will treat it as an error.

Dynamic Generation with Attribute Value Templates

Both the name and namespace attributes interpret their values as Attribute Value Templates (AVTs). This allows dynamic generation of prefixes, local names, and namespace URIs at runtime using curly braces {}:

<xsl:attribute name="{$dynPrefix}:{$dynLocalName}" namespace="{$dynURI}">
    <xsl:value-of select="value"/>
</xsl:attribute>

The processor evaluates the expressions within {} first, forms the expanded name, and then follows standard namespace assignment rules.

Important Structural Rules

  • No Default Namespaces for Attributes: An unprefixed attribute never inherits a default namespace (xmlns="..."). To assign an attribute to a namespace, a prefix must be provided either in the name attribute or automatically generated by the processor when namespace is specified.
  • Serialization Precedence: The namespace URI dictates equality, not the prefix. Two attributes with the same local name and namespace URI cannot coexist on the same element, even if assigned different prefixes.
