Using xsl:break in XSLT 3.0 xsl:iterate

In XSLT 3.0, the <xsl:break> element provides an early-exit mechanism for the <xsl:iterate> instruction, allowing developers to terminate loop processing before reaching the end of an input sequence. When encountered, <xsl:break> halts any further evaluations of remaining items and optionally evaluates its own contents to append a final result to the output of the enclosing <xsl:iterate> block.

Purpose and Execution Flow

The <xsl:iterate> instruction processes items in a sequence sequentially, mimicking traditional imperative loops with stateful parameters. While standard iterations continue using <xsl:next-iteration>, the <xsl:break> element acts as an explicit interrupt—comparable to the break statement in languages like Java, C#, or Python.

When an <xsl:break> element is evaluated:

  1. Immediate Termination: The processor immediately ceases processing the sequence supplied to <xsl:iterate>. No further items in the sequence are evaluated.
  2. Result Generation: The sequence constructor inside the <xsl:break> element is evaluated, and the resulting nodes or atomic values are emitted as part of the overall result of the <xsl:iterate> instruction.
  3. Control Transfer: Control passes directly to the instruction immediately following the closing </xsl:iterate> tag.

Generating Output with <xsl:break>

Unlike standard imperative break statements that merely stop execution, <xsl:break> is a sequence constructor. It can contain templates, literal result elements, or instructions like <xsl:value-of> or <xsl:sequence>. Any content placed inside <xsl:break> becomes the final chunk of output produced by the iteration block.

<xsl:iterate select="//transaction">
  <xsl:param name="running-total" select="0"/>
  
  <xsl:choose>
    <xsl:when test="$running-total + @amount > 1000">
      <xsl:break>
        <warning>Transaction limit exceeded at ID: <xsl:value-of select="@id"/></warning>
      </xsl:break>
    </xsl:when>
    <xsl:otherwise>
      <processed-id><xsl:value-of select="@id"/></processed-id>
      <xsl:next-iteration>
        <xsl:with-param name="running-total" select="$running-total + @amount"/>
      </xsl:next-iteration>
    </xsl:otherwise>
  </xsl:choose>
</xsl:iterate>

In this scenario, as soon as the total exceeds 1,000, processing halts immediately. The <warning> element generated inside <xsl:break> is emitted, and all subsequent <transaction> elements are ignored.

Placement Rules

To be valid within an XSLT 3.0 stylesheet:

  • <xsl:break> must appear as a descendant of <xsl:iterate>.
  • It cannot be evaluated concurrently with <xsl:next-iteration>. In any conditional branch within the iteration, exactly one of the following must happen: execution finishes naturally, <xsl:next-iteration> is called to process the next item, or <xsl:break> is called to stop the loop entirely.
