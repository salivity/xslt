How to Make HTTP Requests in SaxonJS XSLT

SaxonJS enables client-side XSLT 3.0 execution directly in web browsers, expanding traditional transformation capabilities with interactive extensions. This article explains how to initiate asynchronous browser HTTP requests from within XSLT stylesheets using the ixsl:schedule-action extension instruction, structure request parameters using XSLT 3.0 maps, and handle asynchronous responses to dynamically update web pages without custom JavaScript wrappers.

Enabling the Interactive XSLT Namespace

To access SaxonJS browser extensions, declare the Interactive XSLT (ixsl) namespace at the top of your XSLT stylesheet:

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:ixsl="http://saxonica.com/ns/interactiveXSLT"
    xmlns:map="http://www.w3.org/2005/xpath-functions/map"
    exclude-result-prefixes="ixsl map">

Using ixsl:schedule-action for HTTP Requests

In SaxonJS, network operations use the standard browser fetch or XMLHttpRequest APIs internally. They are invoked natively in XSLT using the <ixsl:schedule-action> instruction configured with the http-request attribute.

Because network calls are asynchronous, <ixsl:schedule-action> schedules the request and defines a callback—typically an <xsl:call-template> child instruction—that executes once the remote server returns a response.

Making a GET Request

A basic GET request requires passing a configuration map to http-request that includes at least the request method and the target URI:

<xsl:template match="button[@id='fetch-data']" mode="ixsl:onclick">
    <ixsl:schedule-action http-request="map{
        'method': 'GET',
        'href': 'https://api.example.com/items'
    }">
        <xsl:call-template name="handle-response"/>
    </ixsl:schedule-action>
</xsl:template>

Handling the Response

When the request completes, SaxonJS invokes the scheduled callback template. The HTTP response details are exposed via the ixsl:event() function as an XSLT map containing properties such as:

  • status: HTTP response status code (e.g., 200).
  • statusText: The status message returned by the server.
  • headers: A map containing response header keys and values.
  • body: The parsed payload (an XML document, a parsed JSON structure as maps/arrays, or plain text depending on the response Content-Type).
  • media-type: The content type returned by the server.

Example response handler:

<xsl:template name="handle-response">
    <xsl:variable name="response" select="ixsl:event()"/>

    <xsl:choose>
        <xsl:when test="$response?status = 200">
            <!-- Append parsed response data to an HTML container -->
            <xsl:result-document href="#output-container" method="ixsl:append-content">
                <div class="result">
                    <xsl:value-of select="$response?body"/>
                </div>
            </xsl:result-document>
        </xsl:when>
        <xsl:otherwise>
            <!-- Handle HTTP error -->
            <xsl:result-document href="#error-message" method="ixsl:replace-content">
                <p>Error loading data: <xsl:value-of select="$response?statusText"/></p>
            </xsl:result-document>
        </xsl:otherwise>
    </xsl:choose>
</xsl:template>

Making POST Requests with Headers and Payloads

For requests sending payloads (such as POST or PUT), add the headers and body entries to the request map.

<xsl:template name="submit-form-data">
    <xsl:variable name="payload" select="map{
        'name': 'Sample Item',
        'active': true()
    }"/>

    <ixsl:schedule-action http-request="map{
        'method': 'POST',
        'href': 'https://api.example.com/items',
        'headers': map{
            'Content-Type': 'application/json',
            'Accept': 'application/json'
        },
        'body': serialize($payload, map{'method': 'json'})
    }">
        <xsl:call-template name="handle-post-response"/>
    </ixsl:schedule-action>
</xsl:template>

When sending XML, the body field can hold an XML document node or element directly, and SaxonJS serializes it automatically according to the specified Content-Type.
