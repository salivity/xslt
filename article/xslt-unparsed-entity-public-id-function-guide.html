XSLT unparsed-entity-public-id Function Guide

This article provides an overview of the unparsed-entity-public-id() function used during XSLT document inspection. It outlines the core purpose of the function, explains how it retrieves metadata from Document Type Definitions (DTDs), and demonstrates how it helps XSLT stylesheets handle external non-XML resources during transformations.

Purpose of the Function

The unparsed-entity-public-id() function in XSLT returns the public identifier of an unparsed entity declared within the Document Type Definition (DTD) of a source XML document.

In XML, unparsed entities are external resources—such as images, video clips, or binary files—declared in the DTD using the NDATA keyword. When an entity includes a public identifier (a formal, standardized identifier often used to catalog resources across systems), unparsed-entity-public-id() allows the XSLT processor to inspect and retrieve that identifier as a string.

Syntax and Behavior

The function signature is defined as:

unparsed-entity-public-id($entity-name as xs:string) as xs:string
  • Argument: It accepts a single string argument representing the name of the unparsed entity to look up.
  • Return Value: It returns a string containing the public identifier associated with the entity. If the specified entity does not exist in the DTD, or if the entity was declared with only a system identifier and no public identifier, the function returns an empty string ("").

Use Case in Document Inspection

When transforming XML documents that reference external media via DTD entity declarations, XSLT processors need a way to resolve or map those references.

While the related unparsed-entity-uri() function retrieves the system identifier (typically a direct URI or file path), unparsed-entity-public-id() provides access to the formal public identifier (such as a Formal Public Identifier / FPI or URN). This is useful in publishing and document management workflows where:

  1. Catalog Resolution: Assets are resolved using public catalogs (like OASIS catalogs) rather than static file paths.
  2. Metadata Auditing: The stylesheet needs to inspect, validate, or generate reports on entity declarations without modifying the underlying DTD.
  3. Fallback Mechanisms: A stylesheet can check for the existence of a standardized public identifier to determine how to format an output link or embed a resource when a direct URI is local or unavailable.
