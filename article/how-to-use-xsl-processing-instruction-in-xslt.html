How to Use xsl:processing-instruction in XSLT

This article explores the purpose and implementation of the <xsl:processing-instruction> element in XSLT. You will learn how this element enables the creation of processing instructions such as xml-stylesheet declarations and server-side PHP tags, why standard text-escaping methods fail for this purpose, and how to implement it correctly in your transformation stylesheets.

In XSLT, processing instructions (PIs) provide instructions to external processors consuming the resulting document. Because XSLT parsers enforce strict XML syntax rules, attempting to output characters like <? and ?> as raw text will result in XML parsing errors or unwanted entity escaping (e.g., &lt;?php ... ?&gt;). The <xsl:processing-instruction> element solves this problem by allowing the XSLT processor to construct native, unescaped processing instructions in the result tree.

Syntax and Attributes

The element relies on a single mandatory attribute:

  • name: Specifies the target of the processing instruction (for example, php, xml-stylesheet, or any custom application target).

The content placed inside the <xsl:processing-instruction> element forms the data string that immediately follows the instruction's name.

<xsl:processing-instruction name="target">
    instruction-data
</xsl:processing-instruction>

Generating Stylesheet Directives

A common use case is linking a CSS or XSL stylesheet to an XML document using the xml-stylesheet processing instruction.

<xsl:processing-instruction name="xml-stylesheet">
    href="styles.css" type="text/css"
</xsl:processing-instruction>

When evaluated, the processor generates the following valid XML directive:

<?xml-stylesheet href="styles.css" type="text/css"?>

You can also use XSLT expressions or attributes dynamically within the instruction using <xsl:value-of>:

<xsl:processing-instruction name="xml-stylesheet">
    <xsl:text>href="</xsl:text>
    <xsl:value-of select="/document/theme"/>
    <xsl:text>.css" type="text/css"</xsl:text>
</xsl:processing-instruction>

Generating PHP Code

When using XSLT to generate PHP files or dynamic templates, <xsl:processing-instruction> allows you to inject PHP code without triggering XML syntax errors.

<xsl:processing-instruction name="php">
    echo 'Current Year: ' . date('Y');
</xsl:processing-instruction>

This generates:

<?php echo 'Current Year: ' . date('Y');?>

Limitations and Considerations

  1. Forbidden Characters: According to the W3C XML recommendation, a processing instruction's data cannot contain the string ?>, as this sequence marks the close of the processing instruction. Attempting to output ?> within the element body will cause an XSLT transformation error.
  2. Target Restrictions: The name attribute must be an NCName (Non-Colonized Name). It cannot be xml (case-insensitive) because XML declaration headers (<?xml version="1.0"?>) are managed via the <xsl:output> element rather than processing instructions.
  3. Spacing: The processor automatically inserts a space between the target name and the instruction body. However, any leading or trailing whitespace inside the element body is preserved, so formatting should be carefully controlled using <xsl:text> if strict spacing is required.
