Match XML Elements Regardless of Namespace in XSLT

Matching XML elements regardless of their namespace URI is essential when processing heterogeneous documents or XML where the namespace prefix and URI may change unexpectedly. In modern XSLT (2.0 and 3.0), you can achieve this using the wildcard prefix syntax *:elementName. In legacy XSLT 1.0 environments, the standard solution is using a predicate with the local-name() function, formatted as *[local-name() = 'elementName']. This guide demonstrates how to implement both patterns in template rules and XPath expressions.

The Modern Pattern: XSLT 2.0 and 3.0 (*:localName)

If you are using an XSLT 2.0 or 3.0 processor (such as Saxon), you can use the wildcard namespace syntax *:. This prefix instructs the processor to match the given local name under any namespace, including elements with no namespace at all.

Template Match Example:

<xsl:template match="*:book">
    <div class="book">
        <xsl:value-of select="*:title"/>
    </div>
</xsl:template>

XPath Expression Example:

<xsl:variable name="titles" select="//*:book/*:title" />

This pattern matches <book>, <ns1:book xmlns:ns1="http://example.com/schema">, or <ns2:book xmlns:ns2="http://other.org/ns">.

The Legacy Pattern: XSLT 1.0 (local-name())

XSLT 1.0 does not support the *: prefix syntax. To ignore the namespace, you match any element (*) and filter it using a predicate that checks the local-name() function.

Template Match Example:

<xsl:template match="*[local-name() = 'book']">
    <div class="book">
        <xsl:value-of select="*[local-name() = 'title']"/>
    </div>
</xsl:template>

XPath Expression Example:

<xsl:variable name="titles" select="//*[local-name() = 'book']/*[local-name() = 'title']" />

Handling Both Attributes and Elements

You can apply the same logic to attributes across namespaces:

  • XSLT 2.0/3.0: @*:id
  • XSLT 1.0: @*[local-name() = 'id']
<!-- Matches any element with an 'id' attribute, regardless of namespace -->
<xsl:template match="*[@*:id]">
    <xsl:value-of select="@*:id"/>
</xsl:template>

Best Practices and Considerations

  • Unintended Collisions: Stripping namespace awareness means elements with the same local name from different namespaces (for example, a <title> under Dublin Core vs. a <title> under HTML) will match the same rule.
  • Performance: In large XML documents, predicates like *[local-name() = 'item'] in XSLT 1.0 can be slower than direct name tests because the processor must evaluate the function for every node. The *:item wildcard in XSLT 2.0+ is optimized by modern query planners and is typically faster.
