How XSLT and XPath Handle Division by Zero

In an XSLT processor, the handling of numeric division by zero is determined entirely by the underlying XPath specification version and the data types involved in the operation. While XPath 1.0 treats all numbers as IEEE 754 floating-point values and never throws a runtime error for division by zero, modern standards (XPath 2.0, 3.0, and 3.1) distinguish between floating-point types and exact decimal types, resulting in either special IEEE values or a fatal dynamic error.

XPath 1.0 Semantics

In XPath 1.0, there is only one numeric data type: the IEEE 754 double-precision 64-bit floating-point number. Because IEEE 754 defines specific representations for mathematical anomalies, division by zero (div) never produces a fatal processing error in XPath 1.0.

The evaluation rules are:

  • Positive Number divided by Zero: Evaluating N div 0 (where N > 0) results in Infinity.
  • Negative Number divided by Zero: Evaluating -N div 0 (where N > 0) results in -Infinity.
  • Zero divided by Zero: Evaluating 0 div 0 or -0 div 0 results in NaN (Not-a-Number).

Because no error is thrown, the processor will continue executing the stylesheet, serializing these values into the result tree as the strings "Infinity", "-Infinity", or "NaN".

XPath 2.0, 3.0, and 3.1 Semantics

XPath 2.0 and later versions align with XML Schema (XSD) datatypes, introducing support for xs:decimal, xs:integer, xs:float, and xs:double. The behavior of numeric division depends on the specific arithmetic operator and the types of the operands.

Floating-Point Division (xs:double and xs:float)

When both operands are xs:double or xs:float (or are promoted to them), the operation adheres to IEEE 754 rules, matching XPath 1.0 behavior:

  • A positive value divided by positive zero (+0.0) returns INF.
  • A positive value divided by negative zero (-0.0) returns -INF.
  • A negative value divided by positive zero (+0.0) returns -INF.
  • A negative value divided by negative zero (-0.0) returns INF.
  • Dividing zero by zero (0.0 div 0.0) returns NaN.

No dynamic error is raised during standard floating-point division by zero.

Decimal and Integer Division (xs:decimal and xs:integer)

Unlike floating-point types, xs:decimal and xs:integer do not support representations for infinity or NaN.

When dividing values typed as xs:decimal or xs:integer using the div operator:

  • If the divisor evaluates to zero (0), the processor terminates execution with dynamic error err:FOAR0001 (Division by zero).

Untyped values (such as text extracted from schema-less XML documents) default to xs:double when processed with arithmetic operations in XPath 2.0+, meaning they follow floating-point rules unless explicitly cast to xs:decimal or xs:integer.

Integer Division (idiv)

XPath 2.0 introduced the idiv operator for integer division. Regardless of whether the operands are xs:integer, xs:decimal, xs:float, or xs:double, evaluating idiv with a divisor of zero always raises dynamic error err:FOAR0001. The operator also raises an error if either operand is NaN, or if the dividend is INF or -INF.

Summary of Safe Evaluation

To prevent stylesheet failure across different processors and versions when the divisor might be zero, explicit conditions must guard the division:

<xsl:value-of select="if ($divisor != 0) then ($dividend div $divisor) else 0"/>

For XPath 1.0 processors lacking conditional if expressions, test expressions are typically handled using <xsl:choose> or boolean logic:

<xsl:value-of select="($divisor != 0 and ($dividend div $divisor)) or 0"/>
