Grounded vs Consumed Sequences in XSLT 3.0

In XSLT 3.0 streaming, processing large XML documents efficiently depends on distinguishing how sequences are accessed and stored. This article examines the differences between a grounded sequence and a consumed stream sequence, highlighting their behavior regarding memory consumption, navigation capability, and node reusability during stream evaluation.

What is a Grounded Sequence?

In XSLT 3.0 streamability analysis, an expression has a grounded posture when its result exists independently of the streamed input document's position. A grounded sequence typically consists of atomic values, newly constructed nodes, or nodes created using functions like copy-of().

Because a grounded sequence resides fully in memory:

  • Arbitrary Navigation: You can traverse it using any axis, including reverse axes (parent::, preceding-sibling::) or random-access expressions ($seq[5]).
  • Multiple Evaluations: The sequence can be evaluated, bound to variables, sorted, and looped over multiple times without restriction.
  • Memory Cost: Storing large subtrees as grounded sequences increases heap memory usage, which counters the benefits of streaming if overused.

What is a Consumed Stream Sequence?

A streamed sequence consists of nodes that point directly to the underlying XML parser reading the document incrementally. These nodes generally possess a posture of striding or crawling.

A streamed sequence becomes consumed when an XSLT instruction reads through it to produce output or evaluate an expression. In XSLT streaming semantics:

  • Forward-Only Access: The stream reader only moves forward. Once the processor traverses a node in a streamed sequence to evaluate an instruction (such as xsl:apply-templates or xsl:for-each), that node is consumed and passes out of scope.
  • Single-Pass Restriction: A consumed sequence cannot be read a second time. Attempting to iterate over or reference a consumed streamed node again causes an XSLT streamability violation (a static or dynamic error).
  • Restricted Navigation: While still unconsumed, a streamed sequence can only be navigated using forward axes (primarily child:: and attribute::). Reverse and sibling navigation are disallowed.

Key Differences

Feature Grounded Sequence Consumed Stream Sequence
Storage Location System memory (RAM) Parser stream buffer
Evaluation Limit Infinite; reusable across instructions Single-use; cannot be revisited
Axis Support Full XPath navigation (forward and reverse) Restricted to forward downward axes
Memory Footprint Proportional to the size of the copied data Constant, near-zero buffer overhead
Creation Method copy-of(), atomic values, new element constructors Selecting nodes directly from snapshot() or streaming axes

Practical Implication

The transition between these two types of sequences is a fundamental pattern in XSLT 3.0 streaming. While an entire multi-gigabyte document must remain a stream sequence to avoid memory exhaustion, developers often consume individual child elements from the stream and convert them into small grounded sequences using copy-of() or snapshot(). This allows localized, complex transformations using standard XPath operations on small fragments while preserving the overall low-memory, single-pass processing of the master document.
