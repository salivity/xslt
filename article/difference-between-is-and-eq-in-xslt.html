Difference Between is and eq in XSLT

In XSLT and XPath 2.0 and later, determining whether two items are identical depends entirely on whether you are comparing memory references or underlying data. The is operator checks for node identity, determining whether two expressions resolve to the exact same node within an XML document tree. In contrast, the eq operator checks for value equality, evaluating whether the typed atomic values of two items are equal, regardless of where they are located.

The is Operator: Node Identity

The is operator tests whether two node references point to the same physical node in the XML document hierarchy.

  • Operand Requirements: Both operands must be a single node (or an empty sequence). If an operand evaluates to an atomic value (such as a string or integer) rather than a node, the processor raises a type error.
  • Mechanism: It does not inspect the contents, attributes, or string values of the elements. It checks only their structural identity.
  • Empty Sequences: If either operand evaluates to an empty sequence, the result of the is expression is an empty sequence (which evaluates to false in a boolean context).

Example:

$nodeA is $nodeB

This expression returns true only if $nodeA and $nodeB represent the identical node in the tree. Even if two elements have the exact same tag name, attributes, and text content, $nodeA is $nodeB will return false if they are two distinct sibling or separate nodes.

The eq Operator: Value Equality

The eq operator evaluates the atomic values of two items after performing atomization.

  • Operand Requirements: Both operands must evaluate to a single atomic value (or a node that can be atomized into a single atomic value), or an empty sequence.
  • Mechanism: When applied to nodes, the processor extracts the typed value (or xs:untypedAtomic if no schema is present) of each node and compares the data.
  • Strictness: Unlike the general equality operator (=), which allows sequences of multiple items and has existential semantics, eq is strictly for single-item comparisons.

Example:

$nodeA eq $nodeB

This expression returns true if the atomized value of $nodeA matches the atomized value of $nodeB, regardless of whether they are the same node or exist in different parts of the document.

Direct Comparison

Consider the following XML document:

<catalog>
    <item id="1">Widget</item>
    <item id="2">Widget</item>
</catalog>

Given the variables:

  • $first := /catalog/item[1]
  • $second := /catalog/item[2]
  • $alias := /catalog/item[1]

The operators behave as follows:

Expression Result Reason
$first is $second false They are two distinct element nodes in the tree.
$first eq $second true Both atomize to the string value "Widget".
$first is $alias true Both paths select the exact same element in the tree.
$first eq $alias true The values are identical.

When to Use Which

  • Use is when testing whether a node is the current context node (. is $target), verifying that a node belongs to a specific set, or confirming that two axes reached the same position in a document tree.
  • Use eq when comparing business data, strings, numbers, dates, or element text content between two single items.
