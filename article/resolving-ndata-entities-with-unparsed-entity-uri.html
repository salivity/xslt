Resolving NDATA Entities with unparsed-entity-uri

The unparsed-entity-uri() function in XSLT provides a standardized mechanism to retrieve the absolute URI of non-XML resources declared in a Document Type Definition (DTD). In legacy XML workflows, non-XML data such as images, multimedia, or binary formats were commonly referenced using NDATA unparsed external entities rather than direct URI attributes. This article explains the technical mechanics of how unparsed-entity-uri() inspects the document’s DTD declarations, processes entity and notation mappings, and resolves relative system identifiers into fully qualified URIs during transformation.

Understanding DTD Unparsed Entities and NDATA

In standard XML 1.0, an unparsed entity is an external resource containing non-XML data. Because the XML processor cannot parse this data as XML, the DTD declaration associates the entity with an NDATA (notation data) keyword. This keyword binds the entity to a specific notation declaration that specifies the format or helper application associated with the data.

A typical DTD declaration pairing an unparsed entity with a notation looks like this:

<!NOTATION png SYSTEM "image/png">
<!ENTITY diagram1 SYSTEM "graphics/diagram1.png" NDATA png>

In the XML instance document, this entity is referenced through an attribute explicitly typed as ENTITY or ENTITIES:

<figure graphic="diagram1" />

Instead of containing a path string, the graphic attribute holds the name token corresponding to the entity declared in the DTD.

The Resolution Mechanism of unparsed-entity-uri()

The unparsed-entity-uri() function accepts a single string argument—the name of the unparsed entity—and returns its absolute URI as a string. The resolution occurs in sequential stages:

  1. Entity Name Lookup: When unparsed-entity-uri(@graphic) is invoked, the XSLT processor queries the internal or external DTD subset of the document containing the context node for an unparsed entity matching the provided name string (e.g., "diagram1").
  2. System Identifier Extraction: Upon locating the entity declaration, the processor extracts the entity's SYSTEM identifier (e.g., "graphics/diagram1.png"). If a PUBLIC identifier is present, the parser's entity catalog may map it to a system identifier first.
  3. Base URI Normalization: The processor determines the base URI of the entity declaration. If the declaration resides in an external DTD module, the base URI is that external file's location; if declared in the internal subset, it is the base URI of the XML document itself. The processor then resolves the relative system identifier against this base URI.
  4. Result Generation: The function returns the normalized, absolute URI string (such as file:///projects/docs/graphics/diagram1.png). If the entity name does not match any declared unparsed entity in the DTD, the function returns an empty string.

Implementation in XSLT

In an XSLT stylesheet (compatible with both XSLT 1.0 and XSLT 2.0+), the function translates the abstract entity name into an actionable link or source path:

<xsl:template match="figure">
  <img src="{unparsed-entity-uri(@graphic)}" alt="{@caption}" />
</xsl:template>

If the input XML contains <figure graphic="diagram1" caption="Network Diagram"/>, the processor calls unparsed-entity-uri('diagram1'), reads the DTD definition, resolves the path relative to the document or external DTD, and generates the resulting output:

<img src="file:///projects/docs/graphics/diagram1.png" alt="Network Diagram" />

Processor Dependencies

For unparsed-entity-uri() to resolve successfully, two operational conditions must be met:

  • DTD Retention: The underlying XML parser must read the DTD. Non-validating parsers that strip DTDs or skip external parameter entities will fail to pass the entity table to the XSLT data model, causing the function to return an empty string.
  • Notation Requirement: The entity declaration must include the NDATA keyword. Parsed external entities (those without NDATA) are intended for direct XML inclusion and cannot be resolved using unparsed-entity-uri().
