Relative Document Node Order in XSLT 2.0+

In XSLT 2.0 and later versions (leveraging XPath 2.0+), the << and >> operators are dedicated node comparison operators used to determine the relative document order of two nodes. Rather than comparing the string or typed values of nodes, these operators evaluate structural positions within an XML hierarchy. This article covers the syntax, rules, and underlying mechanics of the << and >> operators, along with how edge cases like attributes and different documents are resolved.

The Node Comparison Operators: << and >>

The << and >> operators evaluate whether one node precedes or follows another in document order:

  • $nodeA << $nodeB: Returns true if $nodeA precedes $nodeB in document order; otherwise returns false.
  • $nodeA >> $nodeB: Returns true if $nodeA follows $nodeB in document order; otherwise returns false.

If either operand is an empty sequence (()), the expression returns an empty sequence, which evaluates to false in an effective boolean value context. If an operand evaluates to a sequence of more than one node, a type error (XPTY0004) is raised.

Understanding Document Order

Document order corresponds to the sequence in which the first character of the XML representation of each node occurs, matching a depth-first, pre-order traversal of the document tree:

  1. Root (Document Node): Always appears first.
  2. Element Nodes: An element occurs before its child elements and content.
  3. Attribute and Namespace Nodes: Associated with an element, they occur after the element node itself but before any child element or text nodes. The relative order among sibling attribute nodes is stable but implementation-dependent.
  4. Sibling Nodes: Sibling elements and text nodes follow their structural sequence in the source document.
  5. Descendants: All descendants of a node appear before the following siblings of that node.

Comparison Rules and Edge Cases

1. Identity Requirement

The << and >> operators only return true when nodes are distinct. If $nodeA and $nodeB refer to the exact same node (where $nodeA is $nodeB is true), both $nodeA << $nodeB and $nodeA >> $nodeB evaluate to false.

2. Nodes in Different Documents

When comparing two nodes from entirely different XML documents (or distinct temporary trees constructed in memory):

  • The relative order between the two documents is implementation-dependent.
  • The order is guaranteed to be stable throughout the execution of the stylesheet. If $docA/root << $docB/root is true, every node in $docA will precede every node in $docB for that entire transformation run.

3. Attributes and Children

Because attributes belong to an element but are not considered child nodes, they are ordered immediately after their parent element:

<item id="1">
    <description>Widget</description>
</item>

In this structure:

  • item << item/@id is true.
  • item/@id << item/description is true.
  • item/description >> item/@id is true.

Practical Example

Consider the following XML fragment:

<section>
    <p id="p1">First paragraph</p>
    <p id="p2">Second paragraph</p>
</section>

Using XPath expressions within an XSLT 2.0+ template:

<!-- Evaluates to true -->
<xsl:if test="//p[@id='p1'] &lt;&lt; //p[@id='p2']">
    <xsl:text>Paragraph 1 comes before Paragraph 2.</xsl:text>
</xsl:if>

<!-- Evaluates to true -->
<xsl:if test="//p[@id='p2'] &gt;&gt; //p[@id='p1']">
    <xsl:text>Paragraph 2 comes after Paragraph 1.</xsl:text>
</xsl:if>

(Note: In raw XML/XSLT attribute contexts, << and >> must be escaped as &lt;&lt; and &gt;&gt; to satisfy XML well-formedness rules.)
