XSLT 3.0 serialize Function Parameters

This article provides an overview of the serialization parameters available for the fn:serialize() function in XSLT 3.0 and XPath 3.0/3.1. It covers the two formats used to define these parameters—XML parameter elements and XPath 3.1 maps—followed by a comprehensive breakdown of each standard parameter and its effect on the serialized output.

Supplying Serialization Parameters

In XSLT 3.0, the fn:serialize() function accepts an input sequence as its first argument and an optional set of serialization parameters as its second argument. These parameters can be supplied in two ways:

  1. An XML Node: An <output:serialization-parameters> element belonging to the http://www.w3.org/2010/xslt-xquery-serialization namespace containing child elements named after the parameters.
  2. A Map (XPath 3.1 / XSLT 3.0): An XDM map where keys match the parameter names (either as strings or QNames) and values correspond to the parameter settings.

Standard Serialization Parameters

Output Method and Formatting

  • method: Specifies the output format. Standard values are "xml", "html", "xhtml", "text", "json", and "adaptive". Vendor-specific QNames are also permitted.
  • indent: A boolean (true()/false() in maps, or "yes"/"no" in XML) indicating whether whitespace should be added to pretty-print the resulting structure.
  • suppress-indentation: A list of element QNames for which whitespace indentation should not be applied, even if indent is enabled.
  • item-separator: A string inserted between individual items in the serialized sequence. If unspecified, it defaults to a space or implementation-defined delimiter.

Document and Declaration Options

  • omit-xml-declaration: Specifies whether the XML declaration (<?xml ... ?>) is omitted from the output. Accepts a boolean or "yes"/"no".
  • standalone: Defines the standalone pseudo-attribute in the XML declaration. Values can be "yes", "no", or "omit".
  • doctype-public: A string containing the public identifier used in the generated <!DOCTYPE> declaration.
  • doctype-system: A string containing the system identifier used in the generated <!DOCTYPE> declaration.
  • html-version: A decimal value (such as 5.0) specifying the targeted version of HTML when method is set to "html" or "xhtml".

Character Encoding and Escaping

  • encoding: The character encoding used for the output string or byte sequence (e.g., "UTF-8", "ISO-8859-1").
  • byte-order-mark: Determines whether a Byte Order Mark (BOM) should be prepended to the serialized output (applicable to encodings like UTF-8 or UTF-16).
  • cdata-section-elements: A sequence of element QNames whose text node children should be emitted inside CDATA sections instead of standard escaped characters.
  • normalization-form: Applies Unicode normalization to the output. Standard values include "NFC", "NFD", "NFKC", "NFKD", "fully-normalized", or "none".
  • use-character-maps: A map or list associating specific Unicode characters with string substitutions to bypass standard escaping.

Namespaces and Web Options

  • undeclare-prefixes: Determines whether XML 1.1 namespace undeclarations (e.g., xmlns:p="") are output when prefixes go out of scope. Accepts "yes" or "no".
  • escape-uri-attributes: Used primarily with HTML and XHTML methods. Determines whether non-ASCII and reserved URI characters in URI attributes are percent-encoded ("yes" or "no").
  • include-content-type: Determines whether an HTML <meta> tag specifying the MIME type and character encoding should be automatically generated ("yes" or "no").
  • media-type: The MIME type of the output document (e.g., "application/xml", "text/html").
  • json-node-output-method: Specifies how XML node items encountered inside serialized JSON structures should be rendered. Valid options include "xml", "xhtml", "html", or "text".
