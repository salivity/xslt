How to Use doc-available in XSLT 2.0+

The doc-available() function in XSLT 2.0 and later versions serves as a vital safeguard for checking the existence and validity of external XML documents before attempting to process them. In standard XSLT workflows, invoking the doc() function on a non-existent or malformed document causes the transformation to fail immediately with a fatal dynamic error. By using doc-available(), developers can perform runtime checks, gracefully handle missing dependencies, and provide fallback logic without terminating the transformation process.

The Problem with doc()

In XSLT 2.0+, the standard way to retrieve external XML data is via the doc() or document() functions. However, doc($uri) has a strict requirement: if the resource identified by the URI cannot be retrieved, or if the content cannot be parsed as well-formed XML, the processor raises a dynamic error (FODC0002). This halts stylesheet execution entirely, which is problematic in enterprise pipelines where external data sources may be optional, transient, or temporarily unreachable.

How doc-available() Works

The doc-available() function is defined in the standard XPath/XSLT Functions and Operators library. It accepts a string representing a URI and returns a boolean value:

fn:doc-available($uri as xs:string?) as xs:boolean

The function performs two distinct checks:

  1. Resource Existence and Reachability: It attempts to locate and read the resource at the specified URI.
  2. XML Well-Formedness: It verifies whether the retrieved resource can be parsed as a valid XML document.

If the resource exists, is accessible, and parses as well-formed XML, doc-available() returns true(). If the resource does not exist, the network fails, or the target file contains syntax errors (such as unclosed tags), the function returns false() instead of crashing the stylesheet.

Implementation Example

The primary pattern for using doc-available() involves pairing it with an xsl:choose or xsl:if conditional statement prior to calling doc():

<xsl:variable name="fileUri" select="'external-data.xml'"/>

<xsl:choose>
    <xsl:when test="doc-available($fileUri)">
        <!-- Safe to retrieve and process the external document -->
        <xsl:apply-templates select="doc($fileUri)/root"/>
    </xsl:when>
    <xsl:otherwise>
        <!-- Graceful fallback if the file is missing or invalid -->
        <xsl:message terminate="no">
            Warning: <xsl:value-of select="$fileUri"/> could not be loaded. Applying default data.
        </xsl:message>
        <default-output status="external-source-unavailable"/>
    </xsl:otherwise>
</xsl:choose>

Key Considerations

  • Caching Behavior: Most compliant XSLT processors (such as Saxon) cache the document fetched during the doc-available() evaluation. Calling doc() directly afterward typically reads the pre-parsed document from memory rather than issuing a second network or disk request.
  • Non-XML Resources: doc-available() is strictly for XML documents. If the target resource is plain text, JSON, or binary data, doc-available() returns false(). In XSLT 3.0, complementary functions such as unparsed-text-available() exist for validating plain-text resources.
  • Empty or Null Arguments: If the argument passed to doc-available() evaluates to an empty sequence or an empty string, the function returns false().
