fold-left and fold-right in Functional XSLT 3.0

This article provides a concise guide to the fold-left() and fold-right() functions in XSLT 3.0 and XPath 3.0, explaining their purpose, syntax, and operational differences. You will learn how these higher-order functions enable sequence reduction and state accumulation, eliminating the need for verbose recursive templates while adhering to pure functional programming principles.

Understanding Sequence Reduction

In functional programming, folding (also known as reduce, accumulate, or aggregate) processes a data structure in a specific order to build up a single return value. Prior to XSLT 3.0, reducing a sequence into a single computed value—such as calculating a rolling total, reversing a list, or building a deeply nested tree—typically required writing custom recursive templates or user-defined functions using xsl:iterate.

With the introduction of higher-order functions in XPath 3.0 (and thus XSLT 3.0), fn:fold-left() and fn:fold-right() became standard tools to process sequences declaratively without explicit iteration or template recursion.

Both functions require three arguments:

  1. $seq: The sequence of items to process (item()*).
  2. $zero: The initial value or accumulator (item()*).
  3. $f: A function item that accepts two arguments and returns the updated accumulator (function(item()*, item()) as item()* or vice versa).

The fold-left() Function

fold-left() processes the sequence from left to right (from the first item to the last). In each iteration, it supplies the accumulated result as the first argument and the current item from the sequence as the second argument to the reduction function.

Signature and Evaluation Order

fn:fold-left($seq as item()*, $zero as item()*, $f as function(item()*, item()) as item()*) as item()*

If the sequence is (1, 2, 3), the evaluation proceeds as follows:

$f($f($f($zero, 1), 2), 3)

Example: Custom String Aggregation

<xsl:variable name="words" select="('XSLT', '3.0', 'Functional', 'Programming')"/>
<xsl:variable name="result" select="
    fold-left($words, '', function($accum, $item) {
        if ($accum = '') then $item else concat($accum, ' -> ', $item)
    })
"/>
<!-- Result: 'XSLT -> 3.0 -> Functional -> Programming' -->

The fold-right() Function

fold-right() processes the sequence from right to left (from the last item to the first). In contrast to fold-left(), the reduction function receives the current item as its first argument and the running accumulator as its second argument.

Signature and Evaluation Order

fn:fold-right($seq as item()*, $zero as item()*, $f as function(item(), item()*) as item()*) as item()*

If the sequence is (1, 2, 3), the evaluation proceeds as follows:

$f(1, $f(2, $f(3, $zero)))

Example: Building Nested Elements

fold-right() is particularly effective for nesting wrappers around content, where the leftmost item becomes the outermost container.

<xsl:variable name="tags" select="('div', 'section', 'article')"/>
<xsl:variable name="nested" select="
    fold-right($tags, <p>Content</p>, function($tag, $accum) {
        element { $tag } { $accum }
    })
"/>
<!-- Result: <div><section><article><p>Content</p></article></section></div> -->

Key Differences and Functional Considerations

1. Associativity

For commutative and associative operations like addition or multiplication, both functions yield identical results:

fold-left((1, 2, 3), 0, function($a, $b) { $a + $b })  (: Returns 6 :)
fold-right((1, 2, 3), 0, function($a, $b) { $a + $b }) (: Returns 6 :)

For non-associative operations such as subtraction, division, or list restructuring, the choice directly impacts the outcome:

fold-left((10, 5, 2), 100, function($a, $b) { $a - $b })  (: ((100 - 10) - 5) - 2 = 83 :)
fold-right((10, 5, 2), 100, function($a, $b) { $a - $b }) (: 10 - (5 - (2 - 100)) = -83 :)

2. Argument Signatures

  • In fold-left(), the function item takes ($accumulator, $item).
  • In fold-right(), the function item takes ($item, $accumulator).

Swapping the functions without adjusting the parameter order of the callback will cause evaluation errors or unexpected type mismatch failures.

3. Performance and Memory

fold-left() is generally tail-recursive, allowing XSLT processors (like Saxon) to optimize execution and evaluate sequences in constant stack space. fold-right() requires constructing an evaluation stack that holds references to all pending functions until the end of the sequence is reached, making fold-left() the preferred choice when the direction of evaluation does not alter the business logic.
