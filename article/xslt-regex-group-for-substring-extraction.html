XSLT regex-group() for Substring Extraction

This article provides an overview of the regex-group() function in XSLT, detailing its primary role in parsing strings and extracting specific tokenized substrings. It covers how the function works within the context of the <xsl:analyze-string> instruction, how captured groups are referenced, and practical examples illustrating how to isolate complex data tokens into structured XML elements.

The Role of regex-group() in XSLT

Introduced in XSLT 2.0, the regex-group() function extracts parts of a matched string defined by parenthesized capturing groups within a regular expression. While functions like tokenize() break strings apart using simple delimiters, regex-group() enables targeted, pattern-based tokenization where individual components of a token need to be extracted simultaneously.

The function operates strictly within the <xsl:matching-substring> child element of the <xsl:analyze-string> instruction. When a regular expression matches an input sequence, regex-group() retrieves the exact characters captured by a specific set of parentheses inside that regular expression.

Syntax and Operation

The syntax for the function is:

regex-group($n as xs:integer) as xs:string
  • regex-group(0): Returns the entire substring matched by the complete regular expression pattern.
  • regex-group(1): Returns the substring captured by the first open-parenthesis group (...) in the pattern.
  • regex-group(n): Returns the substring captured by the \(n\)-th parenthesized group, counted from left to right based on the opening parentheses.
  • If the specified group was not matched, or if the index exceeds the number of capture groups in the pattern, the function returns an empty string ("").

Extracting Tokenized Data

In data transformation workflows, tokens often contain internal structure—such as key-value pairs, dates, or formatted codes—that cannot be parsed cleanly using single delimiter characters. regex-group() solves this by breaking the match into discrete tokens in a single processing step.

Example: Parsing Key-Value Pairs

Consider an input string containing semi-colon-separated attributes: id=101; status=active; role=admin.

Using regex-group(), you can tokenize the string and separate keys from values simultaneously:

<xsl:analyze-string select="'id=101; status=active; role=admin'" regex="([a-zA-Z]+)=([a-zA-Z0-9]+)">
    <xsl:matching-substring>
        <attribute name="{regex-group(1)}">
            <xsl:value-of select="regex-group(2)"/>
        </attribute>
    </xsl:matching-substring>
</xsl:analyze-string>

In this transformation:

  • Group 1 ([a-zA-Z]+) captures the token key (e.g., id, status, role).
  • Group 2 ([a-zA-Z0-9]+) captures the token value (e.g., 101, active, admin).
  • The result transforms unstructured text directly into <attribute name="id">101</attribute> nodes.

Advantages Over Standard Tokenization

  1. Positional Precision: regex-group() allows direct mapping of sub-tokens without secondary parsing steps or array indexing.
  2. Selective Matching: Non-capturing groups (?:...) can be used to control matching logic without shifting the index numbers of the extracted tokens.
  3. Data Cleaning: Surrounding whitespace, punctuation, and structural markers (such as quotes or brackets) can be excluded from the captured output by placing them outside the capturing parentheses in the regex pattern.
