How to Handle NaN Values in XSLT

Processing arithmetic or numeric conversions in XSLT can result in NaN (Not-a-Number) when the processor encounters invalid numeric data or performs an undefined calculation. This article explains why NaN occurs in XSLT, provides the standard techniques to detect and intercept it in both XSLT 1.0 and XSLT 2.0+, and demonstrates how to substitute fallback values to ensure clean, valid output.

Why NaN Occurs in XSLT

In XPath and XSLT, NaN represents a value that is not representable as a numeric quantity. It typically appears when:

  • Applying the number() function to empty nodes or non-numeric strings (e.g., number('abc')).
  • Performing arithmetic operations on missing or non-numeric elements.
  • Dividing zero by zero (0 div 0).

Unchecked NaN outputs often break downstream XML or JSON parsers, making graceful handling essential.

Method 1: The String Comparison Approach (XSLT 1.0 and 2.0+)

The most readable way to intercept NaN is to convert the result of the calculation or conversion to a string and check if it matches 'NaN'.

Example using <xsl:choose>

<xsl:variable name="calculatedValue" select="number(price) * number(quantity)" />

<xsl:choose>
  <xsl:when test="string($calculatedValue) = 'NaN'">
    <output>0.00</output>
  </xsl:when>
  <xsl:otherwise>
    <output><xsl:value-of select="$calculatedValue" /></output>
  </xsl:otherwise>
</xsl:choose>

This method is backward-compatible with all XSLT versions and avoids parser errors across different processor implementations.

Method 2: The Self-Inequality Trick (XPath 1.0)

According to the IEEE 754 floating-point standard used by XPath, NaN is not equal to anything—including itself. Therefore, comparing a numeric expression to itself will only return false if the value is NaN.

<xsl:variable name="num" select="number(input)" />

<xsl:choose>
  <!-- If $num does not equal $num, it is guaranteed to be NaN -->
  <xsl:when test="$num != $num">
    <xsl:text>Default Value</xsl:text>
  </xsl:when>
  <xsl:otherwise>
    <xsl:value-of select="$num" />
  </xsl:otherwise>
</xsl:choose>

While concise, this method can be counterintuitive for developers unfamiliar with IEEE 754 rules, so code comments are recommended when using it.

Method 3: Pre-validation with castable as (XSLT 2.0 and 3.0)

In modern XSLT versions, the cleanest practice is to prevent NaN from occurring in the first place using the XPath castable as operator.

<xsl:variable name="rawPrice" select="item/price" />

<xsl:value-of select="
  if ($rawPrice castable as xs:decimal) 
  then xs:decimal($rawPrice) 
  else 0
" />

This prevents the engine from generating NaN during type casting, allowing you to establish immediate defaults.

Implementing an Inline Fallback Function (XSLT 2.0+)

For clean, reusable code in larger stylesheets, define a custom <xsl:function> to wrap numeric parsing and sanitize outputs.

<xsl:function name="my:safe-number" as="xs:double">
  <xsl:param name="value" as="item()?" />
  <xsl:param name="default" as="xs:double" />
  
  <xsl:sequence select="
    if ($value castable as xs:double) 
    then xs:double($value) 
    else $default
  " />
</xsl:function>

You can then apply calculations safely anywhere in your stylesheet:

<total>
  <xsl:value-of select="my:safe-number(order/subtotal, 0.0) + my:safe-number(order/tax, 0.0)" />
</total>
