How base-uri() Resolves Relative Paths in XSLT

The base-uri() function in XSLT and XPath determines the absolute base URI of a specified node or the static evaluation context. In XSLT processing, external assets, secondary data files, and modular stylesheets are often referenced using relative paths, and base-uri() provides the foundational reference point needed to accurately resolve those paths into fully qualified absolute URIs.

Understanding the Function

Defined in the XPath and XSLT specifications (version 2.0 and later), the base-uri() function returns the base URI property of a target node as an xs:anyURI string. It can be invoked in two ways:

  1. base-uri(node): Returns the base URI of the provided node.
  2. base-uri(): When called with no arguments, it returns the base URI of the context node.

If a node has no base URI (for instance, an in-memory constructed node with no assigned origin), the function returns the empty sequence.

The Mechanism for Resolving Relative Paths

Relative paths inside an XML ecosystem are inherently ambiguous without a reference anchor. When parsing an XML document or running a stylesheet, the processor relies on a base URI to determine the absolute location of external resources.

The base-uri() function works directly alongside the resolve-uri() function to normalize paths. The syntax typically looks like this:

resolve-uri(@href, base-uri(.))

In this expression, if @href contains images/graphic.png and the context node originates from https://example.com/docs/intro.xml, resolve-uri() uses the output of base-uri(.) to yield https://example.com/docs/images/graphic.png.

Determining Factors for Base URI Values

An element's base URI is not always identical to the file path of the root document. It is determined hierarchically according to the XML Base specification:

  • The Resource Entity: The physical URI of the external entity, input document, or stylesheet file containing the node.
  • The xml:base Attribute: Any xml:base attribute declared on the node itself or on any of its ancestor elements. An explicit xml:base="../shared/" overrides the default location for that element and its descendants.
  • Included and Imported Modules: When using <xsl:include> or <xsl:import>, elements in those templates inherit the base URI of the specific stylesheet module they reside in, rather than the primary entry-point stylesheet.

Static Context vs. Node Context

A common source of confusion in XSLT is the difference between the stylesheet's base URI and the source document's base URI:

  • Stylesheet Base URI: Used when resolving static imports, includes, or literals evaluated relative to the XSLT file itself (often retrieved via the static-base-uri() function).
  • Source Node Base URI: Retrieved via base-uri($node). This reflects the physical origin or xml:base of the input XML data.

When using functions like doc() or document(), passing a relative URI defaults to resolving against either the stylesheet instruction or the node, depending on the XSLT version and function signature used. Explicitly wrapping paths with resolve-uri($path, base-uri($node)) removes ambiguity, ensuring that the target file is resolved strictly against the data document's origin rather than the stylesheet's file location.
