HTML5 Serialization in XSLT 3.0

This article explains how specifying version="5.0" or html-version="5.0" in XSLT 3.0 alters the serialization of output documents to adhere to modern HTML standards. By enabling these parameters in the <xsl:output> declaration, developers transition from legacy HTML 4.01 formatting to contemporary HTML5 semantics, streamlining document type definitions, character encoding elements, void element rendering, and attribute handling.

The Role of version="5.0" and html-version="5.0"

In XSLT 2.0, the html output method defaulted to the HTML 4.01 recommendation. With the introduction of XSLT 3.0 and the underlying W3C XQuery and XPath Serialization 3.0 and 3.1 specifications, full support for HTML5 was standardized:

  • version="5.0": Introduced in Serialization 3.0 to signal that serialization should follow HTML5 rules instead of HTML 4.01.
  • html-version="5.0": Formally defined in Serialization 3.1 as a dedicated parameter to specify the target HTML version without conflicting with generic serialization version identifiers.

In modern processors such as Saxon, both declarations trigger the HTML5 serialization pipeline:

<xsl:output method="html" version="5.0" encoding="UTF-8" indent="yes"/>
<!-- Or using Serialization 3.1 syntax -->
<xsl:output method="html" html-version="5.0" encoding="UTF-8" indent="yes"/>

Key Effects on Output Generation

Setting the serialization target to HTML5 introduces four primary structural changes to the rendered document.

1. Simplified DOCTYPE Declaration

In legacy HTML serialization, generating a standard DOCTYPE required extensive system and public identifier definitions, resulting in lengthy headers such as:

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">

When targeting HTML 5.0, the serializer automatically produces the standard, case-insensitive HTML5 prelude:

<!DOCTYPE html>

2. Modern Character Encoding Metadata

When an XSLT transformation outputs a <head> element, serializers traditionally injected an older http-equiv metadata tag:

<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">

Under HTML 5.0 serialization rules, this tag is modernized into the compact HTML5 syntax:

<meta charset="UTF-8">

3. Void Element Formatting

HTML5 defines specific "void elements" (such as area, base, br, col, embed, hr, img, input, link, meta, source, track, and wbr) that must not contain child nodes.

Under XML/XHTML serialization, these elements require a self-closing slash (e.g., <br />), and under legacy HTML, they were often rendered inconsistently. With HTML 5.0 serialization, void elements are emitted without end tags or trailing slashes (e.g., <br>, <img src="...">), complying with the standard HTML syntax.

4. Boolean Attribute Handling

HTML5 recognizes boolean attributes where the presence of the attribute name represents the true value. While XML demands explicit key-value pairs (e.g., disabled="disabled"), HTML 5.0 serialization minimizes these attributes where appropriate, producing valid and clean markup such as <input type="checkbox" checked disabled>.

Support for Embedded SVG and MathML

Unlike HTML 4, HTML5 natively supports inline foreign namespaces, specifically SVG and MathML. When version="5.0" or html-version="5.0" is active, the serializer preserves namespace prefixes and casing requirements necessary for inline <svg> and <math> elements, allowing clean integration of vector graphics and mathematical notation without switching output methods to XML.
