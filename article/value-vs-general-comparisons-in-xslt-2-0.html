Value vs General Comparisons in XSLT 2.0

In XSLT 2.0 and XPath 2.0, comparison operators are divided into general comparisons (=, !=, <, <=, >, >=) and value comparisons (eq, ne, lt, le, gt, ge). This article breaks down the technical differences between these two groups, focusing on sequence handling, cardinality constraints, and boolean logic behavior to help you write safer and more predictable stylesheet transformations.

General Comparisons (=, !=, <, <=, >, >=)

General comparisons are designed to work with sequences of zero, one, or multiple items. They use existential quantification, meaning the comparison returns true if there is at least one pair of atomic values—one drawn from the left-hand sequence and one from the right-hand sequence—that satisfies the condition.

  • Multi-item support: If $a is (1, 2) and $b is (2, 3), the expression $a = $b returns true because the value 2 exists in both sequences.
  • The != trap: Because general comparisons evaluate existentially, $a != $b does not necessarily mean not($a = $b). For example, if $seq is (1, 2), the expression $seq != 1 evaluates to true because there is an item in the sequence (2) that does not equal 1. Similarly, (1, 2) != (1, 2) evaluates to true.
  • Empty sequences: If either operand is an empty sequence (()), a general comparison always evaluates to false. For example, () = () is false.

Value Comparisons (eq, ne, lt, le, gt, ge)

Value comparisons are designed for comparing individual, single atomic values. They enforce strict cardinality and do not search through sequences.

  • Strict cardinality: Both operands must evaluate to either a single atomic item or an empty sequence. If an operand evaluates to a sequence of two or more items, the processor raises a type error (XPTY0004).
  • Predictable negation: With value comparisons, $a ne $b is strictly equivalent to not($a eq $b), provided neither operand is an empty sequence.
  • Empty sequence handling: If either operand is an empty sequence, the value comparison returns an empty sequence (()), which evaluates to false in an effective boolean value context (such as an xsl:if test). Unlike general comparisons, no error is thrown for empty sequences, but multi-item sequences will immediately fail.

Key Differences Summary

Feature General Comparisons (=, !=, <, etc.) Value Comparisons (eq, ne, lt, etc.)
Accepted Cardinality Zero, one, or many items Zero or exactly one item
Multi-item Sequence Behavior Evaluates existentially across all pairs Raises a dynamic error (XPTY0004)
Empty Sequence Result Always returns false Returns an empty sequence ()
Negation Symmetry $a != $b can be true even when $a = $b is true $a ne $b is always not($a eq $b)

When to Use Each

Use general comparisons when:

  • You are querying node-sets or sequences where multiple matches are valid or expected (e.g., //category = 'tech').
  • You are maintaining backward compatibility with XSLT 1.0 code.

Use value comparisons when:

  • You know the operands should only ever represent a single value (e.g., comparing an ID, a count, or a specific attribute).
  • You want the stylesheet processor to alert you to data integrity bugs where an expression unexpectedly yields multiple values instead of a singleton.
