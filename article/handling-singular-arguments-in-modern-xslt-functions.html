Handling Singular Arguments in Modern XSLT Functions

Modern XSLT processors (version 2.0 and later) evaluate function arguments according to strict type and cardinality rules defined by the XPath 2.0+ specifications. When a function expects a singular argument—meaning an item with an occurrence indicator requiring exactly one item—supplying an empty sequence or multiple items triggers Function Conversion Rules. Under standard evaluation, any mismatch where zero items or more than one item is passed to a singular parameter results in a fatal dynamic type error (err:XPTY0004), unless explicit occurrence indicators permit it or XPath 1.0 compatibility mode is enabled.

Function Signatures and Occurrence Indicators

In XSLT 2.0, 3.0, and modern XPath, function parameters are declared with an item type and an optional occurrence indicator:

  • No indicator (e.g., xs:string or item()): Requires exactly one item.
  • ? (e.g., xs:string?): Allows zero or one item.
  • + (e.g., xs:string+): Allows one or more items.
  • * (e.g., xs:string*): Allows zero or more items.

When a parameter omits an occurrence indicator, the required cardinality defaults to exactly one.

The Function Conversion Rules

Before an argument value is bound to a parameter, modern XSLT applies Function Conversion Rules in a defined sequence:

  1. Atomization: If the required type is atomic (such as xs:integer or xs:string), any nodes supplied in the argument are atomized to retrieve their typed values.
  2. Type Promotion and Numeric Substitution: Atomized values may be promoted (e.g., xs:decimal to xs:double) or cast (such as xs:untypedAtomic to the target atomic type).
  3. Cardinality Checking: The processor counts the number of items in the resulting sequence and verifies that it satisfies the required occurrence indicator.

Passing Zero Items (The Empty Sequence)

If an expression evaluates to an empty sequence () and is passed to a singular argument:

  • If the signature requires exactly one item (item()): The cardinality check fails immediately. The processor raises a dynamic type error with the standard error code err:XPTY0004, halting transformation.
  • If the signature allows zero or one item (item()?): The empty sequence satisfies the cardinality check. The function executes, receiving () as the argument value. Built-in functions that accept optional singular arguments often return () in response.

Passing Multiple Items

If an expression evaluates to a sequence containing two or more items (or if atomization of a supplied node produces multiple atomic values):

  • Standard XSLT 2.0+ Behavior: The processor evaluates the length of the sequence against the expected single item. Because the sequence contains more than one item, the conversion rules cannot reduce it. A dynamic type error (err:XPTY0004) is raised. Unlike some programming languages, modern XSLT does not automatically discard trailing items or iterate over the sequence unless explicitly instructed using a mapping expression (such as !) or an xsl:for-each.

The XPath 1.0 Compatibility Mode Exception

If an XSLT 2.0+ stylesheet specifies version="1.0" on the xsl:stylesheet element or an enclosing element, the processor runs in XPath 1.0 Compatibility Mode. This changes how singular arguments are resolved:

  • Multiple Items: If a sequence of nodes is passed where a single atomic value is expected, the processor automatically takes the first item in the sequence and ignores the rest, mirroring classic XPath 1.0 behavior.
  • Zero Items: If an empty sequence is supplied where a single string or number is required, the processor converts the empty sequence into an empty string "" or NaN, respectively, rather than raising an error.
