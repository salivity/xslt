Using subsequence() for Pagination in XSLT 2.0

This article explores the role and significance of the subsequence() function introduced in XPath and XSLT 2.0 for implementing pagination patterns. It examines how this function replaces fragile, verbose legacy techniques from XSLT 1.0, details its performance benefits through streaming and early termination, and demonstrates how to implement a clean, dynamic pagination system in modern XSLT stylesheets.

The Legacy Challenge: Pagination in XSLT 1.0

In XSLT 1.0, pagination relied on filtering node-sets using predicates with the position() function:

<xsl:for-each select="item[position() &gt;= $startIndex and position() &lt;= $endIndex]">
    <!-- Process item -->
</xsl:for-each>

While functional for small documents, this approach has notable drawbacks:

  • Verbosity: Writing and maintaining compound boolean expressions for simple slicing adds unnecessary visual noise.
  • Context Sensitivity: The position() function depends heavily on the context size, making it tricky to use inside nested templates or after dynamic sorting without multiple temporary tree passes.
  • Performance Limitations: Many XSLT 1.0 engines evaluate the entire node-set before discarding elements outside the requested range, leading to high memory usage and slow response times on large XML datasets.

The Role of subsequence()

XPath 2.0 introduced the subsequence() function to extract a contiguous slice from any sequence:

fn:subsequence($sourceSeq as item()*, $startingLoc as xs:double) as item()*
fn:subsequence($sourceSeq as item()*, $startingLoc as xs:double, $length as xs:double) as item()*

In pagination workflows, the function takes the sequence of source items, a 1-based start index, and the desired page size.

Key Advantages in Pagination Patterns

1. Performance and Lazy Evaluation

Modern XSLT processors (such as Saxon) implement lazy evaluation for sequences. When using subsequence($items, $start, $pageSize), the processor can skip directly to $start and stop reading the input sequence once $pageSize items are retrieved. It does not need to construct or traverse the remainder of the dataset, drastically reducing execution time and memory footprint on large documents.

2. Separation of Sorting and Slicing

XSLT 2.0 allows sequences of nodes or atomic values to be stored in variables. You can sort or filter an entire dataset once, store the result in a variable, and slice it without re-evaluating the sort criteria:

<xsl:variable name="sortedItems" as="element(item)*">
    <xsl:perform-sort select="//item">
        <xsl:sort select="@date" order="descending"/>
    </xsl:perform-sort>
</xsl:variable>

<xsl:variable name="currentPage" select="subsequence($sortedItems, $startIndex, $pageSize)"/>

3. Simpler Offset Arithmetic

Calculating page boundaries becomes straightforward arithmetic rather than complex relational logic. Given a 1-based page number $pageNumber and a $pageSize:

$startIndex = (($pageNumber - 1) * $pageSize) + 1

Passing this value directly into subsequence($items, $startIndex, $pageSize) handles boundary conditions naturally. If the page requests fewer items than $pageSize (such as on the final page), subsequence() simply returns the available items without raising an error.

Implementation Example

The following template demonstrates a standard pagination pattern using subsequence():

<xsl:stylesheet version="2.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform" xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <xsl:param name="pageNumber" as="xs:integer" select="1"/>
    <xsl:param name="pageSize" as="xs:integer" select="10"/>

    <xsl:template match="/catalog">
        <xsl:variable name="allItems" select="product"/>
        <xsl:variable name="startIndex" select="(($pageNumber - 1) * $pageSize) + 1"/>
        <xsl:variable name="pagedItems" select="subsequence($allItems, $startIndex, $pageSize)"/>

        <div class="pagination-info">
            Displaying page <xsl:value-of select="$pageNumber"/> of 
            <xsl:value-of select="ceiling(count($allItems) div $pageSize)"/>
        </div>

        <ul class="product-list">
            <xsl:apply-templates select="$pagedItems"/>
        </ul>
    </xsl:template>

    <xsl:template match="product">
        <li><xsl:value-of select="name"/></li>
    </xsl:template>

</xsl:stylesheet>

Summary

The subsequence() function is a foundational utility for modern XSLT pagination. By abstracting sequence slicing into an engine-optimizable function, it eliminates the inefficiencies and structural fragility of XSLT 1.0 predicate filters, providing faster execution, cleaner stylesheets, and predictable paging behavior across datasets of any size.
