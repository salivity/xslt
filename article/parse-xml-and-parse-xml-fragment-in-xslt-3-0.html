parse-xml and parse-xml-fragment in XSLT 3.0

In XSLT 3.0, processing raw string data that contains markup is made possible through the standard parse-xml() and parse-xml-fragment() functions. This article explains the primary purpose of both functions, how they convert textual XML into navigable XPath Data Model (XDM) node trees, and the technical differences between parsing standalone XML documents versus arbitrary XML fragments.

The Purpose of String-to-XML Parsing

In modern data pipelines, XML is frequently embedded as escaped text inside JSON payloads, CDATA sections, database fields, or plain text files fetched via unparsed-text(). Prior to XSLT 3.0, transforming this embedded text required proprietary extension functions or multi-stage pipelines.

The parse-xml() and parse-xml-fragment() functions resolve this limitation by taking an xs:string input containing XML markup and dynamically constructing an in-memory document node (document-node()). Once converted, the contents can be queried using standard XPath expressions, matched against templates, or transformed like any other node tree.

The parse-xml() Function

The parse-xml() function is designed to parse a complete, well-formed XML document from a string.

  • Signature: parse-xml($arg as xs:string?) as document-node(element())?
  • Requirement: The input string must strictly conform to the XML specification for a well-formed document. This means it must contain exactly one root element, with all child elements properly nested and closed. An XML declaration (such as <?xml version="1.0"?>) is permitted but optional.
  • Output: It returns a document node containing exactly one child element node, along with any associated comments or processing instructions outside the root element.
  • Behavior on Failure: If the input string contains multiple top-level elements, loose text nodes at the top level, or syntax errors, the function raises a dynamic error (err:FODC0006).

Use parse-xml() when you are certain the incoming string represents a complete XML document with a single root wrapper.

The parse-xml-fragment() Function

The parse-xml-fragment() function is designed to handle well-formed XML fragments or external parsed entities, rather than standalone documents.

  • Signature: parse-xml-fragment($arg as xs:string?) as document-node()?
  • Requirement: The input string does not need a single root element. It can consist of multiple adjacent elements, bare text nodes, comments, processing instructions, or an empty string. The markup itself must still be well-formed (tags must close and nest correctly).
  • Output: It returns a document node that can contain zero, one, or multiple child nodes of any kind (elements, text, comments, processing instructions).
  • Behavior on Failure: It raises a dynamic error (err:FODC0006) only if the markup violates general XML syntax rules, such as mismatched tags or invalid characters.

Use parse-xml-fragment() when handling rich text fields, HTML-like snippets (e.g., <p>Hello</p><p>World</p>), or unstructured markup that lacks an overarching root element.
