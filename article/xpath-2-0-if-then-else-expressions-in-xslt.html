XPath 2.0 If-Then-Else Expressions in XSLT

The introduction of the if-then-else expression in XPath 2.0 drastically simplifies transformations in XSLT 2.0 by allowing conditional logic directly within XPath expressions. In earlier versions of XSLT, handling simple conditions required either verbose markup structures like <xsl:choose> or fragile XPath hacks. With inline conditional expressions, developers can write cleaner, more readable stylesheets, streamline Attribute Value Templates (AVTs), and perform evaluations directly inside expressions without creating unnecessary intermediate elements or variables.

Eliminating Verbose Markup

In XSLT 1.0, conditionally selecting a value typically required splitting logic across multiple lines using <xsl:choose>, <xsl:when>, and <xsl:otherwise>. For example, setting an attribute conditionally required wrapping the logic around <xsl:attribute>.

With XPath 2.0, this verbose structure collapses into a single expression:

<item status="{if (@active = 'true') then 'active' else 'inactive'}" />

By placing the logic directly inside the attribute value template or select attribute, the overall footprint of the stylesheet is substantially reduced.

Replacing XPath 1.0 Boolean Workarounds

Before XSLT 2.0, developers relying solely on XPath for inline conditions often used complex boolean tricks. A common idiom was using node sets and predicates:

concat(substring('Yes', 1, number($is-valid) * 3), substring('No', 1, number(not($is-valid)) * 2))

Or using sequence-selection tricks:

($value-if-true[$condition] | $value-if-false[not($condition)])[1]

These techniques were counterintuitive, error-prone, and heavily reliant on type coercion. The XPath 2.0 if-then-else syntax eliminates these workarounds with a standardized, readable format that explicitly states intent:

if ($is-valid) then 'Yes' else 'No'

Improving Variable Assignment and Functional Composition

Setting variable values conditionally in XSLT 1.0 often produced Result Tree Fragments (RTFs) instead of typed data when using child elements inside <xsl:variable>. In XSLT 2.0, using if-then-else in the select attribute preserves strict typing:

<xsl:variable name="discount" as="xs:decimal" 
              select="if ($customer/is-premium) then 0.20 else 0.05" />

This ensures that the assigned value retains its native schema type (such as xs:decimal or xs:string) rather than becoming an untyped document node, which prevents runtime conversion errors later in the transformation.

Nesting and Complex Branching

XPath 2.0 conditional expressions can be nested to handle multiple conditions sequentially. This mimics else-if behavior in other programming languages without needing multiple nested <xsl:choose> blocks:

if ($score >= 90) then 'A'
else if ($score >= 80) then 'B'
else if ($score >= 70) then 'C'
else 'F'

Every if expression in XPath 2.0 requires an else branch, ensuring that the expression always resolves to a value or an empty sequence (()). This explicit requirement guarantees deterministic output across complex mapping and filtering scenarios.
