Handle Missing Files in XSLT doc() Resolution

Loading external XML files during transformation is a common requirement, but missing resources can easily cause transformations to fail with fatal errors. In modern XSLT, stylesheets can gracefully handle missing external files during doc() or document() resolution by using the doc-available() function to check existence, leveraging xsl:try and xsl:catch blocks to trap dynamic retrieval errors, or delegating the failure recovery to a custom URI resolver at the processor level.

Checking Availability with doc-available() (XSLT 2.0+)

The standard and most common method to prevent fatal errors when reading an external document is the XPath function doc-available(). This function takes the URI of the target document, attempts to resolve it, and returns true() if the document exists and consists of well-formed XML, or false() otherwise.

Using doc-available() in combination with an xsl:choose or xsl:if instruction ensures that the doc() function is only called when safe:

<xsl:variable name="file-uri" select="'external-data.xml'"/>

<xsl:choose>
    <xsl:when test="doc-available($file-uri)">
        <xsl:apply-templates select="doc($file-uri)/*"/>
    </xsl:when>
    <xsl:otherwise>
        <!-- Graceful fallback logic -->
        <status>File not found or invalid: <xsl:value-of select="$file-uri"/></status>
    </xsl:otherwise>
</xsl:choose>

Trapping Exceptions with xsl:try and xsl:catch (XSLT 3.0)

In XSLT 3.0, processors support exception handling via xsl:try and xsl:catch. While doc-available() is proactive, it may perform the document request twice (once to verify availability and once during doc()). Using xsl:try handles the error reactively, catching the standard dynamic retrieval error (error code Q{http://www.w3.org/2005/xqt-errors}FODC0002):

<xsl:try>
    <xsl:sequence select="doc('external-data.xml')"/>
    <xsl:catch errors="*:FODC0002">
        <fallback-data>Default Content</fallback-data>
    </xsl:catch>
</xsl:try>

This approach is particularly useful in environments where network latency, transient timeouts, or dynamic authentication issues make doc-available() insufficient or inefficient.

Managing Missing Files in XSLT 1.0

XSLT 1.0 lacks both doc-available() and xsl:try. According to the XSLT 1.0 specification, calling document('missing-file.xml') should either return an empty node-set or signal an error, depending on processor implementation.

If the processor defaults to returning an empty node-set, the stylesheet can check whether nodes were retrieved:

<xsl:variable name="external-doc" select="document('missing-file.xml')"/>

<xsl:choose>
    <xsl:when test="$external-doc">
        <xsl:apply-templates select="$external-doc"/>
    </xsl:when>
    <xsl:otherwise>
        <fallback>File unavailable</fallback>
    </xsl:otherwise>
</xsl:choose>

If the processor treats missing files as a fatal error, the failure must be handled outside the stylesheet by configuring an application-level URIResolver (such as in Java or .NET). A custom resolver can intercept the request, detect the missing file, and return an empty XML document or a pre-defined fallback XML tree instead of throwing an unhandled exception.
