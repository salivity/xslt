Item Type vs Atomic Type vs Node Type in XSLT

In XSLT and XPath 2.0 and later, sequence validation relies on the XQuery and XPath Data Model (XDM) to constrain and verify variables, function parameters, and template outputs. Understanding sequence validation requires distinguishing between an item type, an atomic type, and a node type. An item type is the generalized supertype representing any individual constituent of a sequence, whereas atomic types represent typed scalar data values and node types represent structural components of an XML tree.

The XDM Hierarchy

Everything in modern XSLT is a sequence of zero, one, or more items. The relationship between item types, node types, and atomic types forms a strict type hierarchy:

  • item(): The universal base type for all sequence entries.
  • node(): A subtype of item() representing document tree components.
  • xs:anyAtomicType: A subtype of item() representing scalar values.

In the XDM, node() and xs:anyAtomicType are disjoint. A single item can be a node or an atomic value, but it cannot be both at the same time.

Item Type (item())

An item type is the broadest categorization available for sequence validation. An item is any single object that can exist within an XSLT sequence.

When validating sequences using as="item()*", the processor accepts:

  • Any kind of node (elements, attributes, text nodes, documents).
  • Any atomic value (integers, strings, booleans, dates).
  • Functions, maps, and arrays (in XSLT 3.0).

Using an item type declaration provides the least strict type safety. It ensures only that an item exists, without enforcing whether it represents structured XML markup or simple scalar data.

Node Type (node())

A node type represents a physical or virtual component of an XML document tree. Nodes possess node identity, a position within a document hierarchy, and document order.

Node types can be specified broadly using node() or narrowed to specific kinds of nodes:

  • element() or element(name, type): Represents XML elements, with optional name and schema constraints.
  • attribute(): Represents XML attributes.
  • text(): Represents character data nodes within elements or documents.
  • document-node(): Represents the root node of an XML document or document fragment.
  • comment() and processing-instruction(): Represent metadata markup.

Validating an argument as as="node()" requires an actual node reference. If you pass a literal string like "test" to a parameter typed as node(), the XSLT processor raises a type error.

Atomic Type (xs:anyAtomicType)

An atomic type represents a scalar, indivisible value without child nodes, attributes, or tree identity. Atomic types are derived from the W3C XML Schema specification and include:

  • xs:string
  • xs:integer, xs:decimal, xs:double
  • xs:boolean
  • xs:date, xs:dateTime
  • xs:QName

When validating a sequence with an atomic type such as as="xs:string", the processor expects a typed value. While an element node containing the text "123" has a string value, it is not an atomic value itself. To pass a node to a parameter expecting an atomic type, the node must undergo atomization (extracting its typed value via functions like data() or automatic typed conversions in function calls).

Key Differences in Sequence Validation

Characteristic Item Type (item()) Node Type (node()) Atomic Type (xs:anyAtomicType)
Scope Universal supertype; includes nodes, atomic values, and functions. Subtype of item(); restricted to XML tree constructs. Subtype of item(); restricted to scalar values.
Hierarchy Root of the item hierarchy. Excludes atomic values and functions. Excludes nodes and functions.
Tree Identity May or may not have identity depending on the item. Always possesses identity and document order. Never possesses identity or document order.
Atomization Preserves items as-is without forced extraction. Requires explicit or implicit atomization to yield values. Already an atomic value; no atomization needed.
Validation Example as="item()*" allows <e/>, 42, and "text". as="element()" allows <e/>, rejects "42". as="xs:integer" allows 42, rejects <e>42</e> without atomization.
