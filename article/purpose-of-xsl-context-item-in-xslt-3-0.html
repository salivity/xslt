Purpose of xsl:context-item in XSLT 3.0

The xsl:context-item declaration in XSLT 3.0 establishes the contract for the initial context item of a stylesheet or package by specifying whether it is required, optional, or prohibited, and defining its expected data type. It provides static and dynamic type-checking before transformation begins, preventing runtime failures and clarifying whether a stylesheet expects a source document or is designed to run independently.

Defining Input Requirements with the use Attribute

In older versions of XSLT, stylesheets implicitly expected a primary XML input document to set the initial context node. XSLT 3.0 allows transformations to initiate via named templates or functions without any source document. The use attribute of xsl:context-item explicitly declares this dependency using one of three values:

  • required: The transformation engine must be supplied with an initial context item. If none is provided, the processor raises an error before execution begins.
  • optional: The stylesheet can accept an initial context item, but it can also execute without one (for example, falling back to a default value or alternative logic).
  • absent: The stylesheet explicitly prohibits an initial context item. If an input document or node is passed, the processor rejects it. This is typical for standalone utilities that generate data or pull from external APIs using functions like doc() or json-doc().

Enforcing Data Types with the as Attribute

Beyond declaring presence, xsl:context-item uses the as attribute to define the sequence type expected for the context item.

For instance, setting as="document-node(element(orders))" ensures that the context item is not just any XML node, but specifically a document node containing an <orders> root element. If the calling application passes an unexpected document structure, a text node, or a map, the processor immediately generates a type error.

Benefits of xsl:context-item

  • Early Error Detection: Type mismatches and missing inputs are identified at the initialization stage rather than deep inside complex template rules.
  • Self-Documentation: It acts as a formal interface definition at the top of the stylesheet, making it clear to other developers and systems what input is expected.
  • Package Encapsulation: When writing reusable components in XSLT 3.0 packages, xsl:context-item defines the preconditions necessary for the package's public components to function reliably.
