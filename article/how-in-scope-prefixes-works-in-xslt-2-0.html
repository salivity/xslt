How in-scope-prefixes Works in XSLT 2.0

The fn:in-scope-prefixes() function in XSLT 2.0 and XPath 2.0 returns a sequence of strings representing all namespace prefixes that are actively bound to a specific element node. This article explains the internal mechanics of how the function identifies and resolves these prefixes from the XML hierarchy, handles default and built-in namespaces, and applies to real-world transformation scenarios.

Function Definition and Syntax

The fn:in-scope-prefixes() function takes a single element node as an argument and returns an unordered sequence of zero or more strings:

fn:in-scope-prefixes($element as element()) as xs:string*

If the supplied argument is not an element node, a type error is raised.

How Prefix Resolution Operates

To retrieve all bound prefixes, the function evaluates the XML document's structure and namespace model for the target element using the following rules:

  1. Hierarchy Traversal (Inheritance): Namespaces declared on ancestor elements cascade down the tree. The function collects prefixes defined on the target element as well as those inherited from any parent elements above it.
  2. Local Overriding (Shadowing): If a child element rebinds a prefix to a different namespace URI than an ancestor, the local binding takes precedence. The sequence contains the prefix once, reflecting its state at that specific element.
  3. The Default Namespace: If a default namespace (xmlns="...") is active on the element (either locally or inherited), it is represented in the output sequence as a zero-length string (""). If no default namespace is in scope, no zero-length string is returned.
  4. The Predefined xml Prefix: The prefix xml, implicitly bound to http://www.w3.org/XML/1998/namespace, is always included in the returned sequence for any valid element.

Resolution Example

Consider the following XML fragment:

<root xmlns="http://example.com/default" xmlns:meta="http://example.com/meta">
    <item xmlns:data="http://example.com/data" id="1">Content</item>
</root>

Evaluating in-scope-prefixes() on the <item> element:

<xsl:value-of select="in-scope-prefixes(//item)" separator=", " />

The processor checks <item> and its ancestors:

  • data: Declared locally on <item>.
  • meta: Inherited from <root>.
  • "" (empty string): The default namespace inherited from <root>.
  • xml: Automatically bound by the XML standard.

The function returns the sequence: ("", "meta", "data", "xml") (order is implementation-dependent).

Key Behavioral Differences to Note

  • No URI Retrieval: in-scope-prefixes() only returns the prefix names. To find the corresponding URI for a given prefix, use the companion function fn:namespace-uri-for-prefix($prefix, $element).
  • Namespace Axis Alternative: Unlike the deprecated namespace::* XPath axis, which produces full namespace nodes, in-scope-prefixes() produces primitive xs:string items, reducing memory overhead during namespace introspection in XSLT 2.0 stylesheets.
