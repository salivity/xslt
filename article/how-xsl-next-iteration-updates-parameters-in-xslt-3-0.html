How xsl:next-iteration Updates Parameters in XSLT 3.0

XSLT 3.0 introduced the <xsl:iterate> instruction to process sequences sequentially while maintaining the language’s core functional programming paradigm. Central to this construct is <xsl:next-iteration>, an instruction that triggers the subsequent step of the loop and handles state changes. This article explains how <xsl:next-iteration> modifies parameter values between cycles, how omitted parameters behave, and how immutability is preserved throughout the process.

The Iteration Model in XSLT 3.0

Traditional procedural loops rely on mutable variables that change their values in place. Because XSLT is a declarative, functional language, variables cannot be updated dynamically. Instead, XSLT 3.0 models loops as tail-recursive functions.

The <xsl:iterate> element declares the sequence to be processed and initializes state variables using <xsl:param>. Each pass through the loop processes one item from the sequence. To proceed to the next item with updated state values, the stylesheet executes <xsl:next-iteration>.

Passing New State via <xsl:with-param>

State updates occur explicitly by passing <xsl:with-param> elements inside <xsl:next-iteration>. The name attribute of <xsl:with-param> must match an <xsl:param> declared at the top of the parent <xsl:iterate> instruction.

During execution:

  1. The expression in the select attribute (or contained sequence constructor) of <xsl:with-param> is evaluated in the context of the current iteration.
  2. The evaluated result is bound to the target parameter name for the next iteration only.
  3. The current iteration finishes without changing the values of its own in-scope parameters, preserving immutability.

Example: Maintaining a Running Total

<xsl:iterate select="order/item">
  <!-- Parameter initialized on the first iteration -->
  <xsl:param name="running-total" as="xs:decimal" select="0.0"/>

  <xsl:variable name="current-price" select="xs:decimal(@price)" />
  
  <!-- Output content for the current item -->
  <item price="{$current-price}" total="{$running-total + $current-price}"/>

  <!-- Move to the next item and update the state -->
  <xsl:next-iteration>
    <xsl:with-param name="running-total" select="$running-total + $current-price"/>
  </xsl:next-iteration>
</xsl:iterate>

In this example, $running-total remains fixed for the duration of the current cycle. The expression $running-total + $current-price calculates a new value that is assigned to $running-total only when the loop advances to the next item.

Implicit Preservation of Omitted Parameters

A key feature of <xsl:next-iteration> is its handling of omitted parameters. If an <xsl:param> declared in <xsl:iterate> does not have a corresponding <xsl:with-param> inside <xsl:next-iteration>, its value does not reset to its initial default. Instead, it implicitly carries forward its value from the current iteration to the next.

For example, consider an iteration managing two state parameters:

<xsl:iterate select="tokens">
  <xsl:param name="line-number" as="xs:integer" select="1"/>
  <xsl:param name="indent-level" as="xs:integer" select="0"/>

  <!-- Logic processing tokens -->

  <xsl:next-iteration>
    <!-- line-number increments -->
    <xsl:with-param name="line-number" select="$line-number + 1"/>
    <!-- indent-level is omitted; it retains its current value in the next step -->
  </xsl:next-iteration>
</xsl:iterate>

Because $indent-level is omitted from <xsl:next-iteration>, the next cycle receives the exact value $indent-level held during the cycle that just concluded.

Execution Rules and Constraints

To ensure predictable state management, XSLT 3.0 enforces specific structural rules on <xsl:next-iteration>:

  • Tail Position Requirement: <xsl:next-iteration> must occur in a tail position within the <xsl:iterate> instruction. It cannot be followed by sibling instructions that produce output, as the transition to the next state must represent the final action of the current cycle.
  • Mutual Exclusivity with <xsl:break>: An iteration can either advance to the next step using <xsl:next-iteration> or terminate early using <xsl:break>. A single code path cannot execute both.
  • Scope Validity: A <xsl:with-param> child of <xsl:next-iteration> cannot reference parameters that are not declared at the top of the enclosing <xsl:iterate>. Passing undeclared parameters results in a static error.
