Embed Raw Markup in XSLT with disable-output-escaping

This guide explains how to prevent XSLT processors from escaping HTML and XML characters such as < and > using the disable-output-escaping attribute. By default, XSLT escapes special characters to ensure valid document structure, but certain scenarios require rendering raw markup stored as text. Below, you will learn the syntax, practical implementation examples, and essential caveats when using this technique in both <xsl:value-of> and <xsl:text> elements.

The disable-output-escaping Attribute

In XSLT, elements that output text automatically convert characters like < to &lt;, > to &gt;, and & to &amp;. To bypass this behavior and emit raw, unescaped tags directly into the output stream, add the attribute disable-output-escaping="yes".

This attribute is supported on two core XSLT elements:

  • <xsl:value-of>
  • <xsl:text>

Rendering Escaped XML/HTML Content

A common scenario involves an XML source containing pre-formatted HTML within a node (often imported from a CMS or legacy system):

<!-- Source XML -->
<article>
  <content>&lt;p&gt;This is &lt;strong&gt;bold&lt;/strong&gt; text.&lt;/p&gt;</content>
</article>

Standard Behavior (Default)

<xsl:value-of select="article/content" />

Output:

&lt;p&gt;This is &lt;strong&gt;bold&lt;/strong&gt; text.&lt;/p&gt;

Disabling Output Escaping

<xsl:value-of select="article/content" disable-output-escaping="yes" />

Output:

<p>This is <strong>bold</strong> text.</p>

Using disable-output-escaping with <xsl:text>

When outputting structural tags that cannot be represented directly as XML nodes inside the stylesheet (for instance, conditional wrapper tags), use <xsl:text>:

<xsl:if test="position() = 1">
  <xsl:text disable-output-escaping="yes">&lt;div class="group"&gt;</xsl:text>
</xsl:if>

<xsl:value-of select="item" />

<xsl:if test="position() = last()">
  <xsl:text disable-output-escaping="yes">&lt;/div&gt;</xsl:text>
</xsl:if>

Important Considerations and Limitations

  1. Serializer Dependency: disable-output-escaping only takes effect when the XSLT processor serializes the result tree directly to text or a stream. If the transformation outputs to a DOM tree or an in-memory document node, the attribute is typically ignored.
  2. Security Concerns: Rendering unescaped markup from untrusted input exposes applications to Cross-Site Scripting (XSS) vulnerabilities. Always sanitize content before disabling escaping.
  3. Alternative Solutions: In modern XSLT (2.0 and 3.0), parsing unescaped HTML into true XML nodes using functions like fn:parse-xml() is generally preferred over disabling escaping, as it maintains document validity.
