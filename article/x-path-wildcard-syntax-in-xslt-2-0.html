XPath Wildcard Syntax in XSLT 2.0

This article provides an overview of how extended wildcard syntax—specifically *:element-name and prefix:*—functions within XPath expressions and XSLT 2.0 match patterns. You will learn the mechanics behind these wildcard forms, how they resolve namespaces, how they replace verbose XPath 1.0 workarounds, and how they affect template match priorities in XSLT stylesheets.

The Need for Expanded Wildcards

In XPath 1.0, element matching was strictly all-or-nothing regarding namespaces. You could match a specific qualified name (prefix:element) or any node regardless of name using *. Matching an element by its local name while ignoring its namespace required verbose predicate checks such as *[local-name() = 'item'].

XPath 2.0 (and consequently XSLT 2.0) resolved this limitation by introducing expanded QName wildcard syntax, allowing partial wildcard matching based either on the local name or the namespace URI.

Matching by Local Name: *:element-name

The *:element-name wildcard syntax matches any element with the specified local name, regardless of what namespace it belongs to.

  • How it operates: The parser ignores the namespace URI of the context node completely. It evaluates to true if the node's local name matches the string following the colon.
  • Namespace handling: It matches nodes in a specific namespace (e.g., {http://example.com/ns}item), nodes in an arbitrary default namespace, and nodes in no namespace at all.
  • Attribute support: This syntax also applies to attributes via @*:attribute-name.
  • Example:
<xsl:template match="*:title">
    <!-- Matches <title>, <atom:title>, <dc:title>, etc. -->
    <h1><xsl:value-of select="."/></h1>
</xsl:template>

This pattern functions as a direct, optimized equivalent to the XPath 1.0 expression *[local-name() = 'title'].

Matching by Namespace: prefix:*

The prefix:* wildcard syntax matches any element within the namespace bound to the given prefix, regardless of the element's local name.

  • How it operates: The prefix must be declared in scope in the XSLT stylesheet (typically on the <xsl:stylesheet> element). XPath resolves prefix to its associated namespace URI and matches any element node whose namespace URI equals that URI.
  • Local name handling: The specific name of the element is ignored; any element belonging to the bound namespace satisfies the pattern.
  • Attribute support: This syntax also works with attributes using @prefix:*.
  • Example:
<!-- Assuming xmlns:svg="http://www.w3.org/2000/svg" is declared -->
<xsl:template match="svg:*">
    <!-- Matches <svg:svg>, <svg:path>, <svg:circle>, etc. -->
    <div class="svg-element">
        <xsl:apply-templates/>
    </div>
</xsl:template>

Pattern Priority in XSLT 2.0

When used inside the match attribute of <xsl:template>, wildcards affect the default conflict resolution priority according to the XSLT specification:

  1. Fully qualified names (e.g., prefix:element or element): Default priority is 0.
  2. Partial wildcards (e.g., *:element or prefix:*): Default priority is -0.25.
  3. Generic wildcards (e.g., * or @* or node()): Default priority is -0.5.

Because partial wildcards have a priority of -0.25, they take precedence over generic wildcards (*) while remaining subordinate to fully qualified element matches (prefix:element) without requiring manual priority attributes.
