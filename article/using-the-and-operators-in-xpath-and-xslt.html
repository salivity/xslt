Using the ? and => Operators in XPath and XSLT

Modern versions of XPath and XSLT (3.0 and 3.1) introduced functional programming capabilities and native support for JSON-like data structures such as maps and arrays. Central to these improvements are the arrow operator (=>) and the lookup operator (?). This article explains the technical purpose of both operators, how they eliminate deeply nested expressions, and how they streamline working with maps, arrays, and dynamic function execution in modern XML stylesheets.

The Arrow Operator (=>)

The arrow operator (=>) provides syntactic sugar for function chaining. In traditional XPath expressions, nested function calls must be read from the inside out, which often harms readability when applying multiple transformations to a single value.

The arrow operator passes the result of the expression on its left as the first argument to the function on its right.

Syntax Comparison

Without the arrow operator (nested syntax):

fn:upper-case(fn:normalize-space(fn:substring($input, 1, 20)))

With the arrow operator:

$input => fn:substring(1, 20) => fn:normalize-space() => fn:upper-case()

Key Benefits

  • Readability: Logic flows from left to right in the exact order execution occurs.
  • Maintainability: Adding, removing, or reordering steps in a data transformation pipeline does not require re-balancing enclosing parentheses.
  • Argument Handling: Any additional arguments defined in the target function follow the second position onward, while the piped value automatically satisfies the first argument.

The Dynamic Lookup Operator (?)

The question mark operator (?) is the postfix lookup operator introduced in XPath 3.1. Its primary purpose is navigating and retrieving data dynamically from composite structures: maps, arrays, and dynamically resolved function items.

XPath 3.1 treats maps and arrays as functions. The ? operator provides a concise, null-safe syntax for accessing their contents without having to call explicit retrieval functions.

1. Map Lookup

When applied to a map, ? queries entry values by their key:

let $user := map { "name": "Alice", "role": "admin" }
return $user?name

If the key does not exist, it evaluates to an empty sequence (()) rather than throwing an error, making dynamic lookups resilient.

2. Array De-referencing and Flattening

When applied to an array, ? accesses members by their 1-based integer index or unfolds the entire array using the wildcard *:

let $scores := [95, 88, 72]
return $scores?1       (: Returns 95 :)

let $all := $scores?*  (: Unpacks the array into a sequence of items: (95, 88, 72) :)

3. Unary Lookup and Filtering

The lookup operator can be used as a unary operator (omitting the left-hand expression) within predicates or path expressions, operating directly on the current context item:

$users[?role = 'admin']?name

In this case, ?role inspects the role key of each map in the sequence $users, and ?name extracts the corresponding name for all matches.

Combining ? and => in Modern Pipelines

These two operators work together to simplify JSON processing and complex transformations within XSLT 3.0 templates.

let $response := fn:json-doc('api-data.json')
return $response?items?*
         => fn:filter(function($item) { $item?status = 'active' })
         => fn:sort((), function($item) { $item?name })

In this pipeline:

  1. ?items?* navigates into the JSON structure and flattens the items array into a sequence.
  2. => pipelines the resulting sequence directly into higher-order functions (filter and sort) without temporary variables or nested parentheses.
