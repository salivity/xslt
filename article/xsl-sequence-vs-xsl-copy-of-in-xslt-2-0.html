xsl:sequence vs xsl:copy-of in XSLT 2.0

In XSLT 2.0, both <xsl:sequence> and <xsl:copy-of> are used to output data and construct sequences, but they handle items differently. The fundamental distinction lies in node identity and memory allocation: <xsl:copy-of> creates new, deep copies of selected nodes, assigning them new node identities, whereas <xsl:sequence> returns references to the original items, preserving their original identity, parentage, and type.

Node Identity and Duplication

When you use <xsl:copy-of select="$nodes"/>, the XSLT processor creates a deep duplicate of every node in the selected sequence, along with its attributes and descendant nodes. These duplicated nodes are brand new instances:

  • They receive distinct, newly generated node identities.
  • Testing for node equality using the is operator between the original node and the copied node returns false.

In contrast, <xsl:sequence select="$nodes"/> does not create copies. It adds the original nodes directly to the result sequence:

  • The node identities remain identical to the sources.
  • Comparing an item returned by <xsl:sequence> to the original using is returns true.

Preservation of Node Hierarchy and Context

Because <xsl:copy-of> creates new nodes, those nodes are detached from their original document context. Their parent, ancestor, and sibling axes are either severed or redirected to the newly constructed tree structure.

<xsl:sequence> maintains the original tree relationships. If you pass a node via <xsl:sequence>, you can still navigate up to its original parent (parent::*) or access its document root (root()) elsewhere in your processing logic.

Handling Atomic Values and Non-Node Items

XSLT 2.0 introduced a richer type system based on XPath 2.0, supporting sequences of atomic values (such as strings, integers, and booleans) alongside nodes.

  • <xsl:sequence> is the native instruction for handling arbitrary sequences. It can emit nodes, atomic values, or a mixture of both without modification or type coercion.
  • <xsl:copy-of> can output atomic values in XSLT 2.0, but its primary design goal remains tree-fragment and node copying. When constructing elements, using <xsl:copy-of> with atomic values creates text nodes in the target tree, whereas <xsl:sequence> within functions or variable definitions typed with as attributes preserves the exact atomic data types.

Performance and Memory Overhead

Creating deep copies of large node trees requires allocating new memory and duplicating all child elements, attributes, and text nodes. Because <xsl:copy-of> performs this deep cloning, it incurs a significant performance and memory penalty on large XML payloads.

<xsl:sequence> merely constructs a sequence of pointers (references) to the existing nodes already stored in memory. As a result, <xsl:sequence> is substantially faster and significantly more memory-efficient.

When to Use Which

  • Use <xsl:sequence> when writing functions (<xsl:function>), passing arguments to named templates, or returning items where you want to inspect types, check node identities, or traverse the original node's ancestors. It is the preferred default instruction in XSLT 2.0 for returning data without side effects.
  • Use <xsl:copy-of> only when you explicitly need a detached, independent copy of an XML structure—such as when injecting existing nodes into a new output document or modifying a subtree without mutating the source representation.
