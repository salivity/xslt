How on-no-match="deep-copy" Works in XSLT 3.0

In XSLT 3.0, the on-no-match="deep-copy" attribute fundamentally redefines the built-in template rules for processing nodes that lack an explicit template match. Instead of stripping element tags and passing processing down to their children as legacy XSLT does, this setting instructs the processor to copy the entire unmatched node and its descendants directly to the result tree. This article explains how this behavior differs from traditional defaults, eliminates boilerplate identity templates, and affects recursive processing.

The Traditional Built-In Template Behavior

In XSLT 1.0 and 2.0, the default behavior for unmatched element nodes is defined as recursive traversal: the processor discards the element tag and executes <xsl:apply-templates/> on its children. For text and attribute nodes, the default behavior copies their string values to the output. In XSLT 3.0, this legacy behavior is explicitly represented by setting on-no-match="text-only-copy" on the xsl:mode declaration. Under this model, any element lacking a matching rule is stripped from the markup, requiring developers to write an explicit "identity transform" template to preserve document structure.

How on-no-match="deep-copy" Changes Processing

Declaring <xsl:mode on-no-match="deep-copy"/> changes the fallback action for any unmatched node to the equivalent of an <xsl:copy-of select="."/> instruction.

When the XSLT processor encounters an element, attribute, comment, processing instruction, or text node without an explicit <xsl:template> rule:

  1. It copies that node immediately to the output.
  2. If the node is an element, it copies all of its attributes, namespace declarations, and child nodes recursively in a single operation.
  3. It halts further template matching on the children of that unmatched element.

Eliminating the Identity Transform

Historically, modifying an XML document while preserving most of its original structure required a standard identity template:

<xsl:template match="@* | node()">
  <xsl:copy>
    <xsl:apply-templates select="@* | node()"/>
  </xsl:copy>
</xsl:template>

With on-no-match="deep-copy", this boilerplate is no longer necessary. The stylesheet only needs to define templates for the specific elements that require alteration or removal. Any part of the document not targeted by a template is preserved automatically.

Deep Copy vs. Shallow Copy

A critical distinction in XSLT 3.0 is the difference between on-no-match="deep-copy" and on-no-match="shallow-copy".

When using deep-copy, the processor does not evaluate templates on the descendants of an unmatched element. The entire subtree is copied verbatim. Consequently, if you have a template matching a deeply nested element (e.g., match="item/price"), but there is no template matching <item> or its ancestors, the processor will copy <item> and all its contents directly upon encountering it. The template for <price> will never execute because template traversal stops at <item>.

If child elements inside an unhandled parent element still require transformation, on-no-match="shallow-copy" should be used instead. shallow-copy copies the current node itself and automatically applies templates to its attributes and children, ensuring downstream templates remain reachable throughout the document tree.

Performance and Streaming Advantages

Because deep-copy copies entire subtrees as single blocks without evaluating template rules for each individual child node, it can significantly improve transformation speed on large documents. Additionally, it integrates well with XSLT 3.0 streaming, allowing the processor to pipe unmanipulated XML chunks directly to the output pipeline with minimal memory overhead.
