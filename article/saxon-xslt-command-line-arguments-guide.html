Saxon XSLT Command-Line Arguments Guide

This guide provides a practical overview of executing XSLT transformations using the Saxon processor directly from the command line. It covers the core syntax, mandatory flags for source and stylesheet files, standard output options, and essential operational switches used to configure transformation behavior.

Basic Syntax

To run a transformation using Saxon, invoke the Java runtime against the Saxon JAR file, followed by the required arguments and any optional parameters:

java -jar saxon-he-12.x.jar -s:source.xml -xsl:stylesheet.xsl -o:output.xml

(Note: Depending on your installation, the class name net.sf.saxon.Transform can be used instead of -jar if Saxon is on your Java classpath.)

Essential Arguments

Saxon uses a distinct colon syntax (-flag:value) to bind arguments to their values without requiring spaces.

  • -s:<filename>: Specifies the source XML document to be transformed. Example: -s:input.xml.
  • -xsl:<filename>: Specifies the primary XSLT stylesheet file. Example: -xsl:transform.xsl.
  • -o:<filename>: Designates the output destination file. If omitted, the transformation output is written directly to standard output (stdout). Example: -o:result.html.

Transformation Entry Points

When starting a transformation without a standard source document or targeting a specific entry point, use the following options:

  • -it or -it:<template-name>: Invokes an initial named template. If no name is provided, execution begins at the template named xsl:initial-template. This is often used when generating documents without a primary input XML file.
  • -im:<mode-name>: Specifies the initial processing mode for the transformation.

Operational and Diagnostic Flags

Saxon includes several flags for monitoring performance, handling errors, and managing resolution:

  • -t: Enables timing and environment tracing. It displays the Saxon version, Java version, loading times, and execution duration.
  • -catalog:<files>: Specifies catalog files used to resolve external entity and URI references.
  • -now:<yyyy-mm-ddThh:mm:ss>: Sets an explicit date and time for dynamic functions like current-dateTime(), ensuring repeatable results during automated testing.
  • -warnings:silent|recover|fatal: Determines how the processor handles recoverable errors:
    • silent: Suppresses warning output and continues execution.
    • recover: Reports warnings but continues processing.
    • fatal: Treats warnings as fatal errors and aborts transformation.
  • -versionmsg:off: Disables the default startup message that identifies the Saxon product release.

Passing Stylesheet Parameters

Global parameters defined in your XSLT via <xsl:param name="paramName"/> can be set by adding name=value pairs at the end of the command line:

java -jar saxon-he-12.x.jar -s:input.xml -xsl:transform.xsl -o:output.xml paramName=paramValue "message=Hello World"

To pass parameters as untyped atomic values or XPath expressions, prefix the parameter name:

  • +paramName=value: Interpreted as a string or filename, resolved as a document reference where applicable.
  • ?paramName=expression: Evaluates the right-hand value as an XPath 3.1 expression rather than a literal string.
