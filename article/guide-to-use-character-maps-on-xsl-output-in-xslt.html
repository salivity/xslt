Guide to use-character-maps on xsl:output in XSLT

The use-character-maps attribute on the <xsl:output> element in XSLT 2.0 and later allows developers to customize how specific characters are serialized into the final output document. By referencing one or more <xsl:character-map> declarations, this attribute instructs the serializer to substitute designated Unicode characters with specified text strings, completely bypassing standard XML and HTML character escaping. This article explains the core purpose of the use-character-maps attribute, how it works during serialization, and why it serves as a robust alternative to legacy escaping workarounds.

Purpose and Functionality

In standard XSLT serialization, special characters such as <, >, and &, as well as characters outside the target output encoding, are automatically converted to predefined XML entities (like &lt;) or numeric character references (like &#160;).

While this default behavior guarantees well-formed XML or HTML, certain output requirements require explicit control over character representation. The use-character-maps attribute solves this by defining a pipeline transformation during serialization:

  1. Explicit Substitution: It replaces specific input characters with a custom string literal.
  2. Escaping Bypass: The replacement string is written directly to the output stream without secondary escaping.

Syntax and Structure

The attribute accepts a whitespace-separated list of QNames representing <xsl:character-map> elements defined at the stylesheet's top level.

<xsl:stylesheet version="2.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

  <!-- Define the character mapping rules -->
  <xsl:character-map name="custom-entities">
    <xsl:output-character character="&#160;" string="&amp;nbsp;" />
    <xsl:output-character character="©" string="&amp;copy;" />
  </xsl:character-map>

  <!-- Apply the map during output serialization -->
  <xsl:output method="html" use-character-maps="custom-entities" />

  <xsl:template match="/">
    <!-- Processing logic -->
  </xsl:template>

</xsl:stylesheet>

In this example, every non-breaking space (&#160;) produced in the result tree is emitted as the named HTML entity &nbsp;, rather than a numeric reference or raw byte sequence.

Common Use Cases

1. Generating Named Entities

Modern XML tools generally resolve entities to Unicode characters. When outputting to systems or legacy browsers that expect named entities (such as &nbsp;, &mdash;, or &copy;), use-character-maps ensures these strings appear literally in the output without being double-escaped to &amp;nbsp;.

2. Emitting Non-Standard Syntax or Template Placeholders

When using XSLT to generate non-XML formats (such as code templates, ASP, JSP, or custom templating engines with delimiters like {{ or <%), standard escaping can corrupt syntax. Character maps allow you to map unused Unicode characters to control delimiters without generating invalid XML during transformation.

3. Producing Legacy DTD-Dependent Formats

If an external consumer expects proprietary character entities defined in a custom DTD, character maps allow exact mapping between Unicode source data and the consumer's proprietary entity syntax.

Advantages Over disable-output-escaping

In XSLT 1.0, developers relied on disable-output-escaping="yes" on <xsl:value-of> or <xsl:text>. However, disable-output-escaping has major drawbacks:

  • It is optional for XSLT processors to support.
  • It does not work when transforming to a DOM or writing to intermediate result tree fragments.
  • It scatters escaping logic throughout templates.

The use-character-maps attribute operates strictly during the serialization phase, keeping stylesheet logic clean and portable while maintaining standard conformance across compliant XSLT processors.
