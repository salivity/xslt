static-base-uri vs base-uri in XSLT

In XSLT, static-base-uri() and base-uri() both resolve base Uniform Resource Identifiers (URIs), but they differ fundamentally in what they reference and when they are evaluated. The static-base-uri() function retrieves the URI of the stylesheet module itself at compile time, whereas the base-uri() function dynamically determines the base URI of a specific XML node being processed at runtime. Understanding this distinction is essential when resolving external resources, such as relative documents, schemas, or secondary input files.

What is static-base-uri()?

The static-base-uri() function takes no arguments and is part of the static context of the XSLT processor. It returns the base URI of the stylesheet element or module where the function call textually resides.

  • Compile-time context: It is fixed during the static analysis phase and does not depend on the input XML data.
  • Modular awareness: If a stylesheet uses xsl:include or xsl:import, a call to static-base-uri() inside an included module returns the URI of that specific module file, not the master stylesheet.
  • Primary use case: Use static-base-uri() when loading assets located relative to your XSLT files, such as stylesheet-specific lookup tables, localization files, or configuration assets using resolve-uri().

What is base-uri()?

The base-uri() function operates in the dynamic context and accepts either zero or one argument (which must be a node). If no argument is provided, it defaults to the context item.

  • Runtime node context: It returns the base URI of the target node, which is derived from the source XML document's actual location.
  • Influenced by markup: The result accounts for runtime mechanisms such as xml:base attributes defined within the source document hierarchy or external entity boundaries.
  • Dynamic dependency: If the context node changes as templates are applied, the returned base URI changes accordingly. If called on a node that has no base URI (such as a newly constructed disconnected element without a document node), it may return an empty sequence.
  • Primary use case: Use base-uri() when resolving paths relative to the input XML document, such as linked images, external data references, or related XML documents specified inside the source data.

Key Differences at a Glance

  • Target Reference: static-base-uri() points to the XSLT code's location on the filesystem or server. base-uri() points to the source XML data's location.
  • Arguments: static-base-uri() accepts zero arguments. base-uri() accepts zero or one node argument.
  • Context Type: static-base-uri() uses the static context (known before execution). base-uri() uses the dynamic context (evaluated during execution).
  • Impact of xml:base: static-base-uri() ignores xml:base attributes present in source data documents, while base-uri() actively evaluates them.
