XSLT 3.0 Accumulator Phase Start vs End Explained

In XSLT 3.0, accumulators provide a stateful mechanism to capture and carry values across nodes without altering purely functional transformations. The phase attribute on an xsl:accumulator-rule distinguishes whether an accumulator updates its value before processing a node's children or after completing their traversal. By selecting between phase="start" and phase="end", developers gain precise control over whether an update reflects pre-order (entry) or post-order (exit) events in the document hierarchy.

The Traversal Lifecycle: Start vs. End

XSLT processors traverse document trees conceptually or physically in depth-first, document order. During this walk, every element node has two distinct interception points:

  1. Start Phase (phase="start"): Occurs the moment the processor visits the node, before any of its child elements, attributes, or descendant nodes are processed.
  2. End Phase (phase="end"): Occurs when the processor has finished visiting all descendants of the node and is about to exit that subtree.

For leaf nodes (such as text nodes, attributes, comments, and processing instructions), both phases happen in immediate succession because leaves have no child nodes. For elements, however, phase="start" and phase="end" can be separated by arbitrary amounts of content and processing steps.

When to Use phase="start"

The phase="start" rule is the default when the phase attribute is omitted. It is applied during the entry phase of a node and is suited for:

  • Context Stacking: Pushing information onto a list or tracking ancestor hierarchy (e.g., recording the current depth or active section path).
  • Sequential Counters: Counting elements as they appear in document order before evaluating their inner contents.
  • Top-Down State Inheritance: Carrying configurations or inherited flags from parent elements downward into child processing.
<xsl:accumulator-rule match="section" 
                      phase="start" 
                      select="$value + 1"/>

When to Use phase="end"

The phase="end" rule is executed during the exit phase of a node. It is suited for:

  • Context Unwinding: Popping items off a simulated stack or resetting flags when leaving a scope.
  • Aggregations: Finalizing totals or summaries that require processing all child nodes before arriving at a final state for that element.
  • Balanced Checks: Ensuring opened markers or tags have balanced closing states.
<xsl:accumulator-rule match="section" 
                      phase="end" 
                      select="$value - 1"/>

Interaction with accumulator-before() and accumulator-after()

The choice of phase directly impacts the values retrieved by the standard accessor functions:

  • accumulator-before() returns the value of the accumulator immediately before the current node is visited. It reflects all updates up to, but excluding, the current node's phase="start" rule.
  • accumulator-after() returns the value of the accumulator after the current node and all its descendants have been visited. It reflects the outcome of the current node's phase="end" rule.

Within a streaming transformation, the distinction is strictly operational. Because a streaming processor encounters opening XML tags (phase="start") and closing XML tags (phase="end") as separate events, explicit phase rules allow accumulators to maintain accurate state without buffering the document tree into memory.
