Compute MD5 and SHA-256 Digests in XSLT

This article outlines how to generate cryptographic digests such as MD5 and SHA-256 during XSLT transformations. Because the core W3C XSLT specifications do not provide native cryptographic hashing functions, developers must rely on extension mechanisms. These include the legacy EXSLT Crypto library, the modern EXPath Crypto module, and processor-specific extensions like Saxon's Java bindings or .NET's embedded scripts.

1. The Legacy EXSLT Crypto Extension

The Community-defined EXSLT standard includes a crypto module targeting common algorithms. It is natively supported by tools built on libxslt (such as xsltproc).

To compute digests, declare the EXSLT crypto namespace:

<xsl:stylesheet version="1.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:crypto="http://exslt.org/crypto"
    extension-element-prefixes="crypto">

    <xsl:template match="input">
        <hash>
            <!-- Compute MD5 -->
            <xsl:value-of select="crypto:md5(string(.))" />
            
            <!-- Compute SHA1 (EXSLT typically supports SHA1, but lacks SHA-256) -->
            <xsl:value-of select="crypto:sha1(string(.))" />
        </hash>
    </xsl:template>
</xsl:stylesheet>

Limitation: The standard EXSLT specification was designed primarily around MD5 and SHA-1. In most implementations (including libxslt), it lacks support for modern algorithms like SHA-256.

2. The EXPath Crypto Module (XSLT 2.0 / 3.0)

The EXPath project provides a modern set of extensions compatible with advanced XSLT processors (such as Saxon-PE/EE with community packages, or native integration in XML databases like eXist-db).

The module uses the http://expath.org/ns/crypto namespace and provides a generalized crypto:hash() function:

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:crypto="http://expath.org/ns/crypto"
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <xsl:template match="data">
        <output>
            <!-- MD5 Hash -->
            <md5>
                <xsl:value-of select="crypto:hash(string(.), 'MD5', 'hex')" />
            </md5>
            
            <!-- SHA-256 Hash -->
            <sha256>
                <xsl:value-of select="crypto:hash(string(.), 'SHA-256', 'hex')" />
            </sha256>
        </output>
    </xsl:template>
</xsl:stylesheet>

The third parameter defines the output encoding, typically set to 'hex' or 'base64'.

3. Saxon Java Extension Functions

In Saxon (PE or EE editions), you can invoke the underlying Java java.security.MessageDigest directly via reflexive extension calls. This is the most common and robust approach for XSLT 2.0 and 3.0 workflows requiring SHA-256.

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:xs="http://www.w3.org/2001/XMLSchema"
    xmlns:md="java:java.security.MessageDigest"
    xmlns:str="java:java.lang.String"
    xmlns:local="urn:local"
    exclude-result-prefixes="#all">

    <!-- Helper function to generate SHA-256 in hex -->
    <xsl:function name="local:sha256" as="xs:string">
        <xsl:param name="input" as="xs:string" />
        
        <xsl:variable name="digest" select="md:getInstance('SHA-256')" />
        <xsl:variable name="bytes" select="str:getBytes($input, 'UTF-8')" />
        <xsl:variable name="hashedBytes" select="md:digest($digest, $bytes)" />
        
        <!-- Convert raw bytes to a lowercase hex string -->
        <xsl:sequence select="string-join(for $b in $hashedBytes return lower-case(substring(xs:string(xs:hexBinary($b)), 1, 2)), '')" />
    </xsl:function>

    <xsl:template match="text-to-hash">
        <digest>
            <xsl:value-of select="local:sha256(.)" />
        </digest>
    </xsl:template>
</xsl:stylesheet>

4. .NET Extension Scripts (System.Xml.Xsl)

If processing XML within the Microsoft .NET ecosystem using XslCompiledTransform, you can embed C# using msxsl:script to access System.Security.Cryptography.

<xsl:stylesheet version="1.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:msxsl="urn:schemas-microsoft-com:xslt"
    xmlns:user="urn:my-scripts"
    exclude-result-prefixes="msxsl user">

    <msxsl:script language="C#" implements-prefix="user">
        <![CDATA[
        public string Sha256(string input) {
            using (var sha = System.Security.Cryptography.SHA256.Create()) {
                byte[] bytes = System.Text.Encoding.UTF8.GetBytes(input);
                byte[] hash = sha.ComputeHash(bytes);
                return System.BitConverter.ToString(hash).Replace("-", "").ToLower();
            }
        }
        ]]>
    </msxsl:script>

    <xsl:template match="value">
        <hash>
            <xsl:value-of select="user:Sha256(string(.))" />
        </hash>
    </xsl:template>
</xsl:stylesheet>

Summary of Processor Recommendations

  • libxslt / xsltproc: Limited to crypto:md5() and crypto:sha1() via EXSLT.
  • Saxon-PE / EE: Utilize direct Java extension functions or the EXPath Crypto module for full support of modern digests like SHA-256 and SHA-512.
  • .NET XslCompiledTransform: Use msxsl:script with C# to call System.Security.Cryptography.
