Automate XSLT with Apache Ant and Maven Builds

Integrating Extensible Stylesheet Language Transformations (XSLT) into Apache Ant and Apache Maven automates the processing of XML data directly within your continuous integration and deployment pipelines. By embedding transformation tasks into build scripts, teams can generate source code, documentation, reports, and configuration files consistently without manual intervention. This article explains how XSLT works natively within Apache Ant using the built-in transformation task and how it integrates into Apache Maven using dedicated transformation plugins.

Integrating XSLT with Apache Ant

Apache Ant provides native support for XSLT processing through its built-in <xslt> task (also known historically as <style>). This task allows you to apply an XSLT stylesheet to a single XML file or batch-process an entire directory of documents.

The <xslt> Task Configuration

The <xslt> task maps source XML files to destination output files using a defined stylesheet:

<project name="XSLT-Example" default="transform">
    <target name="transform">
        <xslt basedir="src/xml" 
              destdir="target/output" 
              style="src/xsl/stylesheet.xsl" 
              extension=".html">
            <include name="**/*.xml"/>
            <param name="environment" expression="production"/>
        </xslt>
    </target>
</project>

Key Features in Ant

  • Batch Processing: The basedir, destdir, and nested <include> or <exclude> patterns allow bulk processing of file sets while maintaining relative directory structures.
  • Parameter Passing: Dynamic parameters can be passed directly to the stylesheet at runtime using the <param> element.
  • Processor Selection: By default, Ant utilizes the Java runtime's built-in TrAX processor (Xalan). To use modern XSLT 2.0 or 3.0 features, define an alternative processor such as Saxon by specifying the classpath and setting processor="trax".

Integrating XSLT with Apache Maven

Unlike Ant, Maven does not have a native XML transformation task built into its core engine. Instead, it relies on ecosystem plugins, primarily the xml-maven-plugin hosted by MojoHaus, to hook transformations into standard build lifecycle phases.

Configuring the xml-maven-plugin

The plugin binds transformation executions to phases like generate-resources, generate-sources, or process-classes:

<plugin>
    <groupId>org.codehaus.mojo</groupId>
    <artifactId>xml-maven-plugin</artifactId>
    <version>1.1.0</version>
    <executions>
        <execution>
            <phase>generate-resources</phase>
            <goals>
                <goal>transform</goal>
            </goals>
        </execution>
    </executions>
    <configuration>
        <transformationSets>
            <transformationSet>
                <dir>src/main/xml</dir>
                <stylesheet>src/main/xsl/transform.xsl</stylesheet>
                <outputDir>${project.build.directory}/generated-resources</outputDir>
                <parameters>
                    <parameter>
                        <name>buildVersion</name>
                        <value>${project.version}</value>
                    </parameter>
                </parameters>
            </transformationSet>
        </transformationSets>
    </configuration>
    <dependencies>
        <!-- Include Saxon for XSLT 2.0/3.0 support -->
        <dependency>
            <groupId>net.sf.saxon</groupId>
            <artifactId>Saxon-HE</artifactId>
            <version>12.4</version>
        </dependency>
    </dependencies>
</plugin>

Key Features in Maven

  • Lifecycle Binding: Transformations execute deterministically during phases such as generate-sources (for creating Java code from XML models) or pre-site (for documentation).
  • Dependency Management: Upgrading the underlying transformation engine requires adding a standard dependency block (e.g., Saxon-HE) directly within the plugin declaration.
  • Incremental Builds: The xml-maven-plugin tracks file modification timestamps to prevent redundant transformations if the source XML and XSLT templates have not changed.

Core Advantages in CI/CD Pipelines

Integrating transformations directly into Ant or Maven standardizes data processing across development environments and CI/CD agents. It eliminates reliance on local desktop tools, guarantees that output formats always match the latest schema definitions, and enables automated validation of structured documents during standard testing phases.
