Role of NaN and INF in XSLT Numeric Computations

In XSLT, NaN (Not a Number) and INF (Infinity) are special numeric values derived from the IEEE 754 floating-point standard that represent undefined or out-of-bounds mathematical operations. Rather than terminating a transformation with a fatal runtime error, XSLT relies on NaN and INF to maintain pipeline stability during unexpected numeric scenarios, such as division by zero or parsing non-numeric strings. Understanding how these values are generated, how they propagate through mathematical expressions, and how to detect them is essential for writing robust XSLT stylesheets.

Origins of NaN and INF in XSLT

XSLT leverages the XPath data model, where floating-point numbers (xs:double and xs:float) conform to the IEEE 754 specification.

  • NaN is produced when a mathematical operation yields an undefined or unrepresentable result. Common causes include:

    • Dividing zero by zero: 0 div 0
    • Performing arithmetic with NaN: 5 + number('invalid')
    • Explicitly casting an invalid string to a numeric type: number('foo')
    • Calculating the square root or logarithm of a negative number in XPath functions.

  • INF and -INF represent positive and negative infinity, produced when an operation overflows the standard floating-point limits. Common causes include:

    • Dividing a positive number by zero: 10 div 0 (results in INF)
    • Dividing a negative number by zero: -10 div 0 (results in -INF)
    • Exceeding the maximum representable double value through multiplication or exponentiation.

Behavior in Computations and Comparisons

Both values follow strict mathematical rules that determine how calculations proceed:

  1. Propagation: If NaN is used as an operand in any standard arithmetic operation (+, -, *, div, mod), the result is always NaN. INF combined with finite numbers typically yields INF, while INF - INF or INF div INF yields NaN.
  2. Equality and Comparison Rules:
    • NaN is never equal to anything, including itself. The expression number('NaN') = number('NaN') evaluates to false. Any relational comparison (<, >, <=, >=) involving NaN also evaluates to false.
    • INF can be compared directly. Positive infinity is greater than any finite number, while negative infinity is less than any finite number. The expression (10 div 0) = (20 div 0) evaluates to true because both sides yield INF.

Role in Fault Tolerance

The primary role of NaN and INF is to provide graceful degradation. In large XML documents with inconsistent data quality, a single missing or corrupt numeric field could easily cause processing failures.

By evaluating corrupt fields to NaN instead of raising an unrecoverable exception, XSLT allows processing to continue. However, this safety comes with the trade-off of silent failures: because NaN propagates through calculations, an unhandled NaN at the beginning of a transformation can corrupt downstream aggregate operations (such as sum()).

Detecting and Handling NaN and INF

Because NaN does not equal itself, standard equality checks require specific techniques depending on the XSLT version:

  • In XSLT 1.0:

    • Checking for NaN using self-inequality: test="$value != $value" (evaluates to true only if $value is NaN).
    • Checking for NaN using string conversion: test="string($value) = 'NaN'".
    • Checking for INF: test="string($value) = 'Infinity' or string($value) = '-Infinity'".

  • In XSLT 2.0 and later:

    • Use string casting or built-in schema types: test="string($value) = 'NaN'" or test="string($value) = ('INF', '-INF')".
    • Alternatively, validate inputs prior to calculation using the castable as xs:double operator to prevent NaN or INF from entering computation pipelines entirely.
