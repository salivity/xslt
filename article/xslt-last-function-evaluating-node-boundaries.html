XSLT last() Function: Evaluating Node Boundaries

In XSLT and XPath, the last() function returns the context size, representing the total number of nodes in the currently evaluated node-set. When working with node boundaries, last() serves as the primary mechanism for detecting the end of a sequence, enabling developers to identify terminal nodes, control conditional delimiters, and structure output documents correctly. This article explains how last() functions at node boundaries, its common practical applications, and the performance implications of using it.

Understanding the Role of last()

The last() function returns an integer equal to the number of items in the current context sequence. When combined with the position() function, it allows an XSLT processor to determine whether the node currently being processed is at the upper boundary of its set:

<xsl:if test="position() = last()">
    <!-- Actions applied only to the final node -->
</xsl:if>

While the lower boundary is always constant (position() = 1), the upper boundary is dynamic and varies depending on the size of the filtered or selected sequence.

Key Use Cases for Node Boundary Evaluation

1. Managing Punctuation and Delimiters

The most common application of last() is omitting trailing separators (such as commas, slashes, or line breaks) in serialized lists. By checking if the current position is less than last(), XSLT avoids fencepost errors:

<xsl:for-each select="item">
    <xsl:value-of select="."/>
    <xsl:if test="position() != last()">, </xsl:if>
</xsl:for-each>

2. Structural and Layout Termination

Document structures often require distinct markup for the final element in a section, such as closing wrapper elements, appending summary rows to a table, or attaching specific CSS classes for styling:

<xsl:template match="paragraph">
    <p>
        <xsl:if test="position() = last()">
            <xsl:attribute name="class">last-paragraph</xsl:attribute>
        </xsl:if>
        <xsl:apply-templates/>
    </p>
</xsl:template>

3. Contextual Scope Adjustments

The boundary returned by last() depends strictly on the current context established by predicates or selection axes. When used inside a predicate, last() re-evaluates to match the subset defined by that predicate:

<!-- Selects the last active user only -->
<xsl:apply-templates select="users/user[@status='active'][last()]"/>

Here, last() represents the final node of the filtered @status='active' node-set rather than the total count of all user elements.

Processing and Performance Considerations

Using last() prevents an XSLT processor from processing nodes in a purely streamed or pipelined fashion. To calculate the value of last(), the processor must evaluate the entire sequence to determine its complete size before executing expressions that depend on it.

In large documents or when processing streamed inputs (such as in XSLT 3.0), evaluating last() forces buffering of the entire node-set into memory, which can increase latency and memory consumption. When boundary evaluation on massive datasets is required, structural restructuring or alternative techniques—such as matching preceding or following siblings—may be used to maintain performance.
