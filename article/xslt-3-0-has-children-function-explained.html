XSLT 3.0 has-children Function Explained

The has-children() function in XSLT 3.0 and XPath 3.0 provides a native, efficient way to determine whether a context node or specified node contains any child nodes. Returning a simple boolean value (true or false), it simplifies node evaluation, improves stylesheet readability, and plays a crucial role in enabling streaming transformations where buffering entire node sets must be avoided.

Syntax and Basic Operation

The function belongs to the standard XPath and XSLT function namespace and can be invoked in two ways:

  • fn:has-children(): Evaluates the current context node.
  • fn:has-children($node as node()?): Evaluates the node passed as an argument.

If the evaluated node possesses at least one child node, the function returns true. If the node is empty, or if the argument is an empty sequence (()), it returns false.

What Counts as a Child Node

Under the XQuery and XPath Data Model (XDM), has-children() checks for any node residing on the child axis. This includes:

  • Element nodes
  • Text nodes (including whitespace text nodes)
  • Comment nodes
  • Processing instruction nodes

Attributes and namespace nodes are associated with elements via distinct axes, meaning an element that contains only attributes and no nested text or markup will cause has-children() to return false.

Improvement Over Legacy Approaches

Prior to XSLT 3.0, developers relied on expressions such as boolean(node()), exists(node()), or count(node()) > 0 to check for child content. While functional, these patterns had drawbacks:

  1. Performance: Expressions like node() construct a sequence of child nodes before converting that sequence to a boolean. While optimizing processors might stop at the first node, has-children() explicitly guarantees an existence check that terminates immediately upon finding the first child.
  2. Intent and Readability: The function makes the conditional test explicit in template matches and control structures, eliminating syntactic clutter.

Optimization for Streaming Transformations

The primary architectural driver for introducing has-children() in XSLT 3.0 is streaming. In a streaming environment, documents are read sequentially from a feed rather than loaded into an in-memory tree.

Standard constructs like child::node() can consume the stream or require lookahead buffering, which may violate streaming rules. The has-children() function is classified by the XSLT 3.0 specification as an inspection function that can often be evaluated without advancing the stream past the boundary of the current element, allowing developers to branch logic based on element structure without breaking streamability.

Practical Example

In practice, has-children() is typically used in xsl:if, xsl:choose, or pattern predicates:

<xsl:template match="section[has-children()]">
    <div class="content-section">
        <xsl:apply-templates/>
    </div>
</xsl:template>

<xsl:template match="section[not(has-children())]">
    <!-- Suppress or handle empty sections -->
</xsl:template>

By leveraging has-children(), XSLT 3.0 developers achieve cleaner code, better runtime performance, and strict compliance with streaming constraints.
