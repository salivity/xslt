Difference Between current() and . in XSLT

In XSLT, both the . (dot) syntax and the current() function are used to reference nodes during transformation, but they resolve to different nodes depending on the evaluation scope. The . operator refers to the context item of the active XPath expression, which dynamically changes inside predicates and path steps. In contrast, the current() function consistently returns the current node processed by the enclosing XSLT instruction (such as <xsl:template> or <xsl:for-each>), remaining unaffected by inner XPath shifts.

Understanding the Context Item (.)

The dot (.) is a native XPath expression that represents the immediate context item. As an XPath expression is evaluated, the meaning of . changes dynamically based on the current step or filter.

When evaluating a predicate expression enclosed in square brackets ([...]), the context shifts to the specific node being evaluated against that predicate:

<xsl:value-of select="books/book[title = .]" />

In the example above, within the predicate [title = .], the . represents each individual <book> element being tested, not the parent element containing the books list.

Understanding the current() Function

The current() function is an XSLT-specific function rather than a standard core XPath feature. It acts as an anchor to the outer XSLT execution context. Regardless of how deeply nested inside an XPath expression or predicate you are, current() always refers to the node that was selected by the innermost enclosing XSLT instruction (xsl:template, xsl:for-each, etc.).

The Critical Difference: Inside Predicates

The distinction between . and current() becomes apparent when filtering nodes using predicates.

Consider an XML document where you need to match elements across different parts of the document based on an attribute:

<xsl:template match="order">
  <!-- We want items whose category matches the order's category -->
  <xsl:apply-templates select="//catalog/item[@category = current()/@category]" />
</xsl:template>

In this scenario:

  • current()/@category retrieves the @category attribute of the <order> element matched by the template.
  • If you used . instead—select="//catalog/item[@category = ./@category]"—the . would refer to the <item> element being evaluated inside the predicate, effectively comparing the item's category to itself.

Summary of Differences

  • Scope of Resolution: . changes with every path step and predicate inside an XPath expression. current() only changes when entering a new XSLT instruction like <xsl:for-each> or <xsl:template>.
  • Standard vs. Extension: . is part of the standard W3C XPath specification and can be used anywhere XPath is supported. current() is defined within the XSLT specification and requires an XSLT processor.
  • Equivalence Outside Predicates: Outside of predicates and inner path steps, . and current() refer to the exact same node.
