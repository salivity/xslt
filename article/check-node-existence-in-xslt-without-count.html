Check Node Existence in XSLT Without Count

Testing for node existence using count($nodes) > 0 is an anti-pattern in XSLT that often causes severe performance degradation on large documents because the processor must traverse the entire node-set to compute the total. This article covers high-performance alternatives that leverage boolean short-circuiting to check for a node's presence, stopping evaluation immediately after finding the first match.

Implicit Boolean Evaluation

The most straightforward and widely supported alternative is to evaluate the node-set directly within a conditional statement without any wrapper functions. In XPath, a node-set evaluated in an effective boolean context evaluates to true if it contains at least one node and false if it is empty.

Instead of writing:

<xsl:if test="count(items/item) > 0">
    <!-- Processing -->
</xsl:if>

Use implicit conversion:

<xsl:if test="items/item">
    <!-- Processing -->
</xsl:if>

Because the processor only needs to determine whether the sequence is non-empty, it can stop evaluation as soon as the first matching node is discovered, avoiding a full scan of the document tree.

The boolean() Function

When passing values to parameters, evaluating complex logic, or storing results in variables where a strict boolean type is required, use the boolean() function.

<xsl:variable name="hasItems" select="boolean(items/item)" />

Like implicit casting, boolean() short-circuits upon detecting the first node. It returns true() immediately rather than counting subsequent nodes.

Positional Predicates: [1]

Another alternative compatible with XSLT 1.0 is targeting only the first node using a positional predicate. This ensures the processor does not need to look beyond the initial match.

<xsl:if test="items/item[1]">
    <!-- Processing -->
</xsl:if>

This is functionally equivalent to checking the node-set directly, but it can be useful in complex path expressions or combined predicates to explicitly signal to the query planner that only the first item matters.

The exists() Function (XSLT 2.0+)

For modern transformations using XSLT 2.0, 3.0, or XPath 2.0+, the standard library provides the exists() function.

<xsl:if test="exists(items/item)">
    <!-- Processing -->
</xsl:if>

exists() returns true if the sequence contains at least one item, regardless of item type (nodes, atomic values, or maps). It is optimized by modern engines like Saxon to abort iteration on the first item, providing both optimal performance and clear semantic intent. Its counterpart, empty(), should be used instead of count($nodes) = 0 to check for node absence.
