XSLT 3.0 default-mode Attribute Explained

The default-mode attribute in XSLT 3.0 simplifies mode assignment by allowing developers to set a stylesheet-wide default processing mode directly on the <xsl:stylesheet> (or <xsl:transform>) element. Prior to XSLT 3.0, using modes required explicitly repeating the mode attribute on every single template rule and invocation instruction. By setting a default mode at the root level, XSLT 3.0 reduces code verbosity, minimizes accidental fallback to the unnamed mode, and enables clean, modular multi-pass transformations.

The Verbosity Problem in Earlier Versions

In XSLT 1.0 and 2.0, any template or instruction meant to operate within a specific mode required an explicit declaration:

<xsl:template match="chapter" mode="toc">
    <!-- processing -->
    <xsl:apply-templates select="section" mode="toc"/>
</xsl:template>

Omitting mode="toc" on an <xsl:apply-templates> instruction caused the engine to revert to the unnamed default mode. This was a frequent source of logic bugs in multi-phase pipelines where processing inadvertently dropped out of the intended phase.

How default-mode Changes Mode Assignment

The default-mode attribute establishes which mode applies implicitly to elements inside the stylesheet module that accept a mode attribute.

<xsl:stylesheet version="3.0" 
                xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
                default-mode="toc">

    <!-- Implicitly in "toc" mode -->
    <xsl:template match="chapter">
        <!-- Implicitly applies templates in "toc" mode -->
        <xsl:apply-templates select="section"/>
    </xsl:template>

</xsl:stylesheet>

When default-mode is declared:

  • <xsl:template> elements without a mode attribute automatically belong to the specified default mode instead of the unnamed #default mode.
  • <xsl:apply-templates> instructions without a mode attribute automatically invoke templates in that specified default mode.
  • <xsl:apply-imports> and <xsl:next-match> behave according to the context of the default mode if not overridden.

Key Advantages in Practice

1. Cleaner Multi-Pass Architectures

Complex transformations often process XML documents in stages (such as cleanup, enrichment, and formatting). Developers commonly separate these stages into individual stylesheet modules. By assigning a distinct default-mode to each file (for example, default-mode="cleanup" in clean.xsl), an entire module can be scoped to a single pipeline stage without repetitive boilerplate.

2. Elimination of Silent Fallback Bugs

In older XSLT versions, forgetting a mode attribute on an inner <xsl:apply-templates> meant the processor fell back to the root unnamed mode, often producing empty or malformed output without throwing a syntax error. With default-mode, child instructions automatically stay within the established workflow.

3. Granular Overrides Remain Available

Using default-mode does not lock the entire stylesheet into a single mode. Individual templates or calls can still override the default by explicitly supplying a mode attribute:

  • Specify another named mode: mode="alternate"
  • Target the standard unnamed mode: mode="#unnamed"
  • Match across any mode: mode="#all"

This balance allows developers to set the predominant operational context for a module while retaining complete control where exceptions are necessary.
