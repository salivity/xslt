Pair CSV Headers and Rows Using XSLT 3.0

Processing delimited text files like CSV directly into structured XML or JSON has become significantly easier with XSLT 3.0. By leveraging native XPath 3.1 text functions such as unparsed-text() and tokenize(), alongside dynamic element generation, developers can parse raw CSV strings, extract header titles, and programmatically bind each row's values to their respective header keys without relying on third-party parsers or extensions.

Reading and Splitting the CSV Data

The transformation begins by reading the raw CSV data using unparsed-text() or passing the raw text into a stylesheet parameter. Once loaded, the text is split into an array of individual lines using tokenize() with a regular expression that handles common line-break variants (\r?\n).

<xsl:variable name="csv-text" select="unparsed-text('data.csv')"/>
<xsl:variable name="lines" select="tokenize($csv-text, '\r?\n')[normalize-space()]"/>

Filtering out empty lines with [normalize-space()] ensures that trailing newlines do not generate phantom nodes during processing.

Sanitizing and Storing Dynamic Headers

The first item in the sequence represents the column headers. Because CSV headers often contain spaces, punctuation, or start with digits—characteristics invalid for XML tag names—they should be sanitized using replace() before being mapped to element names.

<xsl:variable name="headers" as="xs:string*">
    <xsl:for-each select="tokenize($lines[1], ',')">
        <!-- Remove quotes and replace invalid characters with underscores -->
        <xsl:sequence select="replace(replace(., '^&quot;|&quot;$', ''), '[^a-zA-Z0-9_\-\.]', '_')"/>
    </xsl:for-each>
</xsl:variable>

Dynamically Pairing Headers with Row Values

With the headers captured in an indexed sequence, iterate over the subsequent lines (the data rows) starting at index 2. For each row, tokenize the line into columns and use positional indexing to pair the column value with the corresponding header name.

<xsl:template match="/">
    <root>
        <xsl:for-each select="tail($lines)">
            <row>
                <xsl:variable name="columns" select="tokenize(., ',')"/>
                <xsl:for-each select="$columns">
                    <xsl:variable name="pos" select="position()"/>
                    <xsl:variable name="header-name" select="$headers[$pos]"/>
                    
                    <xsl:if test="$header-name">
                        <xsl:element name="{$header-name}">
                            <xsl:value-of select="replace(., '^&quot;|&quot;$', '')"/>
                        </xsl:element>
                    </xsl:if>
                </xsl:for-each>
            </row>
        </xsl:for-each>
    </root>
</xsl:template>

Alternative JSON/Map Pairing Using XPath 3.1 Maps

If targeting JSON output instead of XML, XSLT 3.0 allows the direct creation of XPath 3.1 maps without worrying about XML naming restrictions.

<xsl:for-each select="tail($lines)">
    <xsl:variable name="columns" select="tokenize(., ',')"/>
    <xsl:variable name="row-map" select="
        map:merge(
            for $i in 1 to count($headers)
            return map { $headers[$i]: $columns[$i] }
        )
    "/>
</xsl:for-each>

Considerations for Complex CSV Structures

While regular expression tokenization is fast and effective for straightforward CSV structures, values containing escaped commas or embedded line breaks within quotation marks require more specialized handling. In these scenarios, replace basic tokenize() logic with xsl:analyze-string to parse quotes and field delimiters according to the RFC 4180 standard while maintaining the dynamic header-to-column pairing architecture.
