How to Convert DocBook and TEI XML to Markdown Using XSLT

Converting XML-based documentation formats like DocBook and TEI (Text Encoding Initiative) to Markdown allows organizations to migrate legacy, heavily structured documentation into modern, Git-friendly static site generators and lightweight publishing platforms. By configuring an XSLT (Extensible Stylesheet Language Transformations) stylesheet to output plain text and defining templates that map XML structural and semantic elements to Markdown syntax, you can build an automated, repeatable conversion pipeline.

Setting Up the XSLT Output Method

Markdown files are plain text with minimal formatting characters. Therefore, the XSLT stylesheet must declare its output method as text rather than xml or html. This configuration prevents the transformation engine from generating XML declarations, escaping characters like < and &, or wrapping the final document in XML tags.

<xsl:stylesheet version="2.0" 
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:db="http://docbook.org/ns/docbook"
    xmlns:tei="http://www.tei-c.org/ns/1.0"
    exclude-result-prefixes="db tei">

    <xsl:output method="text" encoding="UTF-8" indent="no"/>
    <xsl:strip-space elements="*"/>

Using XSLT 2.0 or 3.0 is recommended because functions like string-join() and advanced regular expression support simplify the handling of complex text spacing and list nesting.

Mapping Structural Headers

Both DocBook and TEI use hierarchical wrappers for content sections. In DocBook, titles are encapsulated within <section> or <chapter> elements, while TEI uses nested <div> tags containing <head> elements.

To generate the correct Markdown heading level (#, ##, ###), calculate the depth of the current section element in the XML tree using the count() function:

<!-- DocBook Sections -->
<xsl:template match="db:section/db:title">
    <xsl:variable name="level" select="count(ancestor::db:section)"/>
    <xsl:value-of select="string-join((for $i in 1 to $level return '#'), '')"/>
    <xsl:text> </xsl:text>
    <xsl:apply-templates/>
    <xsl:text>&#10;&#10;</xsl:text>
</xsl:template>

<!-- TEI Headings -->
<xsl:template match="tei:div/tei:head">
    <xsl:variable name="level" select="count(ancestor::tei:div)"/>
    <xsl:value-of select="string-join((for $i in 1 to $level return '#'), '')"/>
    <xsl:text> </xsl:text>
    <xsl:apply-templates/>
    <xsl:text>&#10;&#10;</xsl:text>
</xsl:template>

The character entity &#10; inserts a newline character, ensuring the required vertical whitespace around Markdown blocks.

Mapping Inline Formatting and Paragraphs

DocBook <para> and TEI <p> elements represent standard text blocks, requiring two trailing line breaks to form valid Markdown paragraphs. Inline elements represent styles like bold, italic, and code spans.

<!-- Paragraphs -->
<xsl:template match="db:para | tei:p">
    <xsl:apply-templates/>
    <xsl:text>&#10;&#10;</xsl:text>
</xsl:template>

<!-- Bold / Strong -->
<xsl:template match="db:emphasis[@role='bold'] | tei:hi[@rend='bold']">
    <xsl:text>**</xsl:text>
    <xsl:apply-templates/>
    <xsl:text>**</xsl:text>
</xsl:template>

<!-- Italics -->
<xsl:template match="db:emphasis[not(@role)] | tei:hi[@rend='italic']">
    <xsl:text>*</xsl:text>
    <xsl:apply-templates/>
    <xsl:text>*</xsl:text>
</xsl:template>

<!-- Inline Code -->
<xsl:template match="db:code | tei:code">
    <xsl:text>`</xsl:text>
    <xsl:apply-templates/>
    <xsl:text>`</xsl:text>
</xsl:template>

Transforming Lists

Unordered lists in DocBook (<itemizedlist>) and TEI (<list type="unordered">) contain list items (<listitem> and <item>, respectively). Markdown requires an asterisk or hyphen followed by a space, with proper indentation for nested items.

<xsl:template match="db:listitem | tei:item">
    <!-- Indent based on nesting depth -->
    <xsl:variable name="depth" select="count(ancestor::db:itemizedlist | ancestor::tei:list) - 1"/>
    <xsl:value-of select="string-join((for $i in 1 to $depth return '  '), '')"/>
    <xsl:text>* </xsl:text>
    <xsl:apply-templates/>
    <xsl:text>&#10;</xsl:text>
</xsl:template>

<!-- Trailing newline after list completes -->
<xsl:template match="db:itemizedlist | tei:list">
    <xsl:apply-templates/>
    <xsl:text>&#10;</xsl:text>
</xsl:template>

Transforming Links and Media

Hyperlinks and images rely on attribute extraction. DocBook often uses <link xlink:href="..."> and <imagedata fileref="...">, while TEI uses <ref target="..."> and <graphic url="...">.

<!-- Hyperlinks -->
<xsl:template match="db:link">
    <xsl:text>[</xsl:text>
    <xsl:apply-templates/>
    <xsl:text>](</xsl:text>
    <xsl:value-of select="@xlink:href"/>
    <xsl:text>)</xsl:text>
</xsl:template>

<xsl:template match="tei:ref">
    <xsl:text>[</xsl:text>
    <xsl:apply-templates/>
    <xsl:text>](</xsl:text>
    <xsl:value-of select="@target"/>
    <xsl:text>)</xsl:text>
</xsl:template>

<!-- Code Blocks -->
<xsl:template match="db:programlisting | tei:eg">
    <xsl:text>```&#10;</xsl:text>
    <xsl:value-of select="."/>
    <xsl:text>&#10;```&#10;&#10;</xsl:text>
</xsl:template>

Executing the Transformation

Once the XSLT stylesheet is assembled, execute the transformation using a command-line processor such as Saxon or xsltproc.

Using Saxon for XSLT 2.0/3.0:

java -jar saxon-he-12.jar -s:documentation.xml -xsl:convert.xsl -o:documentation.md

Using xsltproc for standard XSLT 1.0 templates:

xsltproc convert.xsl documentation.xml > documentation.md

This workflow translates complex XML semantics into readable, portable Markdown, enabling continuous integration pipelines to build modern documentation directly from historical XML sources.
