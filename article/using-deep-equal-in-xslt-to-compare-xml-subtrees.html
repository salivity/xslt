Using deep-equal in XSLT to Compare XML Subtrees

In XSLT, the fn:deep-equal() function provides a mechanism to determine whether two XML nodes, subtrees, or sequences are structurally and semantically identical. Unlike shallow comparison operators that inspect only string representations or memory references, deep-equal() recursively evaluates every component of two XML hierarchies, including element names, namespaces, attributes, and text contents. This article explains the exact purpose of deep-equal(), how it evaluates XML subtrees, and why it is indispensable for reliable XML data comparison.

The Purpose of deep-equal()

The primary purpose of deep-equal() (introduced in XPath 2.0 and XSLT 2.0) is to test whether two XML fragments are equivalent in structure, names, and content. When comparing complex XML subtrees, developers typically need to verify that both branches match completely.

Standard operators fall short of this requirement:

  • The Equality Operator (=): Compares only the string values of the elements. In XML, an element's string value is the concatenation of all its descendant text nodes. As a result, <item><id>1</id><qty>2</qty></item> and <item><id>12</id></item> would be evaluated as equal by the = operator, despite having entirely different element structures.
  • The Node Identity Operator (is): Evaluates whether two nodes are the exact same node instance in the document tree. Two identical subtrees residing in different parts of a document or in different documents will return false when evaluated with is.

deep-equal() solves these limitations by performing a thorough, recursive comparison of the underlying data structures.

What deep-equal() Compares

When comparing two element nodes, deep-equal($tree1, $tree2) returns true only if all of the following conditions are satisfied:

  1. Node Kind: Both nodes must be of the same kind (e.g., both elements, both documents).
  2. Node Names and Namespaces: The expanded QNames (namespace URI and local name) of the elements must match. Prefix differences are ignored as long as they resolve to the same namespace URI.
  3. Attributes: Both elements must have the same number of attributes, and each attribute on one element must match the name, namespace, and value of an attribute on the other. Attribute order is ignored.
  4. Child Nodes: The children of both elements must match in kind, value, and sequence order.
  5. Text Nodes and Comments: Contained text nodes must match in string value. (In standard XPath 2.0/3.0, comment and processing instruction nodes are ignored by default unless specified).
  6. Recursion: Every child element is evaluated using these same rules down to the leaf nodes of both subtrees.

Typical Implementation

The function takes two sequences (or single nodes) and an optional collation argument:

<xsl:if test="deep-equal($sourceSubtree, $targetSubtree)">
    <!-- Logic executed when both XML trees match completely -->
</xsl:if>

Common Use Cases

  • XML Diffing and Patching: Detecting whether an incoming record has changed compared to a previously stored XML record.
  • Deduplication: Filtering out duplicate nested structures across large datasets.
  • Automated Testing: Validating that an XSLT transformation generated the expected XML document structure by comparing the output against a baseline document.
