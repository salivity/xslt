How to Avoid Invalid Double Hyphens in XSLT Comments

Generating comments in XSLT using the <xsl:comment> instruction requires strict adherence to XML syntax standards, which strictly prohibit consecutive hyphens (--) and trailing hyphens immediately before the closing delimiter. This article explains the underlying XML and XSLT rules regarding comment content, how different processor versions handle violations, and methods for sanitizing dynamic text to ensure valid output.

The Core XML Comment Grammar

According to the W3C XML 1.0 Recommendation, the grammar for an XML comment is defined as:

Comment ::= '<!--' ((Char - '-') | ('-' (Char - '-')))* '-->'

This production rule imposes two absolute constraints on comment text:

  1. No double hyphens: The string -- must not occur anywhere inside the comment.
  2. No trailing hyphen: The comment cannot end with a hyphen (e.g., <!-- comment- --> would yield <!-- comment--->, which contains three consecutive hyphens and violates closing syntax).

Because XML parsers recognize --> as the definitive end of a comment, allowing -- inside the comment text could cause ambiguity or parser desynchronization.

XSLT Processor Behavior and Constraints

When using <xsl:comment> to dynamically construct comments, XSLT processors enforce these limitations during tree construction and serialization.

XSLT 1.0 Behavior

In XSLT 1.0, generating a comment containing -- or ending with a hyphen is an error. The specification allows the processor to choose one of two behaviors:

  • Signal an error: The transformation aborts immediately.
  • Recover automatically: The processor modifies the text to produce well-formed XML, typically by inserting a space between consecutive hyphens (converting -- to - -) or appending a space before the closing -->.

Because recovery is optional, stylesheets that rely on a processor to fix invalid hyphens are not portable.

XSLT 2.0 and 3.0 Serialization Rules

In XSLT 2.0 and later, creating a comment node containing -- in the data model may be permitted temporarily in memory, but a serialization error occurs when writing the node to an XML output stream.

Under the W3C XSLT and XQuery Serialization specification, encountering -- or a trailing - during serialization triggers serialization error [err:SEPM0009]. An XSLT 2.0+ processor will fail the transformation unless serialization parameters or processor extensions explicitly handle character replacement.

Common Causes of Invalid Comment Content

  • Decorative dividers: Developers often attempt to create visual separation inside comments using patterns like <!-- ==================== --> or <!-- -------------------- -->. The latter immediately violates the syntax rule.
  • Dynamic data injection: Passing unescaped text from source XML nodes (such as user-submitted text or system logs) directly into <xsl:comment> often introduces -- (such as em-dash approximations or command-line flags like --verbose).
  • Trailing punctuation: Text that legitimately ends with a hyphen (such as a hyphenated word or minus sign) creates an invalid comment if placed immediately before the closing tag.

Strategies to Prevent Malformed Comments

To prevent transformation failures and ensure cross-processor compatibility, any dynamic or generated text targeted for an <xsl:comment> must be sanitized.

1. In XSLT 2.0 and 3.0 (Using XPath 2.0 Functions)

You can use standard XPath string manipulation functions to break up consecutive hyphens and trim trailing hyphens before emitting the comment:

<xsl:variable name="cleanText" 
              select="replace(replace($rawText, '--+', '- -'), '-$', '- ')" />
<xsl:comment>
    <xsl:value-of select="$cleanText" />
</xsl:comment>

This pattern replaces sequences of multiple hyphens with spaced hyphens and ensures that any hyphen at the end of the string is followed by a space.

2. In XSLT 1.0 (Using Recursive Templates)

Because XSLT 1.0 lacks regular expressions, you must use a recursive named template to find and replace instances of --:

<xsl:template name="sanitize-comment">
    <xsl:param name="text"/>
    <xsl:choose>
        <xsl:when test="contains($text, '--')">
            <xsl:value-of select="substring-before($text, '--')"/>
            <xsl:text>- -</xsl:text>
            <xsl:call-template name="sanitize-comment">
                <xsl:with-param name="text" select="substring-after($text, '--')"/>
            </xsl:call-template>
        </xsl:when>
        <xsl:when test="substring($text, string-length($text)) = '-'">
            <xsl:value-of select="concat($text, ' ')"/>
        </xsl:when>
        <xsl:otherwise>
            <xsl:value-of select="$text"/>
        </xsl:otherwise>
    </xsl:choose>
</xsl:template>

Applying this template ensures that the resulting string satisfies XML grammar requirements across all compliant XSLT engines.
