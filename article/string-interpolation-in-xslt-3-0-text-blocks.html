String Interpolation in XSLT 3.0 Text Blocks

This article explains how string interpolation works in XSLT 3.0 text blocks through the Text Value Templates (TVT) feature. You will learn how the Value: {$var} syntax evaluates dynamic expressions directly inside element content and text nodes, how to activate this behavior using the expand-text attribute, and how to properly escape literal curly braces in your stylesheets.

Understanding Text Value Templates (TVT)

In XSLT 3.0, string interpolation inside text blocks is formally known as a Text Value Template (TVT). Prior to XSLT 3.0, curly brace interpolation—{expression}—was exclusively available inside attribute values (Attribute Value Templates, or AVTs). Inserting variable values or XPath evaluations into text content previously required verbose <xsl:value-of select="$var"/> elements.

With TVT enabled, any expression enclosed within single curly braces {...} located inside a text node or literal result element is treated as an XPath 3.0 expression, evaluated at runtime, and cast to a string.

Enabling String Interpolation with expand-text

String interpolation in text blocks is not active by default to maintain backward compatibility with older XSLT versions. To enable it, you must use the expand-text attribute set to yes.

The expand-text attribute can be defined at multiple scopes:

  • Stylesheet level: Set expand-text="yes" on the <xsl:stylesheet> or <xsl:transform> root element to enable interpolation globally across the entire document.
  • Template level: Place expand-text="yes" on individual <xsl:template> elements.
  • Element level: Place xsl:expand-text="yes" on a specific literal result element or an instruction like <xsl:text expand-text="yes">.

Because expand-text is inherited by child nodes, configuring it higher in the hierarchy applies it downward unless explicitly overridden with expand-text="no".

Syntax and Practical Example

When expand-text="yes" is in scope, any embedded variable or XPath expression evaluates inline:

<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
                version="3.0"
                expand-text="yes">

    <xsl:variable name="var" select="'Active'" />

    <xsl:template match="/">
        <!-- Interpolation in a literal result element -->
        <status>Value: {$var}</status>

        <!-- Interpolation inside an xsl:text instruction -->
        <xsl:text>The current state is: {$var}</xsl:text>
    </xsl:template>

</xsl:stylesheet>

Output:

<status>Value: Active</status>
The current state is: Active

If the expression inside {} evaluates to a sequence of items, XSLT 3.0 atomizes the sequence and separates each value with a single space by default.

Escaping Curly Braces

When using expand-text="yes", literal curly braces must be escaped by doubling them, mirroring the syntax used in Attribute Value Templates:

  • {{ produces a literal {
  • }} produces a literal }

For example:

<code expand-text="yes">function() {{ return 'Value: {$var}'; }}</code>

If $var holds the value 100, this snippet outputs:

function() { return 'Value: 100'; }
