How to Pass Parameters to XSLT from the Command Line

Passing command-line parameters to an XSLT processor enables you to create dynamic, reusable stylesheets that adapt their output based on external runtime inputs. This article covers how to define receiving parameters inside your XSLT file and provides the exact syntax required to pass values using the most popular command-line processors: xsltproc, Saxon, and MSXSL.

1. Declare the Parameter in Your XSLT Stylesheet

Before a processor can accept an external value, the stylesheet must declare the parameter using the top-level <xsl:param> element. It must be a direct child of <xsl:stylesheet> or <xsl:transform>.

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

    <!-- Declare the parameter with an optional default value -->
    <xsl:param name="environment" select="'development'" />

    <xsl:template match="/">
        <html>
            <body>
                <p>Current Environment: <xsl:value-of select="$environment" /></p>
            </body>
        </html>
    </xsl:template>

</xsl:stylesheet>

2. Passing Parameters with xsltproc

The xsltproc utility (part of libxslt) is standard on macOS and most Linux distributions. It differentiates between raw XPath expressions and literal strings.

Passing a String Parameter

Use --stringparam when passing plain text to avoid manual quote escaping:

xsltproc --stringparam environment "production" transform.xsl input.xml

Passing an XPath Expression

Use --param if you are passing an XPath expression, numbers, or boolean values. If passing a string via --param, the value must be wrapped in nested quotes:

# Passing a string using --param (requires nested quotes)
xsltproc --param environment "'production'" transform.xsl input.xml

# Passing a number or XPath expression
xsltproc --param maxItems 10 transform.xsl input.xml

3. Passing Parameters with Saxon

Saxon is the standard processor for modern XSLT (versions 2.0 and 3.0). With Saxon, parameters are passed as name=value pairs placed at the very end of the command.

Standard Syntax

java -jar saxon-he.jar -s:input.xml -xsl:transform.xsl environment="production"

Type Handling in Saxon

  • Literal Strings / Untyped: name=value passes the parameter as an untyped atomic value or string.
  • XPath Expressions: Prefix the parameter name with ? to evaluate the value as an XPath 2.0/3.0 expression: 
    java -jar saxon-he.jar -s:input.xml -xsl:transform.xsl ?maxItems="5 + 5"
  • XML Node/Document: Prefix with + to have the processor parse the string as an XML file name and pass the resulting document node: 
    java -jar saxon-he.jar -s:input.xml -xsl:transform.xsl +config="settings.xml"

4. Passing Parameters with MSXSL

For Windows environments using Microsoft's command-line tool msxsl.exe, parameters are also passed at the end of the command invocation.

msxsl.exe input.xml transform.xsl -o output.html environment="production"

To pass an XPath expression instead of a string literal, wrap the expression within single quotes inside double quotes:

msxsl.exe input.xml transform.xsl -o output.html environment="'production'"

Key Best Practices

  • Always Set Default Values: Define a fallback inside <xsl:param name="..." select="'default'"/> so the stylesheet runs properly even if the command-line argument is omitted.
  • Mind Shell Escaping: When passing strings that contain spaces or special characters, wrap them carefully in quotes according to your shell’s rules (e.g., Bash, Zsh, or Windows PowerShell/CMD).
