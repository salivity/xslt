Using xsl:original in XSLT 3.0 Package Refinement

This article explains the role and mechanics of the xsl:original instruction in XSLT 3.0, focusing specifically on how it enables template refinement within modular stylesheet architectures. By reading this guide, you will learn how xsl:original acts as a delegation mechanism—similar to the super keyword in object-oriented programming—allowing an overriding package to invoke the original implementation of a named template, pass parameters, and extend base functionality without code duplication.

Understanding Package Refinement in XSLT 3.0

XSLT 3.0 introduced packages as a mechanism for modular development, independent compilation, and explicit encapsulation. When a stylesheet imports a library using the xsl:use-package element, it can alter or extend the behavior of the used package using the child element xsl:override.

When overriding components such as functions, attribute sets, template rules, or named templates, you frequently need to supplement existing logic rather than rewrite it from scratch. This process of customizing a component while retaining its core functionality is known as package refinement.

The Role of xsl:original

The xsl:original named template provides the callback mechanism required to execute the version of the component that is being overridden. When placed inside an overriding definition within an xsl:override block, invoking xsl:original executes the original definition provided by the base package.

Key characteristics of xsl:original include:

  • Context Preservation: It allows the overriding template to perform pre-processing on the input or parameters, delegate the core task to the underlying package template, and perform post-processing on the resulting output.
  • Super-Call Analogy: It functions identically to a super() method call in class-based inheritance, giving the derived package access to the hidden parent implementation.
  • Scope Restriction: The name xsl:original is reserved by the XSLT 3.0 specification. It can only be called inside the body of an overriding component within an xsl:override element.

Using xsl:original with Named Templates

When refining a named template, you invoke the original version using the standard <xsl:call-template> instruction with name="xsl:original".

Invocation Syntax

<xsl:package name="http://example.com/extended-pack" 
             package-version="1.0.0" 
             xmlns:xsl="http://www.w3.org/1999/XSL/Transform" 
             version="3.0">

  <xsl:use-package name="http://example.com/base-pack" package-version="1.0.0">
    <xsl:override>
      
      <!-- Overriding the named template 'format-header' -->
      <xsl:template name="format-header">
        <xsl:param name="title" as="xs:string"/>
        
        <!-- Pre-processing -->
        <div class="custom-wrapper">
          
          <!-- Delegate execution to the original template in base-pack -->
          <xsl:call-template name="xsl:original">
            <xsl:with-param name="title" select="upper-case($title)"/>
          </xsl:call-template>
          
        </div>
      </xsl:template>

    </xsl:override>
  </xsl:use-package>

</xsl:package>

Parameter Handling

When calling xsl:original within a named template:

  • Explicit Parameters: You can supply new or modified values using <xsl:with-param>. This allows the refining template to intercept, sanitize, or alter arguments before the original template processes them.
  • Default Values: If the overriding template does not supply a parameter expected by the original template, the original template's default value expression is evaluated unless tunneled parameters satisfy the requirement.
  • Tunnel Parameters: Tunneled parameters pass through xsl:original following standard XSLT rules, making them available to any internal calls made by the base implementation.

Operational Rules and Constraints

To correctly use xsl:original in your stylesheets, adhere to the following constraints enforced by XSLT 3.0 processors:

  1. Exact Component Binding: Inside an overriding named template, <xsl:call-template name="xsl:original"/> strictly refers to the named template with the identical QName in the package being overridden. It cannot be used to target a different named template.
  2. Static Error on Missing Target: If the base package does not expose an overridable component matching the name and type of the overriding component, the processor raises a static error (XTSE3050).
  3. No Circular References: An overriding template cannot call itself recursively under the alias xsl:original; it only ever resolves outward to the base package's definition.
