Prevent Schema Mismatch with XSLT Cardinality

Cardinality matching in XSLT sequence types serves as a compile-time and runtime validation layer that guarantees input and output data structures conform strictly to expected quantities. By defining occurrence indicators (?, *, +) on variables, function parameters, and template returns, developers can enforce schema constraints directly within transformations. This eliminates silent failures, catches missing or duplicate elements early, and prevents downstream schema mismatches against target XML Schemas (XSD).

The Cardinality Indicators

In XSLT 2.0 and later, sequence types describe both the data type and the number of items allowed in a sequence. If no indicator is specified, the sequence type defaults to expecting exactly one item. The three explicit occurrence indicators are:

  • ? (Zero or One): Specifies that the item is optional. It matches an empty sequence () or a sequence containing a single item.
  • * (Zero or More): Specifies an unbounded sequence that can be empty. It permits any number of items, from zero to infinity.
  • + (One or More): Specifies a non-empty sequence. It requires at least one item and permits any additional number of items.

Enforcing Strict Contracts Between Components

Applying sequence types with cardinality constraints across templates (<xsl:template as="...">), variables (<xsl:variable as="...">), and stylesheet functions (<xsl:function as="...">) establishes strict data contracts.

For instance, declaring a parameter as as="xs:string" guarantees that exactly one string is passed. If an XPath expression returns an empty sequence or multiple values, the XSLT processor immediately raises a dynamic type error (XPTY0004). If the source XML might legitimately lack the value, declaring as="xs:string?" explicitly accounts for optionality while continuing to block unintended multiple values.

Direct Mapping to XML Schema (XSD) Rules

XML Schemas define node frequencies using minOccurs and maxOccurs attributes. Cardinality indicators in sequence types map directly to these schema definitions:

  • minOccurs="1" maxOccurs="1" maps to default cardinality (no indicator).
  • minOccurs="0" maxOccurs="1" maps to ?.
  • minOccurs="0" maxOccurs="unbounded" maps to *.
  • minOccurs="1" maxOccurs="unbounded" maps to +.

By mirroring these constraints within XSLT signatures, transformations cannot accidentally produce structures that violate the target XSD. If an output requires at least one <item> element, defining a variable or template return type as as="element(item)+" ensures that an empty sequence is intercepted within the transformation pipeline rather than failing post-transformation during schema validation.

Fail-Fast Error Prevention Over Silent Degeneracy

Without cardinality matching, untyped or loosely typed XPath expressions can silently introduce bugs. For example, an expression intended to select a single identifier (/order/id) might return two nodes if the source XML contains unexpected duplicates.

In loosely typed XSLT, passing a multi-item sequence into a single-value context (such as an attribute constructor or string function) may only process the first node or cause an obscure error later in the process. With strict cardinality matching—such as select="/order/id" as="element(id)"—the processor immediately aborts execution when duplicates occur, pinpointing the schema deviation at the exact point of failure.
