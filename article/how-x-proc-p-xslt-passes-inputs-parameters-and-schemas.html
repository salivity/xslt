How XProc p:xslt Passes Inputs, Parameters, and Schemas

This article explains how the XProc <p:xslt> step integrates XML pipeline data into an XSLT transformation engine. It outlines the conventions used to route primary and secondary documents through standard input ports, bind pipeline variables to transformation parameters, and incorporate schemas for schema-aware transformations.

Input Ports

The <p:xslt> step relies on predefined input ports to supply the XML content and the stylesheet to the XSLT processor:

  • source Port: This is the primary input port. It accepts the XML document (or sequence of documents) that the XSLT stylesheet will transform. The first document on this port serves as the initial context item (the global context document) for the transformation.
  • stylesheet Port: This port accepts the XSLT stylesheet document itself. The step reads the transformation rules, templates, and functions directly from the XML document delivered to this port.
  • Secondary Input Documents: If an XSLT transformation requires access to additional XML documents via functions like document() or doc(), pipelines can resolve these documents through a configured XML catalog or URI resolver. In XProc 3.0, sequences of documents sent to the source port can also be accessed via the standard XSLT collection() function.

Passing Parameters

Parameters declared globally in the stylesheet via <xsl:param> receive their values from XProc declarations:

  • XProc 3.0: Parameters are passed as an XQuery/XPath map to the parameters option. Using <p:with-option>, you bind a map of QName-value pairs to the step: 
    <p:xslt>
  <p:with-option name="parameters" select="map{ 'target-format': 'html5', 'debug-mode': false() }"/>
</p:xslt>
    The step automatically translates map entries into corresponding global stylesheet parameters matching the keys.
  • XProc 1.0: Parameters are passed through the dedicated parameters port using the <p:with-param> element, specifying the parameter name and its evaluated value: 
    <p:xslt>
  <p:with-param name="target-format" select="'html5'"/>
</p:xslt>

Handling Schemas and Type Awareness

Passing schemas to a transformation depends on whether the underlying processor supports schema-aware XSLT (such as Saxon-EE):

  • Pre-Validation in the Pipeline: The standard XProc approach does not inject schemas directly through an input port on <p:xslt>. Instead, the source document is validated prior to the transformation using a dedicated validation step like <p:validate-with-xml-schema>. When passed to <p:xslt>, the document retains its type annotations (PSVI), allowing the XSLT processor to operate on typed data.
  • Stylesheet Schema Import: The stylesheet itself can import XML Schemas directly using the standard <xsl:import-schema> instruction. The XProc engine's underlying entity resolver locates the schema definition files using relative paths or an XML Catalog.
  • Processor Configuration: When custom schema components must be globally available without explicit imports, pipeline engines allow configuring the underlying transformation factory with preloaded XML Schemas via engine-specific properties or configuration files.
