deep-equal() in XSLT: Prefixes, Whitespace, Attributes

The XPath and XSLT deep-equal() function compares two sequences to determine whether their contents are structurally and value-wise identical. When comparing elements, it abstracts away purely syntactic differences, meaning it ignores attribute ordering and namespace prefix variations as long as the underlying names and values match. However, it treats whitespace strictly by default, comparing text nodes character-for-character unless the nodes are stripped or normalized prior to comparison.

Attribute Ordering

In the XML and XQuery/XSLT Data Model (XDM), attributes belong to an unordered set. Consequently, deep-equal() completely ignores the order in which attributes appear inside an element.

Two elements will evaluate to true as long as:

  • Both elements contain the exact same number of attributes.
  • Every attribute in the first element has a matching attribute in the second element with the same expanded QName (namespace URI and local name) and identical value.

For example, <item id="1" status="open"/> and <item status="open" id="1"/> return true.

Namespace Prefixes

The deep-equal() function compares element and attribute names using their expanded QNames, consisting of the namespace URI and the local name.

The prefix used to bind a namespace is considered arbitrary syntax. Therefore:

  • If two elements or attributes use different prefixes (e.g., a:item vs. b:item), but both prefixes resolve to the same namespace URI, deep-equal() returns true.
  • Default namespaces without prefixes are treated identically to prefixed namespaces if the target URIs match.
  • In-scope namespace nodes that are not used by any element or attribute name are not compared.

Whitespace Handling

Whitespace handling in deep-equal() is strict because text nodes are distinct items in the data model.

  • Significant Text: Any difference in whitespace—including spaces, tabs, and line breaks within text nodes—causes deep-equal() to return false. For instance, <name>John Doe</name> and <name>John Doe</name> are not equal.
  • Whitespace-Only Text Nodes: If formatting whitespace (such as indentation or newlines between child elements) is preserved as text nodes in the input tree, deep-equal() treats those whitespace text nodes as child items. If one document contains formatting whitespace and the other does not, the comparison returns false.

To ignore formatting whitespace when using deep-equal(), you must remove it beforehand using the xsl:strip-space directive in your stylesheet, or normalize string values using functions like normalize-space() before comparison.
