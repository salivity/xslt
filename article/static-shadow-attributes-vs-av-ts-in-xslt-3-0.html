Static Shadow Attributes vs AVTs in XSLT 3.0

In XSLT 3.0, static shadow attributes and standard Attribute Value Templates (AVTs) both use curly bracket notation to evaluate expressions, but they serve fundamentally different purposes and operate at different phases of execution. The primary distinction is that static shadow attributes are evaluated at compile time to dynamically configure the stylesheet itself, whereas standard AVTs are evaluated at run time to construct values for the resulting output document or specific instruction properties.

Execution Phase and Evaluation Context

Static shadow attributes—denoted by a leading underscore before the attribute name, such as _select or _test—are processed during the static analysis phase (stylesheet compilation). They can only evaluate static expressions. These expressions have access exclusively to static parameters (<xsl:param static="yes">), system properties, and static functions. They have no access to the source XML document, the dynamic context, or standard runtime variables.

Standard Attribute Value Templates (using {expression} within supported attributes) are evaluated dynamically during the transformation phase (run time). They operate within the dynamic evaluation context, possessing full access to the current node, runtime variables, document trees, and context-dependent functions like position() and current().

Applicability and Scope

Standard AVTs are only permitted on Literal Result Elements and specific XSLT attributes where the W3C specification explicitly allows them (such as the name attribute of <xsl:element>). They cannot be used on structural XSLT control attributes like match, select, or test.

In contrast, shadow attributes can be applied to almost any attribute of any XSLT element. By prefixing an attribute with an underscore, the XSLT processor evaluates the curly-bracketed expression at compile time and generates the corresponding standard attribute without the underscore. This enables dynamic generation of attributes that normally forbid AVTs, including select, test, use-when, and as.

Primary Use Cases

  • Static Shadow Attributes: Used for metaprogramming, conditional compilation, feature toggling, and target-environment optimization. For example, a stylesheet can set _select="if ($DEBUG) then 'debug-mode' else 'production'" on an <xsl:apply-templates> instruction, fixing the execution path at compile time without incurring runtime performance overhead.
  • Standard AVTs: Used for generating dynamic output attributes in literal result elements (e.g., <a href="{$url}">) or computing string values for runtime instructions, based directly on the content of the input document being transformed.
