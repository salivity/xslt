XSLT Serialization: Self-Closing vs Closing Tags

This article explains how XSLT processors handle self-closing tags versus explicit opening and closing tags when serializing XML output. While the W3C XML specification treats both syntaxes as semantically identical, downstream systems often require one specific form. Below is an overview of how the XSLT data model functions during transformation, how the serialization phase determines tag formatting, and the practical methods developers use to force explicit closing tags when necessary.

The Abstract Data Model vs. Serialization

In XSLT, transformations operate on an abstract tree representation known as the XQuery and XPath Data Model (XDM). Within this data model, an element node with no child nodes is simply an empty element. The data model makes no distinction between <item/> and <item></item>.

Because this internal representation does not record how the element was originally written in the source document, the decision to output a self-closing tag or an explicit pair of tags is deferred entirely to the serializer—the component responsible for converting the result tree back into raw text.

Default XML Serialization Behavior

When using standard XML output:

<xsl:output method="xml" encoding="UTF-8" indent="yes"/>

The serializer is permitted by the W3C XML specification to represent any empty element using either syntax:

  • Self-closing: <element/>
  • Full pair: <element></element>

Most modern XSLT processors (such as Saxon, Xalan, or xsltproc) default to the self-closing syntax (<element/>) for empty elements to minimize file size and improve processing speed. Standard XSLT 1.0 and 2.0 specifications provide no native attribute within <xsl:output> to mandate explicit closing tags for empty XML elements.

Serialization Modes and Their Effects

The choice of serialization method via the <xsl:output> element directly impacts how tags are written:

1. method="xml"

The processor treats empty tags as candidates for the abbreviated self-closing form. Unless children (text, comments, or other elements) exist, <tag/> is the default output.

2. method="html"

The serializer applies traditional HTML 4.01/HTML5 rules. Void elements (such as <br>, <img>, <input>, and <hr>) are written without closing tags or with self-closing slashes depending on the configuration. Non-void elements (such as <div></div>, <script></script>, and <p></p>) are explicitly closed, even when empty, because self-closing non-void tags are invalid in standard HTML.

3. method="xhtml"

The serializer follows XHTML guidelines (such as Appendix C of XHTML 1.0). It renders void elements as self-closing with a preceding space (e.g., <br />) and empty non-void elements with explicit closing tags (e.g., <p></p>).

How to Force Explicit Closing Tags in XML Output

Because some legacy parsers or client-side tools incorrectly fail when encountering self-closing tags like <script/> or <div/> inside XML or XHTML data streams, developers use several techniques to force explicit closing tags.

Technique 1: Adding an Empty Comment

Inserting an empty comment inside an element ensures the element is not technically empty in the node tree, forcing the serializer to generate both start and end tags without altering the visual text output:

<script type="text/javascript">
    <xsl:comment/>
</script>

Output:

<script type="text/javascript"><!--\--></script>

Technique 2: Injecting a Zero-Width Space or Empty Character Reference

Adding an invisible entity or a controlled text node prevents the processor from collapsing the element:

<div>
    <xsl:text>&#x200B;</xsl:text>
</div>

Note: This alters the character content of the element and should be avoided if strict data validation or string-length checks are applied downstream.

Technique 3: Using Processor-Specific Serialization Properties

Advanced XSLT engines provide vendor extensions to control tag minimization during serialization.

For example, Saxon allows developers to control whether empty elements are collapsed via output properties or custom character mapping, though standard configurations generally recommend switching the output method to xhtml or html if the intended consumer is a web browser.

Summary

XSLT manages tag closing strictly at the serialization stage rather than during tree construction. While method="xml" will almost always collapse empty elements into self-closing tags, developers targeting environments that require explicit closing tags must either switch to method="xhtml"/method="html" or populate elements with benign nodes—such as comments—to prevent the serializer from collapsing them.
