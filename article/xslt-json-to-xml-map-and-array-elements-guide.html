XSLT json-to-xml: Map and Array Elements Guide

The json-to-xml() function introduced in XPath and XSLT 3.0 provides a standardized way to parse JSON text into an XML representation. At the core of this transformation are the <map> and <array> elements, which translate JSON objects and arrays into structured, queryable XML nodes defined under a specific W3C namespace. Understanding how these elements represent data structures, keys, and values allows developers to manipulate JSON payloads effectively using standard XPath and XSLT templates.

The W3C JSON-to-XML Model

When json-to-xml() parses a JSON string, it outputs an XML document where every element belongs to the standard namespace:

http://www.w3.org/2005/xpath-functions

In this model, JSON data structures (objects and arrays) and scalar values (strings, numbers, booleans, nulls) are converted into distinct XML elements that mirror the JSON hierarchy.

The <map> Element

The <map> element represents a JSON object (a collection of key-value pairs).

  • Child Elements: The children of a <map> element can be any JSON-XML representation: <string>, <number>, <boolean>, <null>, nested <map> elements, or nested <array> elements.
  • The key Attribute: Because JSON objects use string keys, every direct child element of a <map> must include a key attribute specifying the property's name.
  • Unordered Nature: In accordance with the JSON specification, key-value pairs in a <map> have no semantic ordering, though they appear in sequential order in the XML tree.

Example:

Given this JSON object:

{
  "title": "Introduction",
  "views": 150
}

The transformed XML is:

<map xmlns="http://www.w3.org/2005/xpath-functions">
  <string key="title">Introduction</string>
  <number key="views">150</number>
</map>

The <array> Element

The <array> element represents an ordered sequence of JSON values.

  • Child Elements: Like <map>, an <array> can contain any combination of data elements, including scalar types, nested <map> elements, or nested <array> elements.
  • No key Attributes: Direct child elements of an <array> do not possess a key attribute. Their position in the array is determined strictly by their node order in the XML structure.
  • Indexed Access: Items inside an <array> are mapped by sequence, making them easy to select using XPath positional predicates (e.g., fn:array/*[1]).

Example:

Given this JSON array:

["draft", "review", "published"]

The transformed XML is:

<array xmlns="http://www.w3.org/2005/xpath-functions">
  <string>draft</string>
  <string>review</string>
  <string>published</string>
</array>

Combined Example

When arrays and objects are nested within each other, <map> and <array> elements combine hierarchically.

Given the following JSON:

{
  "user": "Alice",
  "roles": ["admin", "editor"]
}

The json-to-xml() function outputs:

<map xmlns="http://www.w3.org/2005/xpath-functions">
  <string key="user">Alice</string>
  <array key="roles">
    <string>admin</string>
    <string>editor</string>
  </array>
</map>

Notice that the <array> element receives a key="roles" attribute because it is a direct child of a <map>. However, the <string> children inside the <array> do not have key attributes.

Querying <map> and <array> in XSLT

To process these elements in XSLT, declare the XPath functions namespace and use template matching or XPath expressions targeting the elements and their attributes:

<xsl:stylesheet version="3.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:fn="http://www.w3.org/2005/xpath-functions">

  <!-- Match a property inside a map by key -->
  <xsl:template match="fn:map/fn:string[@key='user']">
    <username><xsl:value-of select="."/></username>
  </xsl:template>

  <!-- Match items within an array -->
  <xsl:template match="fn:array[@key='roles']/fn:string">
    <role><xsl:value-of select="."/></role>
  </xsl:template>

</xsl:stylesheet>

By relying on explicit <map> and <array> elements and key attributes, the model maintains a complete, lossless mapping of the original JSON syntax while making it fully navigable using native XSLT patterns.
