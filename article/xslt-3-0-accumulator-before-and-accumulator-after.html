XSLT 3.0 accumulator-before and accumulator-after

In XSLT 3.0 streaming, accumulator-before() and accumulator-after() are built-in functions used to access the state of an xsl:accumulator at specific points in a node’s processing cycle. Because streaming transforms process XML documents sequentially without holding the entire document tree in memory, standard axes like preceding-sibling or ancestor are unavailable. Accumulators solve this by maintaining state as the document stream is traversed, and these two functions allow developers to query that state either immediately prior to processing a node and its descendants, or immediately after.

The Purpose of Accumulators in Streaming

Streaming requires sequential, single-pass processing. Standard XSLT variables cannot change their value over time, and querying previous nodes violates streaming rules. An xsl:accumulator behaves as a functional, stream-safe mechanism that listens to document events (such as encountering start and end tags) and updates its value based on defined xsl:accumulator-rule elements.

To read these accumulator values without breaking streamability, XSLT 3.0 provides accumulator-before() and accumulator-after().

The accumulator-before() Function

The accumulator-before($accumulator-name) function returns the value of the designated accumulator immediately before the current node and its descendants are visited.

  • Event Timing: It captures the state after all nodes occurring before this node in document order have been processed, but before any rules matching this node or its child elements take effect.
  • Primary Use Case: Accessing context or running calculations that apply up to the start of the current element. For instance, if you are tracking a running balance or a line counter, accumulator-before() provides the tally right before the current record begins.

The accumulator-after() Function

The accumulator-after($accumulator-name) function returns the value of the accumulator immediately after the current node and all of its descendants have been fully processed.

  • Event Timing: For an element node, this corresponds to the moment the closing tag is encountered. It reflects all modifications made by accumulator rules applied to the element itself, its attributes, and its children.
  • Primary Use Case: Measuring aggregate data or changes produced by a subtree. For example, if an accumulator sums up the costs of individual items inside an <order> element, calling accumulator-after() on the <order> element returns the total cost calculated from all nested <item> tags.

Key Behavioral Differences

The distinction between the two functions is dictated by where the node sits relative to tree traversal:

  1. For Leaf Nodes (e.g., text nodes or attribute nodes): The difference between accumulator-before() and accumulator-after() is simply whether the accumulator rule attached to that specific leaf node has been applied.
  2. For Element Nodes: accumulator-before() captures the state entering the element, while accumulator-after() captures the state leaving the element, including all modifications made by rules within the element's entire content.
  3. Availability Rules: While accumulator-before() can be invoked on streamed nodes before descending into their content, calling accumulator-after() on a streaming element typically requires that the element's content has already been consumed by the processor, ensuring that the post-descent state is legitimately computable.
