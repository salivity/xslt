Standard XML Representation of JSON in XSLT

This article provides an overview of how XSLT 3.0 and XPath 3.1 standardize the conversion between JSON and XML using a predefined schema. By utilizing built-in functions such as fn:json-to-xml() and fn:xml-to-json(), XSLT transforms unstructured or serialized JSON payloads into strongly typed, hierarchical XML trees. The standard maps every native JSON type directly to a designated XML element within the official namespace, enabling seamless querying and transformation using standard XPath expressions.

The W3C defines this standardized mapping under the namespace http://www.w3.org/2005/xpath-functions, commonly bound to prefixes like fn or j. Every JSON data type maps directly to a matching XML element name within this namespace:

  • Objects map to <map>
  • Arrays map to <array>
  • Strings map to <string>
  • Numbers map to <number>
  • Booleans map to <boolean>
  • Null values map to <null>

Representing Object Keys

In JSON, objects consist of unordered key-value pairs. In the standard XML representation, the key is preserved using a key attribute on the corresponding value element.

For example, the JSON object:

{
  "title": "Example",
  "count": 42,
  "active": true
}

is structured in XML as:

<map xmlns="http://www.w3.org/2005/xpath-functions">
  <string key="title">Example</string>
  <number key="count">42</number>
  <boolean key="active">true</boolean>
</map>

Representing Arrays

JSON arrays represent ordered sequences of values. When converted to XML, the <array> element contains child elements corresponding to the array items in their original sequence. These child elements do not possess a key attribute unless the array itself is a property within a parent <map>.

For example, the JSON array:

["alpha", "beta", "gamma"]

is represented as:

<array xmlns="http://www.w3.org/2005/xpath-functions">
  <string>alpha</string>
  <string>beta</string>
  <string>gamma</string>
</array>

Handling Nested Structures and Null Values

Complex, nested structures retain their relationships by nesting <map> and <array> elements. Empty elements represent null values using <null/>, while empty strings are represented as <string/> or <string></string>.

Consider a nested structure:

{
  "user": {
    "name": "Alice",
    "roles": ["admin", "editor"],
    "preferences": null
  }
}

The resulting XML maintains the hierarchy:

<map xmlns="http://www.w3.org/2005/xpath-functions">
  <map key="user">
    <string key="name">Alice</string>
    <array key="roles">
      <string>admin</string>
      <string>editor</string>
    </array>
    <null key="preferences"/>
  </map>
</map>

Escaping and Special Characters

The standard specifies optional attributes for handling Unicode characters and control codes. If a key or string value contains characters not allowed in standard XML characters or requires specific escaping, the standard supports an escaped="true" attribute on the element or an escaped-key="true" attribute for keys. This guarantees that round-trip conversions between JSON and XML via fn:xml-to-json() preserve exact character fidelity without data loss.
