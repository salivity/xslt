XSLT Context Node: Named Templates vs Functions

In XSLT development, understanding how context is bound is essential when deciding between named templates and stylesheet functions. The fundamental difference lies in context inheritance: named templates automatically inherit and operate within the caller's existing context node, whereas XSLT functions evaluate in an environment where the context node is completely undefined by default.

Context Node in Named Templates

A named template, defined using <xsl:template name="..."> and invoked via <xsl:call-template name="...">, retains the dynamic context of the calling instruction. This means:

  • Automatic Context Preservation: The context item (.), context position (position()), and context size (last()) are identical to those at the point of the call.
  • Direct Path Evaluation: You can immediately evaluate relative XPath expressions (such as child::title or @attribute) inside the named template without having to explicitly pass the current node as a parameter.
  • Tunnel and Explicit Parameters: While named templates can accept parameters (<xsl:param>), passing the context item is redundant unless you intend to evaluate a completely different node tree.

Context Node in Function Declarations

Introduced in XSLT 2.0, stylesheet functions defined with <xsl:function name="..."> behave differently because they are invoked directly within XPath expressions. In this environment:

  • No Initial Context Item: When an XSLT function begins execution, the context item is absent (undefined).
  • Dynamic Error on Implicit Reference: Attempting to reference the context item directly (using .) or using context-dependent functions like position() or relative axis steps without a defined context results in a static or dynamic error (such as XPDY0002: Context item is absent).
  • Explicit Parameter Passing: To perform operations on a node within a function, that node must be explicitly passed as an argument. For instance, you must declare <xsl:param name="node" as="node()"/> and write $node/@attribute or $node/child::element.
  • Establishing a Context: If a function needs to use context-dependent operations, a context must be established explicitly inside the function body, typically using an <xsl:for-each select="$node"> instruction or a path expression.

Key Reasons for the Architectural Difference

This distinction exists primarily to preserve functional purity and avoid unexpected side effects within XPath expressions.

XPath functions are intended to behave as pure functions whose output depends solely on their supplied arguments. If functions implicitly bound to the ambient context node, changing an outer XPath expression could invisibly alter the internal behavior of the function, making stylesheets harder to debug, refactor, and optimize. Named templates, by contrast, are procedural instructions designed to produce markup directly within the XSLT execution flow, making context inheritance natural and convenient.
