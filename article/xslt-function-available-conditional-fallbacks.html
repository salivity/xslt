XSLT function-available Conditional Fallbacks

The function-available() function in XSLT evaluates whether an XSLT processor supports a specific XPath or extension function before attempting to call it. By using this function within conditional structures like <xsl:choose> or <xsl:if>, developers can create cross-platform stylesheets that leverage advanced processor-specific features when present while gracefully degrading to standard or alternative logic when running on different engines.

The Cross-Platform Challenge in XSLT

Different XSLT processors—such as Saxon, Xalan, Libxslt, and MSXML—vary widely in their support for XSLT versions, EXSLT modules, and proprietary extension functions. Calling a function that the host processor does not recognize causes a fatal dynamic or static evaluation error, terminating the transformation.

Because stylesheets frequently need to run across diverse environments (such as client-side browsers and server-side runtimes), hardcoding proprietary or version-specific functions introduces significant fragility.

How function-available() Works

The function-available() function accepts a single string argument representing the qualified name (QName) of a function:

function-available('prefix:function-name')

The function returns true() if the processor supports the function within the specified namespace; otherwise, it returns false(). If the argument is an unqualified name without a prefix, it checks for standard core functions in the default function namespace.

Because XPath evaluates conditional branches logically, an unsupported function placed inside an unexecuted branch will not cause a runtime failure in compliant processors, provided the call itself does not trigger a compile-time static error.

Implementing Conditional Fallback Patterns

The standard design pattern uses an <xsl:choose> block to verify function availability before execution, providing a fallback implementation in the <xsl:otherwise> block.

Example: Regular Expression Evaluation

Consider a scenario where you want to use the EXSLT regexp:test function if available, but fall back to standard string matching using contains() if the engine does not support EXSLT:

<xsl:stylesheet version="1.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:regexp="http://exslt.org/regular-expressions"
    extension-element-prefixes="regexp">

  <xsl:template match="item">
    <xsl:choose>
      <!-- Check for EXSLT regular expression support -->
      <xsl:when test="function-available('regexp:test')">
        <xsl:if test="regexp:test(text(), '^[A-Z]{3}-[0-9]{4}$')">
          <valid-item><xsl:value-of select="text()"/></valid-item>
        </xsl:if>
      </xsl:when>

      <!-- Fallback logic for processors without regexp support -->
      <xsl:otherwise>
        <xsl:if test="contains(text(), '-')">
          <valid-item status="unverified"><xsl:value-of select="text()"/></valid-item>
        </xsl:if>
      </xsl:otherwise>
    </xsl:choose>
  </xsl:template>

</xsl:stylesheet>

In this implementation:

  1. Processors supporting regexp:test enter the first <xsl:when> branch and perform precise pattern matching.
  2. Processors lacking the function evaluate function-available('regexp:test') as false(), bypass the branch entirely, and execute the <xsl:otherwise> fallback.

Key Considerations for Cross-Platform Design

  • Namespace Declaration: Any prefix passed to function-available() must be mapped to the appropriate namespace URI in the stylesheet header. If the namespace is missing, the transformation will fail during parsing.
  • Arity Checks (XSLT 2.0+): In XSLT 2.0 and later, function-available() accepts an optional second integer argument specifying the function arity: function-available('my:func', 2). This allows checking for specific function signatures when functions are overloaded.
  • Static vs. Dynamic Analysis: Some strict XSLT 2.0+ processors validate XPath function calls statically during compilation. If an unavailable function is invoked directly in the stylesheet, compilation might fail regardless of the function-available() guard. In these environments, combining function-available() with dynamic execution techniques or splitting version-dependent code into separate modules using xsl:use-when ensures complete portability.
