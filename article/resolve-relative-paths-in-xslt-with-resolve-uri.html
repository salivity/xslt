Resolve Relative Paths in XSLT with resolve-uri

The resolve-uri() function in XSLT and XPath provides a standardized mechanism for converting relative resource paths into fully qualified, absolute URIs. By evaluating a relative path against an appropriate base URI—such as the location of the stylesheet or the source XML document—the function ensures that external assets, secondary XML documents, and schemas can be located reliably. This article explains how resolve-uri() operates, its primary syntax variations, and its practical importance in document transformation workflows.

Purpose of the resolve-uri() Function

In XML processing, documents often contain relative paths pointing to related resources such as images, configuration files, or external data sets. Attempting to load these resources directly using functions like doc() or unparsed-text() can fail if the processor does not know the intended reference point.

The resolve-uri() function resolves this ambiguity by implementing standard URI resolution rules (defined in RFC 3986). It combines a relative path with a known base path to create a deterministic, absolute URI, preventing broken references across different processing environments.

Function Signatures and Behavior

The resolve-uri() function, introduced in XPath 2.0 and supported across modern XSLT processors (such as Saxon), comes in two signatures:

1. Single-Argument Form: resolve-uri($relative)

When invoked with a single argument, the function resolves the provided relative URI against the static base URI of the expression context. In most XSLT stylesheets, this default base URI corresponds to the filesystem or network location of the XSLT file containing the instruction.

<!-- Resolves 'schema.xsd' against the stylesheet's own file location -->
<xsl:variable name="abs-path" select="resolve-uri('schema.xsd')"/>

If $relative is an empty sequence or already an absolute URI, the function behaves accordingly: an absolute URI is returned unchanged, and an empty sequence results in an empty sequence.

2. Two-Argument Form: resolve-uri($relative, $base)

The two-argument form allows you to explicitly provide the base URI against which the relative URI must be resolved. This is essential when the target resource is relative to the input XML document rather than the stylesheet.

<!-- Resolves a relative path stored in an XML attribute against the input document's base URI -->
<xsl:variable name="doc-base" select="base-uri(.)"/>
<xsl:variable name="target-file" select="resolve-uri(@href, $doc-base)"/>
<xsl:copy-of select="doc($target-file)"/>

In this scenario, base-uri(.) retrieves the base URI of the current context node, ensuring that the target file is looked up relative to the input XML.

Key Use Cases in XSLT

  • Dynamic Document Loading: When processing master documents that link to sub-documents (e.g., modular documentation systems like DITA or DocBook), resolve-uri() ensures that child documents referenced via relative paths can be retrieved using doc().
  • Output Path Generation: When producing output formats like HTML or EPUB that contain hyperlinks or embedded media paths, resolve-uri() can be used to normalize and compute correct relative or absolute target locations.
  • Decoupling Stylesheet and Data Locations: In environments where stylesheets reside on a shared server and data files reside locally, using the two-argument form prevents the processor from incorrectly searching for assets in the stylesheet's directory.

Summary

The resolve-uri() function eliminates location ambiguity in XSLT workflows by transforming relative file paths and URLs into reliable, absolute URIs. Using either the stylesheet's static context or an explicitly defined base via base-uri(), developers can safely traverse and reference external files regardless of how or where the transformation pipeline is executed.
