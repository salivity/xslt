copy-of vs snapshot in Streamed XSLT

In streamed XSLT 3.0 processing, both copy-of() and snapshot() materialize streamed nodes into in-memory trees to allow unrestricted, non-streamed navigation, but they differ fundamentally in structural scope. While copy-of() copies only the targeted node and its descendants into an isolated fragment, snapshot() retains the ancestor hierarchy back to the document root. Understanding this structural distinction is critical for balancing memory usage against navigation requirements during streaming transformations.

The Purpose of Materialization in Streaming

Streaming XML limits operations to a single, forward-only pass through the document. Because of this, standard XSLT operations that navigate backwards or reuse nodes multiple times (such as accessing the preceding-sibling:: axis or evaluating a node twice) violate streaming rules.

Both copy-of() and snapshot() overcome these limitations by pulling the streaming node into memory as an unstreamed, navigable XDM (XQuery and XPath Data Model) tree. However, they preserve different amounts of document context.

The copy-of() Function

The copy-of() function creates a deep copy of the selected node and its descendants, completely detached from the original document context.

  • Ancestor Isolation: The resulting tree begins at the copied node (or a new parent document node). All connections to parent and ancestor nodes are severed.
  • Axis Behavior: Calling parent::* or ancestor::* on the output of copy-of() returns an empty sequence.
  • Sibling Behavior: Sibling nodes are not copied, meaning preceding-sibling::* and following-sibling::* return empty sequences.
  • Memory Footprint: Because it stores only the selected subtree, copy-of() utilizes the minimum amount of memory needed to represent the target data.

Use copy-of() when you need to process a specific element multiple times or perform complex descendant queries, and you do not rely on metadata from containing elements.

The snapshot() Function

The snapshot() function creates a deep copy of the selected node and its descendants, while also constructing a skeleton structure of all its ancestor nodes up to the document root.

  • Ancestor Preservation: While it does not copy the descendants of ancestors (cousins, uncles, or siblings of ancestors), it creates shallow copies of each ancestor element and copies all their attributes.
  • Axis Behavior: The parent::* and ancestor::* axes remain fully navigable. You can safely read attributes and namespaces on ancestors (for example, evaluating ../@xml:base or ancestor::chapter/@id).
  • Sibling Behavior: Like copy-of(), siblings of the target node are not copied. However, the path back to the root is preserved.
  • Memory Footprint: It requires slightly more memory than copy-of() to maintain the chain of ancestor nodes and their attributes, though it remains far more memory-efficient than loading the entire XML document.

Use snapshot() when the logic processing the streamed element needs context from outer tags, such as inherited attributes, language declarations, or ancestral identifiers.

Key Differences Summary

Feature copy-of() snapshot()
Descendants Deep copy Deep copy
Ancestors Discarded completely Shallow-copied up to root
Ancestor Attributes Inaccessible Fully accessible
