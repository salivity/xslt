Query Processor Properties with XSLT system-property()

The system-property() function in XSLT allows developers to query the execution environment and retrieve information regarding the XSLT processor being used. This guide explains the syntax of the system-property() function, lists the standard properties defined by the W3C specification, provides concrete XSLT code examples, and demonstrates how to utilize these values for debugging and conditional processing.

Syntax and Namespace Requirement

The system-property() function accepts a single argument: a string representing a Qualified Name (QName) of the property you want to retrieve.

system-property(propertyName)

For standard XSLT properties, the prefix used in the argument (typically xsl:) must be bound to the official XSLT namespace: http://www.w3.org/1999/XSL/Transform. If the property name is not recognized or the prefix is unbound, the function returns an empty string.

Standard XSLT System Properties

The XSLT specification mandates three standard system properties that every conforming processor must provide:

  • xsl:version: Returns a number representing the XSLT specification version implemented by the processor (for example, 1.0, 2.0, or 3.0).
  • xsl:vendor: Returns a string identifying the vendor or creator of the XSLT processor (such as "Saxonica" or "Apache Software Foundation").
  • xsl:vendor-url: Returns a string containing a URL identifying the vendor.

Basic Implementation Example

The following stylesheet queries all three standard properties and outputs them as text elements:

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="xml" indent="yes"/>

    <xsl:template match="/">
        <processor-info>
            <version>
                <xsl:value-of select="system-property('xsl:version')"/>
            </version>
            <vendor>
                <xsl:value-of select="system-property('xsl:vendor')"/>
            </vendor>
            <vendor-url>
                <xsl:value-of select="system-property('xsl:vendor-url')"/>
            </vendor-url>
        </processor-info>
    </xsl:template>
</xsl:stylesheet>

Conditional Processing Based on the Processor

system-property() is commonly used to implement conditional logic when a stylesheet must run across different environments or versions of an engine.

<xsl:choose>
    <xsl:when test="number(system-property('xsl:version')) >= 2.0">
        <!-- Execute advanced logic supported in XSLT 2.0+ -->
        <xsl:value-of select="'Modern XSLT Engine'"/>
    </xsl:when>
    <xsl:otherwise>
        <!-- Fallback logic for XSLT 1.0 processors -->
        <xsl:value-of select="'Legacy XSLT 1.0 Engine'"/>
    </xsl:otherwise>
</xsl:choose>

Vendor-Specific and Environment Properties

Some XSLT processors extend system-property() to query underlying platform details.

  • Java-based processors (e.g., Saxon, Xalan): Can often read Java system properties such as system-property('java.version'), system-property('os.name'), or system-property('file.separator').
  • Processor-specific metadata: Some vendors define their own namespace to expose product editions or build numbers (e.g., Saxon's product edition properties).

When querying platform-specific properties, ensure your stylesheet accounts for potential empty string returns if it is ever executed on a different processor or operating system.
