concat() vs String Templates in XSLT 3.0

This article compares traditional string concatenation using the XPath concat() function with string templates—specifically Text Value Templates (TVTs)—introduced in XSLT 3.0. While both approaches allow developers to combine dynamic expressions with static text, they differ significantly in syntax, readability, maintainability, and processor requirements. Understanding these differences enables developers to write cleaner, more expressive transformations when working with modern XSLT processors.

Syntax and Readability

The concat() function requires passing every piece of literal text and dynamic expression as separate comma-delimited arguments. As the number of dynamic parts and delimiters increases, concat() statements quickly become cluttered with quotation marks, commas, and parentheses.

<!-- Using concat() -->
<xsl:value-of select="concat('Hello, ', $firstName, ' ', $lastName, '! You have ', count(items), ' items.')"/>

XSLT 3.0 introduces Text Value Templates, enabled by setting expand-text="yes" on an element or stylesheet. This allows expressions to be embedded directly inside text nodes or attributes using curly braces ({}), functioning like string interpolation in languages such as JavaScript or C#.

<!-- Using String Templates (TVT) with expand-text="yes" -->
<p xsl:expand-text="yes">Hello, {$firstName} {$lastName}! You have {count(items)} items.</p>

The resulting code is much easier to read and maintain because the literal text maintains its natural spacing and structure without broken quote boundaries.

Handling Separators and Sequences

When dealing with sequences of items, concat() expects individual atomic arguments or an explicit separator through XPath 3.1's string-join() function. Passing a sequence of more than one item to an argument in concat() results in a type error unless handled manually.

In contrast, an expression evaluated inside {} within an XSLT 3.0 string template automatically converts sequences to strings by joining items with a single space separator by default. This makes outputting simple lists or series of values more direct:

<!-- Automatically separates items with a space -->
<span xsl:expand-text="yes">{('Apple', 'Banana', 'Cherry')}</span>
<!-- Output: Apple Banana Cherry -->

Escaping Curly Braces

One key syntactic difference is the handling of literal curly braces:

  • With concat(), curly braces require no special treatment and can be passed directly as string literals: concat('{', $value, '}').
  • With string templates and expand-text="yes", literal curly braces must be doubled ({{ and }}) so the processor does not mistake them for an expression container:
<script xsl:expand-text="yes">
  function run() {{
    console.log("{$message}");
  }}
</script>

Backward Compatibility and Processor Support

The concat() function has been part of the core XPath specification since XPath 1.0. It works across any XSLT processor regardless of age or version (XSLT 1.0, 2.0, or 3.0).

String templates and Text Value Templates require an XSLT 3.0-compliant processor, such as Saxon-HE 9.8+ or higher. If a stylesheet must maintain compatibility with legacy XSLT 1.0 or 2.0 runtimes, concat() remains the standard approach.

Summary

Use concat() when writing backward-compatible stylesheets for XSLT 1.0 or 2.0 processors, or for very short, two-item combinations. Use XSLT 3.0 string templates (expand-text="yes") for multi-variable strings, readable templates, markup generation, and cleaner stylesheet architecture.
