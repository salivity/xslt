Roaming vs Crawling in XSLT 3.0 Streamability

XSLT 3.0 introduces streaming capabilities to process large XML documents sequentially without loading the entire tree into memory. To guarantee that a stylesheet can execute in a single pass, the XSLT processor performs static streamability analysis by assigning a "posture" and a "sweep" to every expression. This article explains the technical differences between two key postures—crawling and roaming—focusing on how their navigation axes differ, how they handle node hierarchy, and how they determine whether an expression is streamable or causes a static error.

Understanding Posture in XSLT 3.0

In XSLT 3.0 streamability analysis, posture describes the relationship between the nodes selected by an expression and the context node. The processor uses posture to track where the current execution pointer is relative to the streaming document. The five standard postures defined in the W3C specification are:

  • Grounded: The value consists of atomic values or nodes stored in an in-memory temporary tree.
  • Striding: Downward navigation selecting peer nodes at a single level (e.g., using child::*).
  • Crawling: Downward navigation selecting nodes at arbitrary depths.
  • Climbed: Upward navigation to ancestor nodes.
  • Roaming: Arbitrary, multi-directional, or unconstrained navigation across the tree.

Among these, crawling and roaming represent two fundamentally different ways expressions navigate XML nodes, leading to vastly different outcomes during streamability analysis.

What Is a Crawling Expression?

A crawling expression moves exclusively downward in the document hierarchy to select descendants at variable depths. It is triggered when an expression uses the descendant:: or descendant-or-self:: axis (commonly written using the // shorthand).

Characteristics of Crawling Posture

  • Axis limitation: Confined strictly to downward descendant traversal.
  • Node overlap: Unlike striding expressions—where selected nodes are siblings and cannot contain each other—crawling expressions can return overlapping nodes where one selected element is an ancestor of another selected element.
  • Streamability: A crawling expression remains streamable under controlled conditions. Because it moves strictly forward in document order within the subtree of the context node, an XSLT streaming engine can process it using consuming constructs such as xsl:iterate or xsl:for-each. However, higher restrictions apply compared to striding expressions to avoid memory buffering of nested matches.

What Is a Roaming Expression?

A roaming expression is an expression whose node traversal cannot be verified to move strictly in forward document order within the context node’s subtree. It occurs when navigation goes sideways, backward, or mixes incompatible axes.

Characteristics of Roaming Posture

  • Axis limitation: Triggered by axes such as following::, preceding::, following-sibling::, preceding-sibling::, or complex combinations of upward and downward steps that escape strict streaming paths.
  • Unbounded movement: The processor cannot guarantee that the selected nodes can be consumed in a single linear pass over the XML stream.
  • Streamability: An expression evaluated to a roaming posture is universally non-streamable within a streaming context. If a roaming expression is used where a streamable posture is required (such as inside xsl:stream without copying the data into memory first), the XSLT processor raises a static streamability violation (XTSE3150 or related static errors).

Key Differences

Feature Crawling Expression Roaming Expression
Direction of Movement Strictly downward (descendant, descendant-or-self) Horizontal, backward, or arbitrary (following, preceding, unconstrained siblings)
Document Order Guarantee Preserves linear forward order within the subtree Fails linear forward traversal guarantees
Node Containment Allows nested elements within the context subtree Navigates outside or across disjoint subtrees
Streamability Status Potentially streamable with restrictions Non-streamable
Typical Fix Simplify to striding (child axes) if possible Wrap in copy-of() or snapshot() to ground into memory

Practical Implications for Stylesheet Authors

When writing streaming XSLT:

  1. Handling Crawling: If an expression like select="//record" is used, the processor marks it as crawling. It can be consumed, but it cannot be combined with secondary consuming actions that require distinct, non-nested buffers. Replacing //record with direct child paths like /root/batch/record converts the posture from crawling to striding, expanding the operations permitted on the stream.
  2. Handling Roaming: If an expression needs to inspect sibling or prior elements (e.g., preceding-sibling::item), the posture becomes roaming, which immediately breaks streaming. To resolve this, authors must ground the target node into memory using copy-of() or snapshot(), which changes the posture to grounded and satisfies streamability rules at the expense of local memory usage.
