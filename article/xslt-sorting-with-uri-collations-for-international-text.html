XSLT Sorting with URI Collations for International Text

This article provides an overview of how XSLT handles sorting and collation for international character sets using URI-based collations. Starting with XSLT 2.0 and continuing through XSLT 3.0, the language moved beyond basic system-dependent sorting to a robust, standardized mechanism using Collation URIs. By mapping specific Internationalized Resource Identifiers (URIs) to Unicode Collation Algorithm (UCA) rules, XSLT allows developers to achieve precise, locale-aware, and culturally accurate sorting across diverse languages and scripts.

The Evolution of Sorting in XSLT

In XSLT 1.0, sorting non-English text relied heavily on the lang attribute inside <xsl:sort>. However, implementations varied significantly across different processors, leading to inconsistent behavior regarding diacritics, case sensitivity, and language-specific alphabetic rules.

XSLT 2.0 and XSLT 3.0 resolved this fragmentation by formalizing the use of Collation URIs. A collation in XSLT represents a set of rules that determines the relative order of strings and whether two strings are considered equal. Instead of relying on operating system defaults, processors look up rules identified by absolute or relative URIs.

The Unicode Codepoint Collation

The standard fallback in XSLT is the Unicode Codepoint Collation, identified by:

http://www.w3.org/2005/xpath-functions/collation/codepoint

When this URI is used, characters are compared strictly by their binary Unicode code points. While fast and completely uniform across all platforms, it does not conform to natural language rules:

  • All uppercase ASCII letters (A-Z) sort before lowercase ASCII letters (a-z).
  • Accented letters (such as é or ü) appear far down the list after standard Latin characters.
  • It is generally unsuitable for human-facing internationalized displays.

The W3C Unicode Collation Algorithm (UCA) URI

To handle internationalization correctly, the W3C defined a standard URI format for the Unicode Collation Algorithm (UCA):

http://www.w3.org/2013/collation/UCA

This URI supports query parameters that allow developers to fine-tune sorting behavior for international character sets:

  • lang: Specifies the BCP 47 language tag (e.g., lang=de for German, lang=sv for Swedish).
  • strength: Defines the level of differences considered significant:
    • primary: Only base letters are considered (e equals E and é).
    • secondary: Distinguishes accents and diacritics (e differs from é).
    • tertiary: Distinguishes case and variants (e differs from E).
  • case-order: Specifies whether uppercase or lowercase comes first (upper-first or lower-first).
  • numeric: Accepts yes or no. When set to yes, sequences of digits are treated as numbers (e.g., "item 2" comes before "item 10").
  • decomposition: Controls how precomposed characters are normalized (standard or none).

Example URI Construction

To sort German text using German phonebook order (where ä is treated like ae), you configure the URI as:

http://www.w3.org/2013/collation/UCA?lang=de;rules=phonebook

To sort Swedish text (where å, ä, and ö are separate letters that appear at the end of the alphabet):

http://www.w3.org/2013/collation/UCA?lang=sv

Applying Collation URIs in XSLT

Collation URIs can be applied directly to <xsl:sort> elements or declared globally across an entire stylesheet.

Local Application via <xsl:sort>

You can specify the collation directly on a sort element using the collation attribute:

<xsl:for-each select="employees/employee">
  <xsl:sort select="last-name" 
            collation="http://www.w3.org/2013/collation/UCA?lang=es;case-order=lower-first" />
  <xsl:value-of select="last-name" />
</xsl:for-each>

In Spanish sorting, this correctly positions characters according to Spanish rules while prioritizing lowercase letters over uppercase letters.

Global Application via default-collation

Instead of repeating the URI in every sorting or comparison operation, you can define a default-collation on the <xsl:stylesheet> element:

<xsl:stylesheet version="3.0"
  xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  default-collation="http://www.w3.org/2013/collation/UCA?lang=fr;strength=secondary">
  
  <xsl:template match="catalog">
    <xsl:for-each select="book">
      <!-- Inherits the French collation automatically -->
      <xsl:sort select="title"/>
      <xsl:value-of select="title"/>
    </xsl:for-each>
  </xsl:template>
  
</xsl:stylesheet>

This default also applies to string comparison functions like fn:compare(), fn:contains(), and fn:index-of().

Processor-Specific URI Schemes

While the W3C UCA URI is widely supported in modern processors, major XSLT engines also provide proprietary URI schemes that bridge with platform-native collation libraries:

  • Saxon: Uses Java or .NET collations via URLs such as http://saxon.sf.net/collation?lang=ja or http://saxon.sf.net/collation?class=my.custom.Collator.
  • Altova (RaptorXML): Supports standard W3C URIs along with operating system-level collations.

When developing cross-platform stylesheets, sticking to the standard http://www.w3.org/2013/collation/UCA scheme ensures the highest level of portability across conformant XSLT processors.
