Greedy vs Non-Greedy Matching in XSLT Regex

In XSLT 2.0 and later, regular expressions used in functions like replace(), matches(), and instructions like <xsl:analyze-string> support both greedy and non-greedy matching strategies. The core difference lies in how quantifiers consume input: greedy quantifiers expand to match the longest possible sequence of characters, while non-greedy (reluctant) quantifiers match the shortest possible sequence. Knowing when to apply each strategy is essential for correctly parsing delimited text, extracting XML content, and preventing unintended data capture.

Greedy Matching

By default, standard regular expression quantifiers in XSLT are greedy. These quantifiers include:

  • * (zero or more times)
  • + (one or more times)
  • ? (zero or one time)
  • {n,m} (between n and m times)

When a greedy quantifier evaluates a string, the regex engine consumes as many characters as possible up to the end of the text. It then works backward (backtracks) until it finds a point where the remainder of the pattern matches.

Greedy Example

Consider the following XML string:

<p>First</p><p>Second</p>

If you apply a greedy pattern using <xsl:analyze-string>:

<xsl:analyze-string select="$text" regex="&lt;p&gt;.*&lt;/p&gt;">
    <xsl:matching-substring>
        <match><xsl:value-of select="."/></match>
    </xsl:matching-substring>
</xsl:analyze-string>

Because .* is greedy, it starts by reading through the entire string to the final </p>. The resulting match is the entire string:

<match><p>First</p><p>Second</p></match>

Non-Greedy (Reluctant) Matching

Non-greedy matching is enabled by placing a question mark (?) directly after a quantifier:

  • *? (zero or more times, reluctant)
  • +? (one or more times, reluctant)
  • ?? (zero or one time, reluctant)
  • {n,m}? (between n and m times, reluctant)

A non-greedy quantifier consumes only the minimum number of characters necessary to satisfy the match. The engine checks the rest of the pattern after each character consumed, rather than reading to the end of the string first.

Non-Greedy Example

Using the same string (<p>First</p><p>Second</p>), modify the pattern to make the wildcard reluctant:

<xsl:analyze-string select="$text" regex="&lt;p&gt;.*?&lt;/p&gt;">
    <xsl:matching-substring>
        <match><xsl:value-of select="."/></match>
    </xsl:matching-substring>
</xsl:analyze-string>

The regex engine stops at the very first closing </p> it encounters, resulting in two separate matches:

<match><p>First</p></match>
<match><p>Second</p></match>

Practical Application in XSLT Functions

The distinction between greedy and non-greedy matching applies across standard XPath and XSLT regex operations:

  • fn:replace(): Replacing text using a greedy pattern can erase everything between the first and last occurrence of a delimiter, whereas a non-greedy pattern targets individual delimited segments.
  • fn:matches(): Greedy and non-greedy patterns return the same boolean result if a match exists anywhere in the string, but performance can vary based on the amount of backtracking required.
  • <xsl:analyze-string>: Splitting or wrapping text relies heavily on non-greedy matching to capture repeated inline structures such as markdown, quotes, or tags without merging them into a single block.
