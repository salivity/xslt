Understanding input-type-annotations in XSLT

The input-type-annotations attribute on the <xsl:stylesheet> (or <xsl:transform>) element specifies how an XSLT processor handles type annotations present in validated source documents. This article explores the purpose of input-type-annotations, explains its allowable values—preserve, strip, and unspecified—and highlights how this setting influences schema-aware processing, pattern matching, and overall execution performance.

Purpose of input-type-annotations

In schema-aware XSLT (introduced in XSLT 2.0), XML source documents can undergo schema validation prior to or during transformation. Validation assigns type annotations to nodes—such as marking an element as xs:integer or xs:date rather than untyped text.

The input-type-annotations attribute acts as a global instruction to the XSLT processor, dictating whether these validated type annotations should be retained when loading source trees into the transformation context or stripped down to basic untyped representations.

Permitted Values

The attribute accepts one of three values:

  1. preserve: The processor retains all type annotations assigned to elements and attributes during schema validation. Elements retain their specific complex or simple types, and attributes keep their validated simple types.
  2. strip: The processor strips all type annotations from the source document before evaluating any stylesheet instructions. Elements are converted to xs:untyped, and attributes are treated as xs:untypedAtomic.
  3. unspecified: This is the default setting. The processor chooses whether to preserve or strip annotations, typically relying on implementation-defined behavior or external execution parameters provided via the transformation API or command line.

Impact on XSLT Execution

The chosen value directly affects how an XSLT processor executes templates, evaluates XPath expressions, and manages memory:

  • Template Matching and Sequence Types: With preserve, you can match nodes by their schema types (e.g., <xsl:template match="element(*, xs:decimal)">). If set to strip, these matches will fail because every element is labeled as xs:untyped.
  • Atomic Value Comparisons: When annotations are preserved, arithmetic operations and comparisons execute directly on typed values. Under strip, values behave as xs:untypedAtomic, requiring implicit casting during runtime comparisons and potentially altering sorting or relational logic.
  • Function Calls: Functions expecting strongly typed parameters (such as xs:date) will accept typed nodes directly if annotations are preserved, avoiding explicit casting functions.
  • Performance and Memory: Preserving type annotations requires additional memory to store the type metadata for every node in the tree. Setting the attribute to strip can reduce memory overhead and speed up processing when a stylesheet does not require schema-aware logic.
