Shallow Copy Modes in XSLT 3.0 Explained

This article explores the purpose and functionality of shallow-copy modes (on-no-match="shallow-copy") introduced in XSLT 3.0. In earlier versions of XSLT, creating an identity transformation required writing explicit, verbose boilerplate templates to copy unchanged nodes. XSLT 3.0 streamlines this process by introducing declarative mode declarations, where on-no-match="shallow-copy" automatically reproduces the source tree structure while allowing developers to focus solely on the nodes that require modification.

The Problem with Earlier XSLT Versions

In XSLT 1.0 and 2.0, the default behavior for unmatched elements (the built-in template rule) was to process child nodes recursively while outputting only the text content, dropping all element tags and attributes.

To preserve the input structure—a pattern known as an identity transform—developers had to include a standard boilerplate template in every stylesheet:

<xsl:template match="@*|node()">
    <xsl:copy>
        <xsl:apply-templates select="@*|node()"/>
    </xsl:copy>
</xsl:template>

While functional, this approach added clutter to stylesheets, required manual management across multiple modes, and could complicate optimization and streaming scenarios.

The Purpose of on-no-match="shallow-copy"

The on-no-match attribute on the <xsl:mode> declaration defines the fallback behavior when an xsl:apply-templates instruction encounters a node with no explicit matching template rule.

Setting on-no-match="shallow-copy" instructs the XSLT processor to:

  1. Copy the current node (element, document node, comment, or processing instruction) to the result tree.
  2. Automatically copy any attributes if the current node is an element.
  3. Apply templates recursively to all child nodes and attributes.

This makes the identity transform the baseline behavior of the transformation without needing a single explicit identity template.

Basic Syntax and Usage

To activate shallow copying across an entire stylesheet, define the unnamed default mode at the top level:

<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform" version="3.0">
    <!-- Set default behavior to shallow copy -->
    <xsl:mode on-no-match="shallow-copy"/>

    <!-- Only specify templates for nodes that change -->
    <xsl:template match="price">
        <price currency="USD">
            <xsl:value-of select=". * 1.2"/>
        </price>
    </xsl:template>
</xsl:stylesheet>

In this example, every element, attribute, and text node passes through untouched, except for <price>, which is intercepted and transformed.

Key Benefits

  • Elimination of Boilerplate: Replaces multi-line identity transform templates with a single attribute on <xsl:mode>.
  • Improved Readability: Readers can immediately see what the stylesheet modifies, as there is no distracting infrastructure code.
  • Mode-Specific Defaults: Different modes can have different default behaviors (such as shallow-copy, deep-copy, fail, or text-only-copy), providing granular control across multi-pass pipelines.
  • Streamability Support: Shallow copying is designed to align with XSLT 3.0 streaming rules, allowing large XML documents to be transformed without loading the entire document into memory.
