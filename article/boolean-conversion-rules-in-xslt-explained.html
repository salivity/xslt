Boolean Conversion Rules in XSLT Explained

In XSLT and XPath, conditional elements like <xsl:if> and <xsl:when> rely on boolean evaluation to control execution flow. When an expression does not produce a native boolean value, the processor automatically applies the rules of the boolean() function—also known as determining the Effective Boolean Value (EBV). Understanding how this conversion operates on strings, node-sets, and sequences is essential for avoiding common logic errors in transformations.

String Evaluation

When the boolean() function evaluates a string, the rule is strictly based on the character length of the string:

  • Empty String (""): Evaluates to false.
  • Non-Empty String: Evaluates to true, regardless of the text content.

A frequent source of bugs occurs when checking string values like "false" or "0". Because the string 'false' has a length of five characters, boolean('false') returns true. To evaluate the semantic truth of string contents, you must explicitly compare it against a target value (e.g., my-string = 'true').

Node and Node-Set Evaluation (XPath 1.0)

In XPath 1.0, collections of nodes are treated as node-sets. The boolean evaluation of a node-set is determined solely by the presence of nodes, not by what those nodes contain:

  • Empty Node-Set: Evaluates to false. If a path expression matches no nodes in the source XML, the result is false.
  • Non-Empty Node-Set: Evaluates to true if it contains at least one node.

For example, <xsl:if test="status"> evaluates to true as long as the <status> element exists in the context, even if the element is empty (<status/>) or explicitly contains the text false (<status>false</status>). To check the content of the node rather than its existence, you must evaluate its string value (e.g., status = 'true') or its normalized length.

Sequence Evaluation (XPath 2.0, 3.0, and XSLT 2.0+)

Modern XSLT versions replace node-sets with sequences. The Effective Boolean Value (EBV) rule handles sequences using three distinct criteria:

  1. Empty Sequence: An empty sequence () always evaluates to false.
  2. Sequences Starting with a Node: If the first item in a sequence is a node (element, attribute, text node, document node, etc.), the sequence evaluates to true, regardless of how many other items exist in the sequence.
  3. Singleton Sequences of Atomic Values: If the sequence contains exactly one atomic value, standard type-specific rules apply:
    • Boolean: Retains its value (true or false).
    • String or Untyped Atomic: true if string length > 0, otherwise false.
    • Numeric: false if the value is zero (0, 0.0) or NaN; true for all other numbers.
  4. Invalid Sequences: If a sequence contains more than one item and the first item is not a node (such as a sequence of multiple integers or strings, e.g., (1, 2)), the processor raises a type error (FORG0006) rather than converting to a boolean.

Summary of Common Conversions
