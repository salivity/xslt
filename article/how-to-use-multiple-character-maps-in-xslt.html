How to Use Multiple Character Maps in XSLT

Referencing multiple character maps simultaneously in an XSLT stylesheet allows developers to cleanly manage and apply character substitution rules across serialized output. In XSLT 2.0 and later versions, this is achieved primarily by providing a whitespace-separated list of character map names to the use-character-maps attribute within an xsl:output declaration, or by composing character maps hierarchically within other xsl:character-map elements.

1. Using Multiple Character Maps in xsl:output

The most direct approach to applying multiple character maps simultaneously is listing their QNames separated by spaces in the use-character-maps attribute of the xsl:output element.

<xsl:stylesheet version="2.0" 
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

    <!-- Define the first character map -->
    <xsl:character-map name="special-symbols">
        <xsl:output-character character="&#169;" string="(c)"/>
        <xsl:output-character character="&#174;" string="(r)"/>
    </xsl:character-map>

    <!-- Define the second character map -->
    <xsl:character-map name="formatting-chars">
        <xsl:output-character character="&#160;" string="&amp;nbsp;"/>
        <xsl:output-character character="&#8212;" string="--"/>
    </xsl:character-map>

    <!-- Reference both character maps simultaneously -->
    <xsl:output method="html" 
                use-character-maps="special-symbols formatting-chars" />

    <xsl:template match="/">
        <html>
            <body>
                <xsl:text>Copyright &#169;&#160;2026&#8212;All rights reserved.</xsl:text>
            </body>
        </html>
    </xsl:template>

</xsl:stylesheet>

2. Composing Character Maps Using Inheritance

You can also create composite maps. An xsl:character-map can reference other character maps using its own use-character-maps attribute. This modular approach allows you to group logical mappings together under a single master map.

<!-- Base maps -->
<xsl:character-map name="currency-symbols">
    <xsl:output-character character="&#8364;" string="EUR"/>
    <xsl:output-character character="&#163;" string="GBP"/>
</xsl:character-map>

<xsl:character-map name="punctuation">
    <xsl:output-character character="&#8220;" string="&quot;"/>
    <xsl:output-character character="&#8221;" string="&quot;"/>
</xsl:character-map>

<!-- Master map referencing base maps and adding custom mappings -->
<xsl:character-map name="all-replacements" use-character-maps="currency-symbols punctuation">
    <xsl:output-character character="&#8482;" string="(tm)"/>
</xsl:character-map>

<!-- Output referencing the combined map -->
<xsl:output method="xml" use-character-maps="all-replacements"/>

Precedence and Conflict Resolution

When multiple character maps define a replacement string for the exact same source character, the XSLT processor resolves the conflict using defined precedence rules:

  1. List Order: If multiple maps are declared in the same use-character-maps attribute, maps that appear later in the whitespace-separated list take precedence over maps that appear earlier.
  2. Import Precedence: Character maps in importing stylesheets take precedence over character maps defined in imported stylesheets.
  3. Local Definition: If a parent character map references child maps using use-character-maps, the character mappings defined directly inside the parent map override any identical mappings imported from its referenced maps.
