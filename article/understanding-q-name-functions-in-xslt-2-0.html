Understanding QName Functions in XSLT 2.0

In XSLT 2.0, manipulating XML identifiers often involves working with the strongly typed xs:QName data type. This article provides a focused explanation of local-name-from-QName() and namespace-uri-from-QName(), two functions designed to deconstruct qualified names into their core components. You will learn why these functions exist, how they differ from legacy node-inspection functions, and how to use them effectively in stylesheet transformations.

The Role of xs:QName in XSLT 2.0

Unlike XSLT 1.0, where qualified names were typically handled as plain strings or inspected directly from node trees, XSLT 2.0 uses the XPath 2.0 type system. A qualified name can exist as an instance of the xs:QName atomic type, consisting of a namespace URI, a local name, and an optional prefix. Because an xs:QName is an atomic value rather than an XML node, standard node functions like local-name() and namespace-uri() cannot accept it as an argument.

Purpose of local-name-from-QName()

The local-name-from-QName() function extracts the local part of an xs:QName value.

  • Signature: fn:local-name-from-QName($arg as xs:QName?) as xs:NCName?
  • Behavior: It takes an xs:QName and returns an xs:NCName representing the local name without any prefix or namespace context. If the input is an empty sequence, the function returns an empty sequence.

This function is essential when you obtain a QName dynamically—such as from node-name(), resolve-QName(), or xs:QName()—and need to perform string comparisons or generate new elements using only the local portion of that name.

Purpose of namespace-uri-from-QName()

The namespace-uri-from-QName() function extracts the namespace URI part of an xs:QName value.

  • Signature: fn:namespace-uri-from-QName($arg as xs:QName?) as xs:anyURI?
  • Behavior: It takes an xs:QName and returns the namespace URI as an xs:anyURI. If the QName is in no namespace, it returns an empty sequence. If the argument is an empty sequence, the function also returns an empty sequence.

This function ensures robust namespace evaluation. Because prefixes in XML are arbitrary and vary across documents, extracting and comparing the URI ensures that elements and attributes are matched accurately according to their true namespace identity.

Practical Example

When inspecting nodes using the node-name() function, an xs:QName is returned. The extraction functions separate the components cleanly:

<xsl:variable name="elementQName" select="node-name(.)" />
<xsl:variable name="localPart" select="local-name-from-QName($elementQName)" />
<xsl:variable name="uriPart" select="namespace-uri-from-QName($elementQName)" />

<xsl:if test="$uriPart = 'http://example.com/schema' and $localPart = 'target'">
    <!-- Transformation logic -->
</xsl:if>

Summary of Benefits

  • Type Safety: Directly handles xs:QName instances without requiring implicit or explicit string casting.
  • Prefix Independence: Allows you to isolate and validate the namespace URI independently of whatever transient prefix was declared in the source XML.
  • Component Extraction: Simplifies the process of decomposing typed QNames for logging, dynamic XML generation, or schema validation logic.
