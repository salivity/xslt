Using XSLT 3.0 in .NET with Saxon and IKVM

The standard .NET runtime provides native support only for XSLT 1.0, leaving modern C# developers without built-in access to modern transformation specifications. To overcome this limitation, third-party libraries bridge the gap by bringing Saxon—the reference implementation for advanced XSLT specifications—into the .NET ecosystem using byte-code translation technologies like IKVM. This article explores how cross-compiling Java-based Saxon into .NET assemblies enables XSLT 3.0 functionality, the architectural mechanisms behind this approach, and how developers can integrate it into modern applications.

The Native .NET XSLT Limitation

Microsoft's native implementation, System.Xml.Xsl.XslCompiledTransform, is strictly confined to the XSLT 1.0 recommendation from 1999. While fast and deeply integrated into the framework, it lacks modern constructs such as:

  • Native JSON parsing, querying, and serialization (fn:json-to-xml, fn:xml-to-json).
  • Streaming transformations for multi-gigabyte files without loading the entire document into memory.
  • Advanced programming features, including packages, modular stylesheets, try/catch exception handling, and higher-order functions.

Because Microsoft has not updated its core XSLT engine to support XSLT 2.0 or 3.0, developers must rely on third-party engines to process contemporary stylesheets.

How IKVM Bridges Java and .NET

Saxon, developed by Saxonica, is the primary implementation of XSLT 3.0 and XPath 3.1. Historically written in Java, bringing its open-source edition (Saxon-HE) to .NET requires converting Java bytecode into Common Intermediate Language (CIL).

This is where IKVM comes in. IKVM is an implementation of Java for the Microsoft .NET platform that includes:

  1. A Bytecode Compiler (ikvmc): Translates Java .class and .jar files directly into .NET .dll assemblies.
  2. A Java Class Library Port: Re-implements the core Java runtime environment (JDK classes) natively on top of the .NET CLR.

By compiling Saxon's JAR files through IKVM, developers obtain a set of .NET assemblies that execute inside the CLR without requiring an external Java Runtime Environment (JRE) installed on the host machine.

Integration and Usage in C#

Community-maintained packages deliver IKVM-compiled Saxon-HE directly via NuGet. Once referenced, developers can interact with the transformation engine using standard C# syntax:

using Saxon.Api;
using System.IO;

public class Xslt3Transformer
{
    public static void Transform(string xmlPath, string xsltPath, string outputPath)
    {
        // Initialize the Saxon Processor
        var processor = new Processor();
        var compiler = processor.NewXsltCompiler();

        // Compile the XSLT 3.0 stylesheet
        var executable = compiler.Compile(new Uri(xsltPath));
        var transformer = executable.Load30();

        // Execute transformation
        using var inputStream = File.OpenRead(xmlPath);
        using var outputStream = File.Create(outputPath);
        
        var serializer = processor.NewSerializer(outputStream);
        transformer.ApplyTemplates(inputStream, serializer);
    }
}

The Saxon.Api namespace provides strongly typed wrappers around the compiled Java classes, exposing idiomatic interfaces for compiling stylesheets, managing parameters, handling errors, and executing queries.

Advantages of the IKVM Saxon Approach

  • Full XSLT 3.0 Compliance: Unlocks full compatibility with modern stylesheets, including dynamic evaluation and XPath 3.1 map and array manipulation.
  • Open-Source Availability: Saxon-HE (Home Edition) is free and open-source, making it cost-effective for projects that require modern XSLT without commercial licensing.
  • No Java Dependency: End users and deployment environments do not need a JRE or JDK installed; everything runs as native .NET dependencies within the application directory.

Practical Considerations and Alternatives

While IKVM-compiled Saxon provides full XSLT 3.0 capabilities, developers should consider a few trade-offs:

  • Assembly Footprint: Including IKVM and the Java runtime compatibility libraries adds several megabytes of dependencies to the application.
  • Performance: While execution performance is generally high, cross-compiled code can experience slightly longer cold-start compilation times compared to pure native CIL implementations.
  • SaxonCS Alternative: Saxonica provides a commercial, fully native .NET implementation called SaxonCS. Built using cross-compilation technology that targets native C# source code rather than runtime emulation, SaxonCS offers superior performance and commercial support, though it requires a paid license.

For teams requiring free, open-source compliance with modern transformation standards, IKVM-compiled Saxon remains the primary bridge connecting .NET applications to the modern XSLT 3.0 ecosystem.
