Using XSLT 2.0 Character Maps for Custom Entities

This guide demonstrates how to configure character maps in XSLT 2.0 to output custom named entity strings or raw characters. Standard XSLT serialization automatically escapes characters like & into &amp;, preventing the direct output of custom XML or HTML entities. By using <xsl:character-map> in conjunction with the <xsl:output> declaration, you can bypass default escaping and map specific Unicode characters directly to custom entity strings during serialization.

The Purpose of Character Maps

During the serialization phase of an XSLT transformation, processors normally escape markup-significant characters to maintain well-formedness. In scenarios where you need to preserve specific named entities (such as &nbsp;, &copyright;, or application-specific DTD entities) instead of their numeric or resolved character equivalents, character maps provide a standards-compliant mechanism to dictate exact string outputs without resorting to deprecated features like disable-output-escaping.

Step-by-Step Configuration

To generate custom entity strings, you define a top-level <xsl:character-map> element containing one or more <xsl:output-character> definitions, and then associate that map with your <xsl:output> declaration.

1. Define the Character Map

Place the <xsl:character-map> element at the top level of your stylesheet (as a child of <xsl:stylesheet>). Each mapping requires two attributes:

  • character: The single character that should be intercepted during serialization.
  • string: The exact string literal that replaces the character in the final serialized output.
<xsl:character-map name="custom-entities">
    <!-- Map the non-breaking space character to its entity string -->
    <xsl:output-character character="&#160;" string="&amp;nbsp;" />
    
    <!-- Map a custom symbol or placeholder to a custom entity string -->
    <xsl:output-character character="&#xE000;" string="&amp;customEntity;" />
</xsl:character-map>

Note: The & in the string attribute must be written as &amp; inside the XSLT stylesheet because the stylesheet itself must be well-formed XML.

2. Apply the Map to the Output

Link the character map to your output configuration by adding the use-character-maps attribute to the <xsl:output> element:

<xsl:output method="xml" 
            indent="yes" 
            encoding="UTF-8" 
            use-character-maps="custom-entities" />

Full Working Example

In practice, developers often use characters from the Unicode Private Use Area (such as &#xE000; through &#xF8FF;) as transient placeholders to guarantee that normal text characters are not replaced unintentionally.

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="2.0" 
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

    <!-- Define the character map -->
    <xsl:character-map name="entity-map">
        <xsl:output-character character="&#160;" string="&amp;nbsp;" />
        <xsl:output-character character="&#xE001;" string="&amp;myCustomEntity;" />
    </xsl:character-map>

    <!-- Instruct the serializer to use the map -->
    <xsl:output method="xml" 
                encoding="UTF-8" 
                indent="yes" 
                use-character-maps="entity-map" />

    <!-- Transformation template -->
    <xsl:template match="/">
        <root>
            <item>Standard Space</item>
            <item>Non-breaking:&#160;</item>
            <item>Custom:&#xE001;</item>
        </root>
    </xsl:template>

</xsl:stylesheet>

Serialized Output

When the transformation runs, the XSLT processor emits the replacement strings directly into the final stream without escaping the ampersand:

<?xml version="1.0" encoding="UTF-8"?>
<root>
    <item>Standard Space</item>
    <item>Non-breaking:&nbsp;</item>
    <item>Custom:&myCustomEntity;</item>
</root>

Key Considerations

  • Serialization Only: Character maps only take effect during serialization. They do not alter nodes within the internal XSLT tree representation.
  • Multiple Maps: The use-character-maps attribute accepts a whitespace-separated list of map names, which are evaluated in the order they are listed.
  • Well-Formedness: While character maps allow raw strings like &customEntity; in the output, ensure your downstream consumer or parser has the corresponding DTD or entity declarations to parse the output document correctly.
