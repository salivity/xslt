How SaxonJS Handles Browser DOM Events in XSLT

SaxonJS bridges the gap between functional XSLT 3.0 transformations and the browser's event-driven runtime through its Interactive XSLT (IXSL) extension architecture. Instead of treating XSLT as a one-pass transformation engine, SaxonJS allows stylesheets to attach template rules directly to browser Document Object Model (DOM) events, inspect event payloads, modify the existing page DOM in place, and communicate bidirectionally with JavaScript APIs.

The Interactive XSLT (IXSL) Namespace

Event interaction in SaxonJS relies on the IXSL namespace (http://saxonica.com/ns/interactiveXSLT). This namespace exposes extension functions, attributes, and template modes designed for browser execution. By defining the namespace prefix (commonly ixsl), stylesheets can intercept standard HTML events such as clicks, form changes, keystrokes, and lifecycle notifications.

Binding Templates to DOM Events

SaxonJS binds template rules to DOM events using specialized template modes that correspond to native browser event handlers. When an event fires, the SaxonJS runtime matches the event target against templates declared with the matching ixsl:on* mode.

<xsl:template match="button[@id='submit-btn']" mode="ixsl:onclick">
    <!-- Action executed when the button is clicked -->
</xsl:template>

When SaxonJS renders elements into the DOM, it automatically attaches the appropriate event listeners behind the scenes. Developers do not need to call addEventListener manually in JavaScript; the compiled SaxonJS SEF (Stylesheet Execution Facility) processor wires the event directly to the matching template rule.

Inspecting Event Data

When an event triggers a template, developers can access the native browser Event object using the ixsl:event() function. SaxonJS allows XPath 3.1 expressions to traverse the event properties directly using dynamic lookup (?) or the ixsl:get() function.

  • Accessing Targets: Retrieve the triggering element using ixsl:event()?target.
  • Accessing Input Values: Read user input using ixsl:event()?target?value.
  • Mouse and Keyboard Details: Retrieve properties like ixsl:event()?clientX, ixsl:event()?key, or modifier states.
  • Preventing Default Actions: Cancel native browser actions (such as form submission or link navigation) by calling native methods on the event: 
    <xsl:sequence select="ixsl:call(ixsl:event(), 'preventDefault', [])"/>

Modifying the DOM in Response to Events

Standard XSLT generates a new result tree, but client-side interaction requires mutating the existing page. SaxonJS accomplishes this via the xsl:result-document instruction configured with IXSL-specific output methods and targets.

  • Targeting DOM Nodes: The href attribute accepts URI-like selectors, such as ?select expressions or ID fragment identifiers (#my-container), to determine where the output is placed.
  • Update Modes: The method attribute determines how the targeted DOM is manipulated:
    • ixsl:replace-content: Replaces the inner HTML/nodes of the target.
    • ixsl:append-content: Appends children to the target.
    • ixsl:insert-before / ixsl:insert-after: Injects nodes adjacent to the target.
    • ixsl:delete: Removes the targeted node from the DOM.
<xsl:template match="input[@type='text']" mode="ixsl:oninput">
    <xsl:result-document href="#preview-pane" method="ixsl:replace-content">
        <p><xsl:value-of select="ixsl:event()?target?value"/></p>
    </xsl:result-document>
</xsl:template>

Asynchronous Operations and Custom Events

SaxonJS coordinates asynchronous browser behavior through the <ixsl:schedule-action> instruction. This instruction supports:

  • Timers: Setting timeouts or intervals directly from XSLT.
  • HTTP Fetch Operations: Executing asynchronous HTTP requests and handling the response within an XSLT template once completed.

Beyond standard native events (click, change, keydown), SaxonJS can handle and dispatch custom DOM events. Stylesheets can listen for CustomEvent instances emitted by third-party JavaScript libraries via mode="ixsl:oncustom-event-name". Conversely, an XSLT template can use ixsl:call() to instantiate and dispatch a native CustomEvent on any DOM node, signaling external JavaScript components that an internal XSLT state change has occurred.
