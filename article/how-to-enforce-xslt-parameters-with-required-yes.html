How to Enforce XSLT Parameters with required="yes"

This article explains how the required="yes" attribute functions in XSLT 2.0 and later versions to enforce mandatory parameter passing. In earlier versions of XSLT, parameters were inherently optional, often leading to silent failures or unintended default states when callers omitted necessary values. By setting required="yes" on an <xsl:param> element, stylesheet authors can turn parameter omissions into immediate processor errors, ensuring template and stylesheet contracts are strictly maintained.

In XSLT 1.0, all parameters declared via <xsl:param> were optional. If a caller failed to provide a value using <xsl:with-param>, the processor simply evaluated the parameter’s default value or fell back to an empty string. XSLT 2.0 addressed this limitation by introducing the required attribute, which accepts either "yes" or "no". Marking a parameter with required="yes" makes the parameter mandatory for any caller invoking that template or stylesheet.

When a parameter is designated as required, the XSLT processor enforces its presence at execution time or during static analysis. If an <xsl:call-template> or <xsl:apply-templates> instruction fails to supply the required parameter via <xsl:with-param>, the processor halts execution and raises a dynamic error (specifically error code XTDE0700). If an XSLT processor supports static analysis and can determine ahead of time that a named template call lacks a required parameter, it can flag the issue before stylesheet evaluation even begins.

The enforcement rule also applies to global stylesheet parameters. When required="yes" is specified on a top-level <xsl:param> element, the external transformation environment—such as a command-line interface, Ant task, or programming language API—must supply that parameter. If the execution environment does not provide the value, the processor generates a fatal error.

To ensure consistency, XSLT rules prohibit a required parameter from having a default value. An <xsl:param> element configured with required="yes" cannot include a select attribute or contain any child nodes. If an author attempts to provide both required="yes" and a default value, the processor rejects the stylesheet with a static error (error code XTSE0010).

Using required="yes" combines effectively with the as attribute for strong data typing. Declaring both attributes ensures not only that a value is passed, but that it matches the expected data type, leading to safer, more robust, and self-documenting XSLT code.
