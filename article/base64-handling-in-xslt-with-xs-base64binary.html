Base64 Handling in XSLT with xs:base64Binary

This article explores how XSLT handles base64 binary encoding and decoding using the built-in XML Schema data type xs:base64Binary. It explains the mechanics of the xs:base64Binary constructor, clarifies common misconceptions regarding string-to-binary transformation, and outlines the practical steps required to process, convert, and output base64 data within XSLT 2.0 and 3.0 stylesheets.

The Role of xs:base64Binary

In XSLT 2.0 and later, the XML Schema namespace (xmlns:xs="http://www.w3.org/2001/XMLSchema") provides standard atomic types for binary representations: xs:base64Binary and xs:hexBinary.

The xs:base64Binary type represents arbitrary Base64-encoded data as defined by RFC 2045. When used as an atomic data type within XSLT and XPath, it validates and encapsulates data strictly conforming to the Base64 alphabet (A–Z, a–z, 0–9, +, /, and = for padding).

The xs:base64Binary Constructor

The constructor function xs:base64Binary($input) creates an instance of the binary type. The $input argument must be one of two things:

  1. A string that already contains valid Base64-encoded lexical data.
  2. An instance of xs:hexBinary.
<!-- Creating an xs:base64Binary item from a pre-encoded string -->
<xsl:variable name="base64Item" select="xs:base64Binary('SGVsbG8gV29ybGQ=')"/>

The Common Plain-Text Misconception

A common point of confusion is assuming xs:base64Binary('Hello World') will encode the plain-text string "Hello World" into Base64. It does not.

Because "Hello World" contains a space and characters that do not conform to valid Base64 padding and framing, passing raw plain text to the constructor causes a dynamic error: FORG0001: Cannot convert string to xs:base64Binary. The constructor does not transform text into bytes; it parses an existing Base64 lexical stream into an atomic representation.

Decoding Base64 in XSLT

Decoding Base64 data involves taking a Base64-encoded string and converting it into readable text or raw bytes.

1. Converting to Hexadecimal (XPath 2.0+)

Standard XPath and XSLT provide direct casting between xs:base64Binary and xs:hexBinary. This allows you to inspect and manipulate the underlying octets:

<xsl:variable name="base64Data" select="xs:base64Binary('SGVsbG8=')"/>
<xsl:variable name="hexData" select="xs:hexBinary($base64Data)"/>
<!-- Output: 48656c6c6f -->
<xsl:value-of select="$hexData"/>

2. Decoding to Plain Text

Standard XSLT 2.0 does not include a direct function to translate raw octets into a Unicode string without extension functions. However, XSLT 3.0 and the EXPath Binary Module bridge this gap:

  • XSLT 3.0 / XPath 3.1 with EXPath: The bin:decode-string($base64Data, 'UTF-8') function takes an xs:base64Binary value and decodes it directly into a standard text string.
  • XSLT 3.0 Native Parsing: If the Base64 data contains an embedded XML or JSON document, XSLT 3.0 allows decoding and parsing simultaneously using fn:parse-xml() or fn:json-doc() paired with URI resolvers or extensions provided by processors like Saxon.

Encoding to Base64 in XSLT

Encoding raw data into Base64 requires producing an xs:base64Binary instance from an alternate format.

1. Cross-Casting from Hexadecimal

If data is already available in hexadecimal format (e.g., hash outputs or binary payloads), it can be cast directly to xs:base64Binary:

<xsl:variable name="hexString" select="xs:hexBinary('48656c6c6f')"/>
<xsl:variable name="base64Data" select="xs:base64Binary($hexString)"/>
<xsl:variable name="encodedString" select="string($base64Data)"/>
<!-- Output: SGVsbG8= -->
<xsl:value-of select="$encodedString"/>

2. Encoding Strings in XSLT 3.0

To encode plain text into Base64 natively in modern processing pipelines, use the EXPath binary extension or the bin:encode-string() function supported by modern XSLT 3.0 processors:

<xsl:variable name="encoded" select="bin:encode-string('Hello World', 'UTF-8')"/>
<!-- Result is an xs:base64Binary instance -->
<xsl:value-of select="string($encoded)"/>

Summary of Operational Rules

  • Validation: Calling xs:base64Binary() on an invalid Base64 string results in a dynamic type error (FORG0001).
  • Serialization: Casting an xs:base64Binary item back to xs:string via string() or xs:string() returns the normalized, properly padded Base64 representation.
  • Interoperability: xs:base64Binary values seamlessly cast to and from xs:hexBinary, allowing byte-level inspection across standard XSLT 2.0 and 3.0 processors without third-party plugins.
