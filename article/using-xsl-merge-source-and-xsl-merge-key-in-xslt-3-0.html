Using xsl:merge-source and xsl:merge-key in XSLT 3.0

XSLT 3.0 introduced the <xsl:merge> instruction to efficiently combine two or more pre-sorted input streams without requiring the entire datasets to be held in memory. Within this framework, <xsl:merge-source> defines the individual input sequences and their properties, while <xsl:merge-key> specifies the criteria used to align and match records across those sources. Together, these elements allow stylesheets to perform high-performance, streamable merge and join operations on large XML documents.

The Role of <xsl:merge-source>

The <xsl:merge-source> element defines an input stream that contributes items to the merge operation. You can declare multiple <xsl:merge-source> elements within a single <xsl:merge> block to merge data from different documents or sequences.

Key functions and attributes include:

  • Defining the Input Sequence: The select attribute provides an XPath expression indicating the sequence of items to process from this source. When streaming, the for-each-stream or for-each-source attributes can be used to read external documents progressively.
  • Source Identification: The name attribute assigns an identifier to the merge source. This identifier is used later within <xsl:merge-action> via the xsl:merge-source-identifier() function to determine which source a given item originated from.
  • Sort Order Enforcement: The sort-satisfied attribute (defaulting to no) indicates whether the input sequence is already guaranteed to be in the order defined by the merge keys. If set to no, the XSLT processor will ensure the data is sorted before merging.

The Role of <xsl:merge-key>

The <xsl:merge-key> element declares the comparison key used to sequence and correlate items across the different merge sources. It is placed inside an <xsl:merge-source> element to define source-specific keys, or placed directly within <xsl:merge> to define a common key for all sources.

Key functions and attributes include:

  • Key Extraction: The select attribute defines the expression evaluated against each context item to extract the key value used for ordering and matching.
  • Comparison Control: Similar to <xsl:sort>, it provides attributes such as data-type (e.g., text or number), order (ascending or descending), case-order, and collation to strictly define how key values are compared.
  • Multiple Keys: Multiple <xsl:merge-key> elements can be defined sequentially to handle composite keys (for example, merging first by last-name, then by first-name).

How They Work Together

During execution, the XSLT processor evaluates the <xsl:merge-key> values for the current items of each <xsl:merge-source>. The processor identifies the lowest key value according to the specified sort rules, groups all items from all sources sharing that key value, and makes them available within the <xsl:merge-action> child element.

Within <xsl:merge-action>, functions such as current-merge-group() and current-merge-key() allow developers to access the correlated records and generate merged output. Once the action block completes, the processor advances only the sources that contributed to the processed key, repeating the cycle until all inputs are exhausted.
