Role of the indent Attribute in XSLT Output

The indent attribute on the <xsl:output> element dictates whether an XSLT processor should introduce additional whitespace to format the resulting XML document. By toggling this attribute between yes and no, developers control whether the generated output is pretty-printed with line breaks and indentation for human readability or kept compact to preserve strict whitespace boundaries and reduce payload size.

Syntax and Values

The indent attribute is declared directly inside the top-level <xsl:output> element:

<xsl:output method="xml" indent="yes" encoding="UTF-8"/>

The attribute accepts two standard values:

  • yes: Authorizes the XSLT processor to add extra whitespace (such as newlines, spaces, and tabs) to visually indent child nodes relative to their parents.
  • no (default for the xml method): Instructs the processor not to introduce any arbitrary whitespace during serialization.

How indent="yes" Works

When set to yes, the processor visually structures the document hierarchy. This makes deeply nested XML documents significantly easier for developers to read, inspect, and debug.

However, the W3C XSLT specification deliberately leaves the exact formatting style implementation-dependent. The specification does not mandate the number of spaces per indentation level, nor does it specify whether tabs or spaces should be used. While standard XSLT does not provide an attribute to specify the exact indentation step (e.g., two spaces versus four spaces), many processors provide proprietary attributes for this purpose, such as saxon:indent-spaces in the Saxon processor.

How indent="no" Works

When set to no, the output contains only the whitespace explicitly generated by literal text nodes, templates, or preserved from the source document using <xsl:preserve-space>.

Using indent="no" is essential in the following scenarios:

  • Machine-to-Machine Transmission: Eliminating non-essential formatting whitespace reduces total file size, saving network bandwidth and memory during parsing.
  • Whitespace-Sensitive Applications: In formats where inter-element whitespace affects rendering or semantics (such as mixed-content models containing inline markup), automatic indentation can inadvertently alter the meaning of the data.

Impact on Whitespace and Mixed Content

The XSLT specification warns processors against adding whitespace where it might change the document's meaning. Consequently, well-behaved processors will suppress indentation within elements containing mixed content (elements containing both text and child elements) or elements governed by xml:space="preserve". Even with indent="yes" enabled, the processor preserves the integrity of text nodes inside such elements to prevent data corruption.
