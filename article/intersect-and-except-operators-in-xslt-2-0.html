Intersect and Except Operators in XSLT 2.0

In XSLT 2.0, the intersect and except operators provide powerful set-manipulation capabilities for node sequences. This article explains the specific purpose of these two operators, how they evaluate node identity and document order, and how they allow developers to perform precise sequence comparisons and filtering without complex XPath workarounds.

The Purpose of intersect

The intersect operator takes two sequences of nodes and returns a new sequence containing only the nodes that are present in both sequences.

In XSLT 1.0, finding common nodes between two sets required cumbersome predicates using node identity tests (such as comparing generate-id() or counting node intersections). In XSLT 2.0, the syntax is simplified:

$sequenceA intersect $sequenceB

The resulting sequence contains only the elements, attributes, or other nodes that appear in both $sequenceA and $sequenceB.

The Purpose of except

The except operator takes two sequences of nodes and returns a new sequence containing all the nodes from the first sequence that do not appear in the second sequence. It functions as a set difference or subtraction operation.

$sequenceA except $sequenceB

This operator is commonly used to exclude specific elements, such as selecting all child nodes except for certain metadata elements, or processing a collection of nodes while omitting items that match an exclusion list.

Key Operational Rules

To use intersect and except effectively, you must understand how XSLT processes them:

  1. Node Identity, Not Value: Both operators evaluate nodes based on node identity, not string or typed values. Two nodes are considered identical only if they represent the exact same node in the XML tree hierarchy. Nodes with identical tag names, attributes, and text content are treated as distinct if they are located at different positions in the source tree.
  2. Nodes Only: Both operators require both operands to be sequences of nodes (node()*). Passing sequences containing atomic values (such as strings, integers, or dates) results in a type error (XPTY0004).
  3. Deduplication and Document Order: Like the union operator (or |), both intersect and except automatically eliminate duplicate nodes from the final result and return the remaining nodes sorted in document order.
