Axis Restrictions in XSLT 3.0 Streamable Templates

XSLT 3.0 introduces streaming to process XML documents larger than available memory, requiring transformation engines to read documents sequentially in a single pass. To guarantee single-pass execution without caching the entire tree, XSLT 3.0 strictly restricts the use of XPath axes within streamable template rules. Expressions inside these templates are categorized by their streamability posture and sweep, allowing certain forward and motionless navigations while prohibiting reverse and forward-lateral tree traversal.

The Underlying Streaming Principle

In a streamable template rule, the context item represents a node in a document that is read sequentially from start to finish. Once an element's closing tag passes, that element can no longer be accessed without storing it in memory. Therefore, XPath expressions evaluated against a streamed context node cannot look backward into the document or leap arbitrarily ahead across sibling elements.

Motionless Axes: attribute, namespace, and self

The safest axes in streaming mode are motionless axes:

  • attribute:: (or @)
  • namespace::
  • self:: (or .)

These axes do not advance the stream cursor down into the child hierarchy or consume child content. When a processor encounters a start tag, attributes and namespaces are already available in the current parsing buffer. Consequently, these axes have a motionless sweep, allowing templates to inspect attributes and namespace declarations repeatedly without violating streaming constraints.

Child and Descendant Axes: Consuming Navigation

The child:: and descendant:: axes advance the read pointer and are classified as consuming operations:

  • The child axis: Navigation to child elements (child::* or simply *) changes the posture of the expression from striding to a deeper level. Because reading child elements consumes the stream, a streamed template can typically execute only one consuming evaluation per context node. Attempting to iterate over the child:: axis multiple times inside the same template generates a static streamability error.
  • The descendant axis: The descendant:: axis (or //) transitions the posture to crawling. While permitted under specific conditions, accessing children of a crawling node is prohibited because it implies buffering variable-depth nodes concurrently.

Prohibited Axes: Reverse and Lateral Traversal

To maintain zero-buffering single-pass guarantees, XSLT 3.0 prohibits or heavily restricts the following axes on streamed nodes:

  • Reverse axes: parent::, ancestor::, ancestor-or-self::, preceding::, and preceding-sibling::. These axes require navigating backwards in document order, which is impossible in a linear stream where prior nodes have been discarded. (Ancestral data must instead be captured proactively using xsl:accumulator.)
  • Lateral axes: following:: and following-sibling::. Evaluating these axes requires buffering forward nodes while maintaining the current context node, breaking the sequential consumption model.

Overcoming Axis Restrictions with Grounding

When arbitrary axis navigation is necessary within a streaming transformation, the stream must be explicitly grounded using functions such as snapshot() or copy-of().

Calling copy-of(.) or snapshot(.) builds a standard, in-memory DOM tree of the current element or subtree. Once a node is grounded, its posture becomes grounded, lifting all axis restrictions and allowing full use of parent, sibling, and reverse axes on that specific sub-tree.
