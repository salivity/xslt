What Is TEI and How Does XSLT Render Scholarly Texts?

The Text Encoding Initiative (TEI) is the foundational standard for encoding complex textual sources in the digital humanities, utilizing specialized XML to capture the deep structural, linguistic, and critical features of historical and literary manuscripts. Because TEI XML emphasizes scholarly semantics rather than visual display, modern web browsers cannot render it effectively on their own. Extensible Stylesheet Language Transformations (XSLT) bridge this gap by functioning as a translation engine, transforming raw, semantically rich TEI XML files into accessible, interactive formats such as HTML, EPUB, or print-ready PDF.

What Is the Text Encoding Initiative (TEI)?

Established in 1987, the Text Encoding Initiative develops and maintains standard guidelines for representing machine-readable texts. Rather than focusing on fonts, colors, or page margins, TEI uses XML tags to capture the meaning and history of a document.

A standard TEI document contains two core parts:

  • The <teiHeader>: Comprehensive metadata describing the electronic file, the source document, the encoding principles applied, and the revision history.
  • The <text> element: The actual document, marked up to represent structural divisions (chapters, poems, scenes) as well as critical editorial phenomena.

In scholarly editing, standard HTML is insufficient because it lacks the vocabulary to describe paleographical nuances, editorial interventions, and textual variations across multiple manuscript witnesses. TEI solves this by providing specialized elements. For example, it can record scribal deletions and additions (<del> and <add>), encode personal and geographic names (<persName> and <placeName>), or represent an apparatus criticus (<app>, <rdg>) that documents variant readings across historical copies.

The Role of XSLT in Processing TEI

Because TEI separates content and semantics from visual presentation, the markup itself contains no layout instructions. A web browser encountering a tag like <persName> does not know whether to render it as bold text, a hyperlink, or a tooltip. This is where XSLT becomes essential.

XSLT is a declarative, template-based programming language specifically designed to transform XML documents into other XML documents, HTML, or plain text. In the context of scholarly editions, an XSLT stylesheet evaluates the hierarchy of the TEI XML file using XPath queries, identifies specific elements, and generates corresponding markup for display.

How XSLT Translates TEI into Formatted Output

XSLT operates on a rule-based model known as template matching. When an XSLT processor (such as Saxon) evaluates a TEI document against a stylesheet, it follows these mechanisms:

  1. Mapping Semantic Tags to Presentation Tags:
    Simple structural elements are directly translated into web components. For instance, an XSLT rule can match a TEI paragraph (<p>) and output an HTML paragraph (<p>), or match a division (<div type="chapter">) and wrap it in an HTML <section> with an appropriate heading.

  2. Handling Complex Critical Markup:
    Scholarly editions frequently need to present alternative views of a text. A scholar may encode an original manuscript error alongside a corrected version using the <choice>, <sic>, and <corr> elements:

    <choice>
    <sic>recieve</sic>
    <corr>receive</corr>
</choice>

    An XSLT template can process this structure to output the corrected word in the main text while automatically placing the original scribal error into an interactive tooltip or an apparatus note at the bottom of the page.

  3. Extracting and Organizing Metadata:
    XSLT extracts administrative data from the <teiHeader>—such as manuscript shelfmarks, transcribers, and publication dates—and formats it into structured landing pages, bibliographies, or citation blocks for researchers.

  4. Generating Navigation and Indices:
    Because XSLT can traverse the entire document tree, it can gather all instances of specific tags (such as every <persName> or <placeName>) to automatically construct a table of contents, a comprehensive index of historical figures, or a gazetteer linked back to the exact occurrences within the text.

The Standard Scholarly Publishing Pipeline

The combination of TEI and XSLT creates a resilient, future-proof publishing pipeline. Scholars encode the text once in TEI XML, preserving it in an archival, platform-independent format.

When publishing, an XSLT processor can run server-side, client-side in the browser, or during a static-site generation build step. Multiple distinct stylesheets can be applied to the exact same source file: one stylesheet can generate a diplomatic view that preserves original lineation and scribal quirks, another can generate a normalized reading edition for students, and a third can convert the text via XSL-FO into a camera-ready PDF for print publication. Through XSLT, complex textual research becomes usable, readable, and widely distributable across modern digital platforms.
