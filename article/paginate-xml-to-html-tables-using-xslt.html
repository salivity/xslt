Paginate XML to HTML Tables Using XSLT

Transforming a large XML catalog into paginated HTML tables is a practical way to manage large datasets, prevent browser performance bottlenecks, and improve user readability. By using XSLT (Extensible Stylesheet Language Transformations), you can batch XML records into fixed-size chunks, either outputting multiple HTML table elements within a single document or generating separate, paginated HTML files using native grouping functions and positional predicates.

The Strategy: Chunking by Position

To paginate an XML dataset, the stylesheet must divide records into equal batches based on a designated page size.

  • XSLT 2.0 and 3.0 handle this natively using the <xsl:for-each-group> element combined with integer division (idiv).
  • XSLT 1.0 relies on the Muenchian method or matching elements where the position satisfies position() mod $pageSize = 1, then selecting sibling nodes.

Method 1: Using XSLT 2.0 / 3.0 (xsl:for-each-group)

The standard modern approach calculates a page index for each record based on its position, grouping records that share the same page index.

Sample XML Catalog

<catalog>
    <product><id>101</id><name>Keyboard</name><price>49.99</price></product>
    <product><id>102</id><name>Mouse</name><price>29.99</price></product>
    <product><id>103</id><name>Monitor</name><price>199.99</price></product>
    <product><id>104</id><name>Headset</name><price>79.99</price></product>
    <!-- Additional products -->
</catalog>

XSLT 2.0/3.0 Stylesheet

<xsl:stylesheet version="2.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="html" encoding="UTF-8" indent="yes"/>

    <!-- Set records per page -->
    <xsl:param name="pageSize" select="2"/>

    <xsl:template match="/catalog">
        <html>
            <head>
                <title>Paginated Catalog</title>
                <style>
                    .page-table { margin-bottom: 30px; border-collapse: collapse; width: 100%; }
                    .page-table th, .page-table td { border: 1px solid #ccc; padding: 8px; }
                </style>
            </head>
            <body>
                <!-- Group records by calculating page index -->
                <xsl:for-each-group select="product" group-by="(position() - 1) idiv $pageSize">
                    <h2>Page <xsl:value-of select="position()"/></h2>
                    <table class="page-table">
                        <thead>
                            <tr>
                                <th>ID</th>
                                <th>Name</th>
                                <th>Price</th>
                            </tr>
                        </thead>
                        <tbody>
                            <!-- Iterate over all items in the current page group -->
                            <xsl:for-each select="current-group()">
                                <tr>
                                    <td><xsl:value-of select="id"/></td>
                                    <td><xsl:value-of select="name"/></td>
                                    <td>$<xsl:value-of select="price"/></td>
                                </tr>
                            </xsl:for-each>
                        </tbody>
                    </table>
                </xsl:for-each-group>
            </body>
        </html>
    </xsl:template>
</xsl:stylesheet>

Method 2: Generating Multiple HTML Files

If the dataset is too large for a single HTML file, use the <xsl:result-document> instruction in XSLT 2.0/3.0 to output a discrete HTML file for each page.

<xsl:template match="/catalog">
    <xsl:for-each-group select="product" group-by="(position() - 1) idiv $pageSize">
        <xsl:variable name="pageNum" select="position()"/>
        
        <xsl:result-document href="catalog-page-{$pageNum}.html" method="html">
            <html>
                <head><title>Catalog - Page <xsl:value-of select="$pageNum"/></title></head>
                <body>
                    <h2>Page <xsl:value-of select="$pageNum"/></h2>
                    <table>
                        <tr><th>ID</th><th>Name</th><th>Price</th></tr>
                        <xsl:for-each select="current-group()">
                            <tr>
                                <td><xsl:value-of select="id"/></td>
                                <td><xsl:value-of select="name"/></td>
                                <td>$<xsl:value-of select="price"/></td>
                            </tr>
                        </xsl:for-each>
                    </table>
                </body>
            </html>
        </xsl:result-document>
    </xsl:for-each-group>
</xsl:template>

Method 3: Using XSLT 1.0 (Positional Predicates)

Environments restricted to XSLT 1.0 (such as default client-side browser engines) must iterate over the first item of each page, then use the following-sibling axis to fetch the remaining elements for that page.

<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="html" indent="yes"/>
    <xsl:param name="pageSize" select="2"/>

    <xsl:template match="/catalog">
        <html>
            <body>
                <!-- Match only the first node of every page -->
                <xsl:for-each select="product[(position() - 1) mod $pageSize = 0]">
                    <xsl:variable name="pageNum" select="(position() - 1) div $pageSize + 1"/>
                    <h2>Page <xsl:value-of select="$pageNum"/></h2>
                    
                    <table>
                        <tr><th>ID</th><th>Name</th><th>Price</th></tr>
                        <!-- Output the current node and its following siblings up to the page limit -->
                        <xsl:apply-templates select=". | following-sibling::product[position() &lt; $pageSize]"/>
                    </table>
                </xsl:for-each>
            </body>
        </html>
    </xsl:template>

    <xsl:template match="product">
        <tr>
            <td><xsl:value-of select="id"/></td>
            <td><xsl:value-of select="name"/></td>
            <td>$<xsl:value-of select="price"/></td>
        </tr>
    </xsl:template>
</xsl:stylesheet>

Summary of Best Practices

  • Processor Choice: Use an XSLT 2.0 or 3.0 processor (such as Saxon) whenever possible. The idiv grouping technique is faster and requires less memory than XSLT 1.0 sibling axes traversal.
  • Output Splitting: For catalogs with tens of thousands of rows, split the output into separate static pages via <xsl:result-document> to avoid massive DOM rendering costs in client browsers.
  • Parameterization: Keep the $pageSize as an external parameter (<xsl:param>) so you can adjust pagination density without modifying the transformation logic.
