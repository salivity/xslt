Using xsl:on-empty for Fallback Content in XSLT 3.0

In XSLT 3.0, the <xsl:on-empty> instruction provides a clean, declarative mechanism to supply fallback content whenever an enclosing sequence constructor produces an empty result. Prior to this feature, developers had to rely on cumbersome workarounds, such as storing computed output in temporary variables and evaluating them with <xsl:if> or <xsl:choose>. This article explains the mechanics of <xsl:on-empty>, how it interacts with sequence constructors and empty nodes, and how to use it effectively alongside <xsl:where-populated> to simplify stylesheet logic.

The Problem with Traditional Fallbacks

In older XSLT versions (1.0 and 2.0), checking whether a sequence constructor generated content required capturing the output in a variable and inspecting its contents before generating wrapper elements or fallback values:

<xsl:variable name="desc" select="description"/>
<xsl:choose>
    <xsl:when test="normalize-space($desc)">
        <xsl:value-of select="$desc"/>
    </xsl:when>
    <xsl:otherwise>No description provided.</xsl:otherwise>
</xsl:choose>

This pattern creates boilerplate, hurts readability, and incurs performance overhead by buffering intermediate trees or sequences into memory.

How <xsl:on-empty> Operates

The <xsl:on-empty> element is an XSLT instruction placed inside any sequence constructor (such as within an <xsl:template>, literal result element, or <xsl:element>).

When the stylesheet executes:

  1. The processor evaluates the primary instructions within the enclosing sequence constructor.
  2. It monitors the resulting sequence to see if any items (nodes or atomic values) are generated.
  3. If the primary instructions produce an empty sequence—or yield no output—the contents of the <xsl:on-empty> instruction are evaluated and emitted instead.
  4. If the primary instructions produce at least one item, the <xsl:on-empty> element is completely ignored.

Basic Example

<div>
    <xsl:value-of select="user/bio"/>
    <xsl:on-empty>User has not provided a biography.</xsl:on-empty>
</div>

If user/bio does not exist or evaluates to an empty sequence, the output is:

<div>User has not provided a biography.</div>

If user/bio contains the string "Software Architect", the output is:

<div>Software Architect</div>

Handling Empty Nodes and <xsl:where-populated>

A critical distinction in XSLT is the difference between an empty sequence and a node containing no text or child nodes.

If a sequence constructor produces an empty element (for example, <span/>), that result is technically a populated sequence containing one element node. By default, <xsl:on-empty> will not trigger because an item was produced.

To handle empty nodes properly, XSLT 3.0 pairs <xsl:on-empty> with <xsl:where-populated>. The <xsl:where-populated> instruction suppresses the generation of an element if its contents are empty or contain only whitespace.

<xsl:where-populated>
    <div class="summary">
        <xsl:apply-templates select="summary-points"/>
        <xsl:on-empty>No summary points found.</xsl:on-empty>
    </div>
</xsl:where-populated>

In this scenario:

  • If summary-points yields items, they appear inside <div class="summary">.
  • If summary-points matches templates that produce no output, the sequence is empty, triggering <xsl:on-empty> to output "No summary points found." inside the <div>.
  • If the entire sequence constructor—including the fallback—were empty, <xsl:where-populated> would omit the <div> element entirely.

Companion Instruction: <xsl:on-non-empty>

XSLT 3.0 also introduces <xsl:on-non-empty>, the logical inverse of <xsl:on-empty>. While <xsl:on-empty> renders only when nothing else was produced, <xsl:on-non-empty> evaluates its contents only when the preceding or surrounding instructions successfully produce at least one item. Together, these two instructions allow fine-grained, conditional layout generation without the need for temporary variables or pre-testing data conditions.
