Traversing XSLT 3.0 Maps with map:keys and map:get

XSLT 3.0 introduced native map data structures, providing a robust way to store and manipulate associative arrays of key-value pairs. Navigating these structures dynamically requires specific functions to discover available entries and access their contents. This article explains the essential roles of map:keys() and map:get(), illustrating how they work in tandem to iterate through maps, access values, and process structured data in XSLT 3.0 stylesheets.

The Role of map:keys()

The map:keys() function retrieves all the keys defined in a specified map. Because maps in XSLT are unordered collections, map:keys($map) returns an arbitrary sequence containing every atomic key present in the map.

Key characteristics of map:keys() include:

  • Dynamic Discovery: It allows you to process maps whose keys are unknown at design time, such as data parsed from arbitrary JSON sources.
  • Sequence Output: The result is an atomic sequence (e.g., xs:string*, xs:integer*), making it directly compatible with standard XPath sequence operations, such as sorting (xsl:sort) or filtering with predicates.

The Role of map:get()

The map:get() function retrieves the value associated with a specific key from a target map. It takes two arguments: the map to query and the key to look up (map:get($map, $key)).

Key characteristics of map:get() include:

  • Safe Extraction: If the requested key exists within the map, map:get() returns the associated value (which can be an atomic value, a sequence, an XML node, or another map/array). If the key is not found, it safely returns an empty sequence (()) without throwing an error.
  • Alternative Syntax: In XSLT 3.0, maps act as functions. While map:get($map, $key) is the explicit function call, the dynamic function call $map($key) achieves the same result.

Traversing a Map Using Both Functions

Traversing a map typically follows a two-step pattern: obtain the list of keys using map:keys(), iterate through that sequence, and extract the corresponding data using map:get().

Here is an example demonstrating this pattern:

<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
                xmlns:map="http://www.w3.org/2005/xpath-functions/map"
                version="3.0">

    <xsl:variable name="employee-roles" as="map(xs:string, xs:string)">
        <xsl:map>
            <xsl:map-entry key="'Alice'" select="'Architect'"/>
            <xsl:map-entry key="'Bob'" select="'Developer'"/>
            <xsl:map-entry key="'Charlie'" select="'Designer'"/>
        </xsl:map>
    </xsl:variable>

    <xsl:template name="xsl:initial-template">
        <roles>
            <!-- 1. Retrieve and iterate over keys -->
            <xsl:for-each select="map:keys($employee-roles)">
                <!-- 2. Sort keys alphabetically -->
                <xsl:sort select="." />
                
                <xsl:variable name="current-key" select="."/>
                <!-- 3. Retrieve value using map:get() -->
                <xsl:variable name="current-value" select="map:get($employee-roles, $current-key)"/>

                <employee name="{$current-key}" role="{$current-value}"/>
            </xsl:for-each>
        </roles>
    </xsl:template>

</xsl:stylesheet>

Why Use map:keys() and map:get() Over map:for-each()?

While XSLT 3.0 also provides map:for-each() to iterate over key-value pairs inline, combining map:keys() with map:get() offers distinct advantages in XSLT template design:

  1. Ordering and Sorting: map:keys() produces an XPath sequence, allowing you to sort keys using <xsl:sort> inside an <xsl:for-each> loop before extracting values.
  2. Selective Filtering: You can apply XPath predicates directly to the key sequence (e.g., map:keys($data)[starts-with(., 'id_')]) to inspect only a subset of entries without querying the entire map.
  3. Template Matching: Keys can be iterated and passed into template rules via <xsl:apply-templates select="map:keys($map)"/>, allowing modal processing tailored to key patterns.
