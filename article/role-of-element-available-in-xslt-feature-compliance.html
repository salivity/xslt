Role of element-available in XSLT Feature Compliance

This article examines how the element-available() function serves as a critical mechanism for verifying processor feature compliance in Extensible Stylesheet Language Transformations (XSLT). By dynamically evaluating the presence of standard and extension instructions before execution, developers can determine whether an XSLT engine adheres to specific specification levels, supports proprietary vendor capabilities, or provides standard extension elements. The following sections explore the technical operation of element-available(), practical implementation patterns, and its value in building cross-processor, forward-compatible stylesheets.

What is element-available()?

The element-available() function is a standard XSLT system function that evaluates an expanded QName passed as a string argument. It returns a boolean value: true if the processor supports the designated element as an instruction, and false if it does not.

element-available('namespace-prefix:instruction-name')

If the name carries no prefix, it is treated as a default null-namespace or evaluated within the default XSLT namespace, depending on the version and execution context.

Testing Standard vs. Extension Elements

XSLT processors vary widely in their adherence to W3C specifications (XSLT 1.0, 2.0, and 3.0) and their support for optional features. The element-available() function tests compliance in two distinct categories:

  1. Standard Instructions: When queried with an element in the standard XSLT namespace (http://www.w3.org/1999/XSL/Transform), the function checks if the processor implements modern specification elements. For instance, testing element-available('xsl:analyze-string') or element-available('xsl:iterate') reveals whether a processor supports specific XSLT 2.0 or 3.0 control structures.
  2. Extension Instructions: When queried with a non-XSLT namespace (such as EXSLT or vendor-specific namespaces from Saxon, Xalan, or MSXML), the function determines whether the processor provides proprietary or community-defined extensions without triggering a fatal compilation error.

Safe Fallback and Graceful Degradation

Without capability testing, invoking an unsupported element causes an XSLT processor to halt execution with a static or dynamic error. element-available() prevents pipeline failure through conditional branching:

<xsl:choose>
  <xsl:when test="element-available('xsl:for-each-group')">
    <!-- Advanced grouping supported by XSLT 2.0+ compliant processor -->
    <xsl:for-each-group select="item" group-by="@category">
      <xsl:value-of select="current-grouping-key()"/>
    </xsl:for-each-group>
  </xsl:when>
  <xsl:otherwise>
    <!-- Fallback logic for XSLT 1.0 baseline processors (e.g., Muenchian grouping) -->
    <xsl:apply-templates select="item[generate-id() = generate-id(key('items-by-category', @category)[1])]"/>
  </xsl:otherwise>
</xsl:choose>

In XSLT 2.0 and later, this pattern extends to static compilation through the use-when attribute:

<xsl:iterate select="records/record" use-when="element-available('xsl:iterate')">
  <!-- Instruction compiled only if supported -->
</xsl:iterate>

Role in Automated Compliance Testing Suites

In formal processor testing, such as the W3C XSLT Test Suite, element-available() functions as an automated probe. Test harnesses utilize it to:

  • Map Engine Capabilities: Systematically iterate through lists of spec-defined elements to construct an automated support matrix for an engine.
  • Isolate Optional Features: Identify whether optional modules—such as serialization parameters, streaming elements, or document projection elements—are enabled in a given build.
  • Validate Specification Conformance: Confirm that an engine accurately returns false for elements outside its claimed conformance level rather than improperly ignoring them or crashing.

By validating whether instructions are recognized prior to instantiation, element-available() acts as a foundational utility for writing robust, cross-platform transformations and verifying XSLT standard compliance.
