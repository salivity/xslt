XSLT Default Values for Empty Sequences Using head()

In XSLT and XPath processing, missing elements or attributes often resolve to an empty sequence rather than a null or default value. While developers traditionally rely on verbose if-then-else expressions to handle missing data, modern XPath (3.0 and later) allows for a much cleaner approach. By combining sequence construction with the head() function, you can provide elegant, inline fallback values for empty sequences with minimal syntactic overhead.

The Problem with Traditional Fallbacks

When querying an optional element or attribute, such as user/role, an absent node produces an empty sequence (). Traditionally, assigning a default value required a conditional construct:

<xsl:variable name="role" select="if (user/role) then user/role else 'guest'" />

While functional, this approach becomes repetitive and cluttered when transforming multiple optional fields, and it requires repeating the target XPath expression twice.

The head() Pattern

XPath flattens sequences automatically. When you place an expression and a fallback literal inside parentheses, XPath concatenates them into a single sequence:

(user/role, 'guest')
  • If user/role evaluates to a node, the resulting sequence is (user/role, 'guest').
  • If user/role is missing (an empty sequence ()), the sequence collapses to simply ('guest').

The head() function returns the first item of a sequence, or an empty sequence if the input sequence is completely empty. By wrapping the concatenated sequence in head(), you reliably extract either the resolved value or the specified default:

<xsl:value-of select="head((user/role, 'guest'))" />

If user/role exists, head() returns its value. If it does not exist, head() returns 'guest'.

The Subscript Index Alternative

An alternative to head() that works similarly across XPath 2.0 and later is using the positional predicate [1]:

<xsl:value-of select="(user/role, 'guest')[1]" />

Both patterns achieve the same outcome. The head() function is often preferred in XPath 3.0+ stylesheets for readability, as it explicitly signals the functional intent of selecting the leading item.

Handling Empty Strings vs. Empty Sequences

A common pitfall occurs when an element exists in the XML source but contains no text (e.g., <role></role>).

In this scenario, user/role does not return an empty sequence; it returns a node with an empty string value (""). Because the node exists, head((user/role, 'guest')) will return the empty string instead of the fallback value.

To ensure the default is applied to both missing nodes and whitespace-only nodes, filter the target expression with a predicate before applying head():

<xsl:value-of select="head((user/role[normalize-space()], 'guest'))" />

This predicate ensures that only elements containing non-whitespace text are treated as valid, allowing whitespace-only or empty elements to fall through to the default value.
