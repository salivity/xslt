Purpose of default-collation in XSLT 2.0

The default-collation attribute on <xsl:stylesheet> in XSLT 2.0 and later versions establishes the default algorithm used for comparing, sorting, and matching text strings across the entire stylesheet. By specifying this attribute at the stylesheet root, developers can enforce language-sensitive sorting, case-insensitive comparisons, or custom cultural ordering conventions globally without manually specifying a collation on every individual XPath function or sorting instruction.

Understanding Collations in XSLT

A collation is a set of rules that governs how character strings are ordered and compared. By default, XSLT processors rely on the Unicode Codepoint Collation (http://www.w3.org/2005/xpath-functions/collation/codepoint). This default approach compares characters based strictly on their underlying binary Unicode values, meaning uppercase letters sort before lowercase letters (for example, "Z" comes before "a"), and accented characters are treated as entirely distinct entities rather than variants of a base letter.

How default-collation Operates

When the default-collation attribute is declared on the <xsl:stylesheet> or <xsl:transform> element, it overrides the standard Unicode Codepoint Collation for all operations within the scope of that stylesheet, unless an explicit collation is locally provided.

It affects multiple standard operations, including:

  • Sorting instructions: <xsl:sort> applies the specified collation order to keys when sorting node sets or sequences.
  • Grouping instructions: <xsl:for-each-group> uses the default collation when matching string keys using attributes like group-by.
  • String comparison functions: Functions such as compare(), contains(), starts-with(), ends-with(), substring-before(), and substring-after() evaluate matches based on the default collation rules.
  • Sequence aggregation functions: Functions like distinct-values(), index-of(), min(), and max() compare string items according to the collation.

Fallback and URI Resolution

The value of the default-collation attribute is a whitespace-separated list of URIs. The XSLT processor iterates through the URIs from left to right and uses the first collation that it recognizes and supports. If the processor does not support any of the listed collations, it raises a static error.

For example:

<xsl:stylesheet version="2.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    default-collation="http://saxon.sf.net/collation?lang=de-DE http://www.w3.org/2005/xpath-functions/collation/codepoint">
    
    <!-- Transformations here use German sorting rules by default -->
</xsl:stylesheet>

In this case, the processor attempts to use a German language collation rule. If that collation is not implemented or recognized by the engine, it falls back to the standard Unicode codepoint collation.

Primary Use Cases

  1. Locale-Aware Sorting: Alphabets vary across languages. For example, Swedish treats "Å", "Ä", and "Ö" as distinct letters at the end of the alphabet, whereas German treats "Ä" as a variant of "A". A localized default collation ensures that output lists conform to specific geographic or linguistic standards.
  2. Global Case-Insensitivity: Setting a case-insensitive collation as the default allows matching expressions like contains(title, 'xslt') to match "XSLT", "Xslt", or "xslt" without requiring manual conversion functions like lower-case().
  3. Cleaner Codebase: Defining the collation centrally removes the redundancy of adding collation="..." attributes to dozens of individual functions and <xsl:sort> elements.
