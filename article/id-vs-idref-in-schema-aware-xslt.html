id() vs idref() in Schema-Aware XSLT

In schema-aware XSLT and XPath, the primary difference between id() and idref() lies in the direction of navigation: id() retrieves the element that possesses a specific identifier, whereas idref() performs an inverse lookup to find all nodes that reference that identifier. While id() operates primarily on xs:ID values to locate target elements, idref() requires schema awareness or a DTD to identify nodes typed as xs:IDREF or xs:IDREFS that point back to an ID.

The id() Function

The id() function resolves a unique identifier to the element node that owns it. It takes one or more strings representing ID values and searches the document for an element whose ID matches.

  • Direction: Resolves from an ID value to the target element.
  • Return Type: Returns the element node (or nodes) that have the matching xs:ID, xml:id, or DTD-defined ID attribute.
  • Typing Requirements: Works in both basic and schema-aware processors using standard attributes like xml:id or DTD-defined IDs. In schema-aware mode, it matches attributes and elements explicitly typed as xs:ID.

Example: If an XML document contains:

<department xml:id="sales">Sales &amp; Marketing</department>

The expression id('sales') returns the <department> element.

The idref() Function

The idref() function performs the reverse operation of id(). Given an ID string, it locates every node in the document that references that ID through an xs:IDREF or xs:IDREFS type.

  • Direction: Performs a reverse lookup, finding references that point to a target ID.
  • Return Type: Returns a sequence of nodes (elements or attributes) whose typed value matches the specified ID and whose type definition is derived from xs:IDREF or xs:IDREFS.
  • Typing Requirements: Strictly requires a typed document tree (via XML Schema validation or a DTD). Without schema validation, the processor has no way to distinguish a standard string from an xs:IDREF, causing idref() to return an empty sequence.

Example: Assuming managerRef is typed as xs:IDREF in the schema:

<project managerRef="emp-101">Website Redesign</project>
<project managerRef="emp-101">Database Migration</project>

The expression idref('emp-101') returns the two managerRef attribute nodes pointing to that identifier.

Key Differences at a Glance

Feature id() idref()
Purpose Finds the target element with the given ID. Finds referring nodes that reference the given ID.
Target Type Looks for nodes typed as xs:ID (or xml:id). Looks for nodes typed as xs:IDREF or xs:IDREFS.
Schema Dependency Can work without a schema using standard xml:id. Requires schema or DTD awareness to detect reference types.
Result Multiplicity Typically 1:1 (IDs are unique within a document). Typically 1:N (multiple nodes can reference the same ID).
Node Types Returned Returns element nodes. Returns attribute or element nodes containing the reference.
