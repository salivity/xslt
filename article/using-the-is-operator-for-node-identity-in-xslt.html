Using the is Operator for Node Identity in XSLT

In XSLT 2.0 and later versions, the is operator compares the identity of two nodes rather than their textual or atomic values. This article covers how the is operator functions under the W3C XPath and XQuery Data Model (XDM), highlights the critical differences between identity comparison and value comparison, outlines syntax and cardinality rules, and demonstrates practical use cases.

Understanding Node Identity

In the XDM data model used by XSLT 2.0, 3.0, and 4.0, every node in an XML document has a distinct identity. Even if two elements share the exact same tag name, attributes, and child content, they remain distinct nodes unless they point to the exact same memory reference in the node tree.

The is operator evaluates whether two operands represent the exact same node instance:

$nodeA is $nodeB
  • It returns true if $nodeA and $nodeB reference the exact same node.
  • It returns false if they reference different nodes, regardless of whether their contents match.

Difference Between is and =

The standard equality operator (=) is a general comparison operator that performs atomization:

<!-- Example XML snippet: <root><item id="1">Text</item><item id="2">Text</item></root> -->
$item1 = $item2  (: Returns true because both string-values are 'Text' :)
$item1 is $item2 (: Returns false because they are distinct elements :)

While = checks whether the typed values or string values of two items match, is ignores content entirely and strictly inspects the underlying node references.

Cardinality and Type Rules

The is operator is categorized as a node comparison operator and enforces strict typing rules:

  1. Singleton Requirement: Both operands must evaluate to a single node or the empty sequence (()). If an operand evaluates to a sequence containing two or more nodes, the XSLT processor raises a dynamic type error (XPTY0004).
  2. Node-Only Operands: Both operands must be nodes. If either operand evaluates to an atomic value (such as a string, integer, or date), a type error is thrown.
  3. Empty Sequence Handling: If either operand is the empty sequence, the result of the comparison is an empty sequence (()), which evaluates to false in an effective boolean value (EBV) context, such as within an xsl:if or [ ... ] predicate.

Common Use Cases

1. Determining Context Matching

You can use is to check whether the current context node is identical to an element stored in a variable:

<xsl:variable name="targetNode" select="/catalog/book[1]" />

<xsl:template match="book">
    <xsl:if test=". is $targetNode">
        <!-- Executes only for the exact first book -->
    </xsl:if>
</xsl:template>

2. Checking Against the Root Node

The is operator can verify if a node is the root element or document node:

<xsl:if test=". is /">
    <!-- Current node is the document node -->
</xsl:if>

3. Boundary Checks Within a Sequence

When iterating through a subset of elements, you can verify if a node is the first or last node of that specific sequence:

<xsl:variable name="filteredItems" select="//item[@active = 'true']" />

<xsl:for-each select="$filteredItems">
    <xsl:if test=". is $filteredItems[1]">
        <!-- First node in the active items sequence -->
    </xsl:if>
</xsl:for-each>

Related Node Comparison Operators

The is operator belongs to a family of node comparison operators that also include document order comparisons:

  • <<: Returns true if the left operand precedes the right operand in document order.
  • >>: Returns true if the left operand follows the right operand in document order.

Like is, both << and >> require single nodes as operands and raise a type error if given sequences of length greater than one or atomic values.
