Using xsl:output-character in XSLT Character Maps

In XSLT 2.0 and later versions, character maps allow developers to alter how specific characters are serialized into final output formats. The <xsl:output-character> element serves as the core mapping instruction inside an <xsl:character-map>, explicitly pairing an individual target character with a designated output string. This article explains the technical role, syntax, and common use cases of <xsl:output-character> during the transformation serialization phase.

Core Functionality and Attributes

The primary role of <xsl:output-character> is to intercept a specific Unicode character during serialization and replace it with an arbitrary literal string. Under standard XSLT serialization, characters with reserved meanings in markup languages (such as <, >, and &) are automatically escaped into predefined entity references (such as &lt; or &amp;) or numeric character references. The <xsl:output-character> element overrides this default escaping behavior.

The element relies on two mandatory attributes:

  • character: Specifies the single Unicode character in the transformation result tree that needs to be replaced.
  • string: Specifies the exact sequence of characters that should be written to the serialized output in place of the matched character.

Execution During Serialization

Character mapping occurs at the very end of the XSLT pipeline during serialization. The <xsl:output-character> element does not modify the XML tree within the stylesheet's intermediate execution stages; it only affects the physical byte or text stream generated by the serializer.

To use <xsl:output-character>, the enclosing <xsl:character-map> must be declared as a top-level element, given a name attribute, and referenced by an <xsl:output> declaration via the use-character-maps attribute:

<xsl:character-map name="custom-entities">
    <xsl:output-character character="&#169;" string="&amp;copy;" />
    <xsl:output-character character="&#160;" string="&amp;nbsp;" />
</xsl:character-map>

<xsl:output method="html" use-character-maps="custom-entities" />

In this scenario, whenever the copyright symbol (© or &#169;) appears in the result tree, the serializer outputs the raw text &copy; instead of standard numeric or UTF-8 representations.

Common Use Cases

  1. Custom Entity Serialization: Legacy systems, web browsers, or specific downstream parsers often require named HTML/XML entities (such as &nbsp; or &mdash;) rather than numeric character codes or raw Unicode bytes.
  2. Generating Non-XML Formats: When generating plain text, CSV, RTF, or programming language code, standard XML escaping can introduce syntax errors. <xsl:output-character> allows you to map specific characters to required escape sequences (for example, escaping double quotes as "" or \").
  3. Preventing Double Escaping: When you intentionally need unescaped markup or specific processing instructions in the output, you can map placeholder characters to unescaped structural symbols.
